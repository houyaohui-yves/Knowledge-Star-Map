# 🌌 Knowledge Star-Map（知识星图）

> 知识之所以有力量，是因为它们在乱序中连点成线。

Knowledge Star-Map 是一个基于 Markdown 和 Obsidian 的个人知识系统。它的首要目标是把日常学习中的外部输入，转化为可以长期积累、连接和调用的个人知识；并在此基础上记录小说、写作、产品或其他方向的灵感。

仓库根目录同时是 Obsidian Vault。从 `Home.md` 进入整个系统。

## 目录职责

| 目录 | 职责 | 是否进入默认知识图谱 |
| --- | --- | --- |
| `00_Inbox/` | 快速捕获、等待整理 | 否，整理时可临时加入 |
| `10_Knowledge/` | 已经理解和内化的知识 | 是 |
| `20_Sources/` | 原始资料和来源笔记 | 否 |
| `30_Ideas/` | 小说及其他创意种子 | 是 |
| `40_Projects/` | 正在孵化或推进的具体成果 | 否 |
| `90_Archive/` | 已结束、过时或冻结的内容 | 否 |
| `99_System/` | 模板、附件、脚本和系统说明 | 否 |

## 知识流转

```text
快速捕获
   ↓
00_Inbox
   ↓
判断内容性质
   ├── 外部输入 → 20_Sources
   ├── 个人理解 → 10_Knowledge
   └── 创意想法 → 30_Ideas
                         ↓
                  明确具体成果
                         ↓
                    40_Projects
                         ↓
                    90_Archive
```

`Sources` 为知识提供依据，`Knowledge` 与 `Ideas` 构成正式知识星图，它们共同为 `Projects` 提供参考。

## 组织原则

- 文件夹管理内容所处的生命周期，不强迫知识只属于一个学科。
- Properties 记录笔记类型、状态和领域。
- `[[双向链接]]` 表达知识、来源和灵感之间的关系。
- MOC（Map of Content）人工组织领域和主题脉络。
- 标签主要用于 `#待整理`、`#待验证` 等临时工作状态。
- 知识笔记尽量保持原子化，用自己的语言表达一个核心认识。

## 五大学科 MOC

五大学科作为导航视角保留在 `10_Knowledge/Maps/Domains/`：

- Constants：形式科学，提供思维工具。
- Matter：自然科学，研究自然现象。
- Tides：社会科学，研究人类社会。
- Echoes：人文学科，研究精神与价值。
- Engines：应用科学，把知识转化为现实方案。

一篇笔记可以同时被多张领域或主题 MOC 引用。

## Obsidian 配置

- 新附件默认放入 `99_System/Attachments/`。
- 模板放入 `99_System/Templates/`。
- 默认全局图谱只显示 `10_Knowledge/` 和 `30_Ideas/`。
- `workspace.json` 和 `graph.json` 是本地界面状态，不进入 Git。

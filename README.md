# 🌌 Knowledge Star-Map（知识星图）

> 知识之所以有力量，是因为它们在乱序中连点成线。

这是以学习、校正理解和长期调用知识为核心的个人知识库，也保存小说、产品等灵感及明确成果。仓库根目录是 Obsidian Vault：Markdown 保存内容与证据，Obsidian 负责阅读、编辑和导航，Git 提供版本追踪，Harness 通过任务入口、规则和工具组织 AI 的工作。

## 从哪里开始

- [Home](Home.md)：浏览知识、来源、灵感与项目。
- [投资专题](10_Knowledge/Maps/Topics/Investing/投资.md)：从基础知识、分析方法进入公司跟踪、持仓决策与复盘；实际账户记录由投资实践项目维护。
- [System](99_System/System.md)：查找规范、模板和工具。
- [目录结构说明](99_System/目录结构说明.md)：实际目录、AI 主线、资料和归档边界。
- [系统改造方案](99_System/知识库系统架构与改造方案.md)：目标架构、实施批次和已完成验证。

本页是用户指南；详细执行标准由专项规范维护。具备本项目文件访问能力的会话可直接提出问题，无需重新解释目录或每次要求记笔记。也可显式使用 `$knowledge-study`，或要求读取 [AGENTS](AGENTS.md) 及其工作流入口。在没有仓库访问能力的会话中，需要提供相关文件；保存草稿不等于入库。

## 怎样使用

| 可以这样说 | 系统怎样处理 |
| --- | --- |
| “我在看 RAG 视频，我的理解是……对吗？” | 先解释和校正，再复用已有笔记保存有效结论；视频只核对实际获得的材料 |
| “从零带我学这个主题” | 根据现有资料提出少量目标和路线，区分已有知识内容与你的实际基础 |
| “考考我”／“复习薄弱点” | 给任务并等待真实作答，记录提示条件与局部表现；普通提问不强制测验 |
| “继续上次的 RAG 课程” | 读取对应来源的当前接续；有多个实质候选才询问，缺少记录时明确说明 |
| “用已有知识分析这个方案” | 找相关概念、案例和适用条件，交代缺口；查询本身不自动建新笔记 |
| “把这些材料整理入库” | 辨识出处、查重，按概念、案例、来源与导航分工保存 |
| “review 这小节笔记” | 只读评审本节及必要关联旧笔记，交付三部分报告和完整证据附录 |
| “按 F01、F02 修改” | 在对应范围落实修改并复查，区分已修改和已解决 |
| “保存 review 报告” | 保存报告与证据，不因此修改知识正文 |
| “看看这些内容有什么需要维护” | 明确范围后只读检查，返回有依据的问题、无需动作或具体待验证项 |
| “继续上次维护，把已确认的问题修好” | 从持久事项恢复，核对当前内容与依据，在授权内修订；中断可接续，验收后才关闭 |
| “记下这个灵感”／“把它做成项目” | 分别保存创意或明确成果目标，引用有关知识 |

课程名、链接、字幕、截图和时间戳可以逐步提供，不必一次填齐。跨会话依靠文件记录接续，不代表助手拥有完整聊天历史，也不会自动听到正在播放的视频。

## 控制保存与节奏

学习默认在一个知识点讲清或段落结束时保存可复用结论、重要误区及接续；没有实质新内容就不写。你可以随时说“只讨论，先别写”“等我说整理再写”“只测不记”“先别测，继续下一节”。暂停时说“今天到这里，整理下次入口”即可。

Review、评分和诊断默认只读；需要修改时直接指定问题或范围。系统结构讨论与 Git 操作不自动生成学习记录。保存指实际写入本地文件，默认不提交、不推送、不切分支、不清理资料。长期偏好变更可直接说“更新协作规则：……”，落实到对应规范。

## 内容怎样配合

目录区分用途：Inbox 暂存未厘清输入；Knowledge 沉淀可复用认识；Sources 保存资料与学习出处；Ideas 保存创意；Projects 推进成果；Local 保存本机实践；Archive 保存退出当前使用的内容；System 保存运行规则和工具。某个专题的内容位置与分工可直接查看其统一入口的“归档与维护边界”；全库目录职责与跨层级规则见[目录清单](99_System/目录结构说明.md)。

以 Query 改写为例：

| 内容 | 主要职责 |
| --- | --- |
| [概念](10_Knowledge/Notes/AI/03_Engineering/RAG中的Query改写.md) | 通用解释、条件、误区与依据 |
| [案例](10_Knowledge/Notes/AI/04_Applications/Query改写案例：上海迪士尼客服问答.md) | 任务、输入、推理、中间结果和输出 |
| [课程来源](20_Sources/Notes/Courses/AI大模型应用课件：RAG技术与应用.md) | 材料范围、核验、真实学习表现和接续 |
| [主题地图](10_Knowledge/Maps/Topics/AI/提示词与RAG：学习地图.md) | 问题入口、关系和阅读顺序 |

通用解释集中维护，案例保留理解所需上下文，独立概念有直接入口。MOC 不复制正文和个人进度；五大学科是导航视角，AI 是跨学科主题域，正文按主要问题归属，并可被多张地图引用。复杂表达和颗粒度标准见[知识组织规范](99_System/知识组织规范.md)。

笔记成熟度、事实核验、个人掌握是三件事：整理完不等于全部事实已核实，助手解释过也不等于你已经会用。理解状态依实际作答或实践记录，效果主张依相应实验；原文、转述、助手补充和推测分别标明。

## 模板与工具

[模板目录](99_System/Templates/)提供知识、来源、MOC、灵感、项目和 Review 六种基础模板，以及公司跟踪、个股持仓与行动、公司研究更新三份投资专用模板，使用入口见[投资专题](10_Knowledge/Maps/Topics/Investing/投资.md)。AI 与其他知识共用知识模板，按需填写 AI 属性；来源模板的学习目标和证据区块可选，空章节可以删除。助手按任务选择模板，用户不需填写配置表。

[PDF 工具](99_System/Scripts/pdftext/README.md)用于文字提取及 OCR；提取成功不等于事实正确，图表与布局影响理解时仍需核对原页。[知识维护工具](99_System/Scripts/knowledge_maintenance/README.md)支持范围检查、证据交接、持久事项、修订保护与恢复。AI 阅读证据并判断，写完后复查才关闭事项；工具不替代完整 Review。

本机课件和临时实践放在 `80_Local/`，不会随 Git 克隆恢复，获取信息与长期认识留在正式笔记。重建与清理边界见[本地工作区说明](99_System/目录结构说明.md#本地工作区)。忽略不等于备份或保密保护。

# 和 GPT 一起学习、整理笔记

本项目已经保存了可供新会话读取的协作规则：

- 根目录 `AGENTS.md`：项目目标、结构、长期偏好和默认写入约定。
- `.agents/skills/knowledge-study/SKILL.md`：理解核对、来源处理、增量记笔记和跨会话接续流程。

Codex 在启动任务时读取项目 `AGENTS.md`，并支持从仓库 `.agents/skills/` 发现技能。技能也可以按任务匹配使用。[项目指令机制](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[技能发现机制](https://learn.chatgpt.com/docs/build-skills)。

## 开始学习

在 Codex 的 Knowledge-Star-Map 项目中新建会话后，可以直接开始：

> 我在看一个讲 RAG 的视频。我的理解是，它会把检索到的知识重新训练进模型，所以模型就记住这些内容了，对吗？

不需要重新介绍知识库或逐次要求记笔记。助手会查找相关已有笔记，讨论理解中的问题，在形成有效结论后整理入库，并告诉你保存在哪里。

视频链接、课程名、字幕、截图或时间戳可以随学习过程提供，不需要开头一次填齐。助手只依据实际可读到的内容核对；你转述的视频观点会注明为转述。

如果想明确启用技能，可以输入：

```text
$knowledge-study 今天学习 RAG，帮我核对理解并边学边记。
```

如果新技能暂未显示，可重新打开项目会话或重启 Codex，也可以说：

> 请读取根目录 AGENTS.md，按其中的学习流程继续。

## 学习时会记录什么

- 来源笔记：课程要点、材料出处、实际提供的章节或时间戳、待核实内容。
- 知识笔记：可复用的概念、适用条件、解释、重要误区和真实关联；优先补充同主题已有笔记。
- Ideas：讨论中明确产生的小说或其他创意。
- 学习接续：写在对应来源笔记中，保存已讨论内容、尚未理解的问题和下次入口。

事实是否可靠、笔记是否成熟、你是否已经掌握是三件不同的事。助手会分别处理，不能因为讲解结束就把知识标为已掌握。

“已正确复述／已能应用”等判断应附你实际表达的证据；没有证据就保留“已讨论、待验证”。原课程出处未知时会如实注明；助手查阅的补充论文与文档单独记录，不冒充课程来源。学习记录保留理解变化和入口，详细解释留在知识笔记。

## 知识笔记怎样组织

概念独立成篇，案例串联应用，MOC 提供直接入口。按独立问题判断是否拆分，同义名称用别名，不为每个术语生成空文件。

概念页维护完整定义、条件和必要例子；案例保留理解当前步骤所需的简短解释、输入、中间结果与结论，即使本地课件后来不可用，仍能通读文章理解推理。链接用于深入阅读，不能替代必要上下文。

每次整理检查概念能否直接找到、文章能否独立读懂、通用解释是否集中维护，以及来源和旧链接是否保留。完整标准见 [知识笔记组织规则](知识笔记组织规则.md)；已有笔记随当前任务逐步改进，不自动全库重构。

## 控制写入节奏

默认在一个知识点讲清或一个学习段落结束时增量保存，无须每次确认。你随时可以调整：

- “这次只讨论，先别写文件。”
- “等我说整理再统一记笔记。”
- “把刚才关于上下文窗口的误区记下来。”
- “今天到这里，整理笔记和下次学习的入口。”

默认保存到本地文件，Git 提交和推送需另行提出。结构调整等维护任务按当前请求处理，不自动生成学习记录。

“评审／评分现有笔记”默认只读，等你要求修订后再改。结束主题或要求总结时，助手会按需要去重、补齐关键来源和边界、整理 MOC；可补完整案例和少量复习题，但不会把生成题目或答案当成你已掌握。

## 下次继续

可以说“继续上次的 RAG 课程”，助手会读取对应来源笔记中的“学习接续”并恢复主题。如果有多个匹配课程，会询问你指的是哪一个。没有已保存记录时，会坦诚说明缺少进度。

跨会话接续依靠文件中的记录，不等于新会话拥有完整聊天历史，也不会让助手自动听到你正在播放的视频。

这些规则适用于能读取此项目的 Codex 会话。普通 ChatGPT 聊天不会仅因为本机有这些文件就自动获得仓库访问能力；在其他客户端使用时，需要另行提供项目说明和文件访问方式。

后续可直接说“更新学习协作规则：……”来调整偏好。助手应修改相应的项目说明或技能，而不是只在当次对话中记住。

# 学习流程改造方案

日期：2026-10-05。状态：设计草案，尚未实施。本文提出未来变更，不替代现行规则，也不授权自动启动测验、修改历史学习状态或创建提醒。

## 3. 入口与教学方式

### 3.1 先识别当前请求

| 用户意图 | 助手动作 | 默认记录行为 |
| --- | --- | --- |
| 问一个具体问题、核对一个理解 | 先回答并纠偏；需要时给例子或推演 | 沿用学习会话的增量写入约定 |
| 要求从头学或系统学习 | 读取已有来源、地图及理解证据，提出少量目标和路线 | 保存有效目标与已知前提，不预建空模块 |
| 要求“考考我／检查我是否会用” | 先给任务，等待真实作答，再评价 | 允许记录本次真实表现；“只测不记”时不写 |
| 要求复习或继续课程 | 读取对应接续与相关待验证项，按第 7 节处理 | 有新作答或进展时更新；仅列出候选不虚构进展 |
| 要求 review 学习笔记 | 执行 Review 1.3 | 默认只读；不自动开始测验或更新学习状态 |
| 要求同时 review 笔记并考察理解 | 分开报告文件问题与个人表现 | 若未另获写入授权，先统一只读交付，避免混合请求扩大写入范围 |
| 要求设计、分析现有规范 | 按规则设计／诊断处理 | 不自动写入学习记录或启动教学 |

明确的当前指令优先于一般学习默认值；“只讨论”“先别记”“暂时不测”立即生效。已获得的操作授权不重复询问。

### 3.2 教学方式随任务选择，不固定问模式菜单

| 方式 | 适用情境 | 操作 |
| --- | --- | --- |
| 随问随学 | 用户有具体问题，或正在跟课 | 围绕当前问题回答，尊重课程顺序 |
| 地图导览 | 用户想知道整体结构和先后依赖 | 从现有 MOC 讲全貌，再选择一个入口；临时路线不自动成为新 MOC |
| 逐步引导 | 用户需要补基础，或当前推理存在前提缺口 | 按概念、必要例子、短推演推进，关键点才邀请作答 |
| 任务递进 | 用户希望能够应用某项技能 | 明确成果标准，再安排由简单到复杂的任务；不机械套用四个等级 |

已有主题、来源和目标时直接沿用。缺少信息且会改变学习路线时，通常只补问一个关键问题。用户说“太简单”时减少铺垫；说“听不懂”时换例子、表示方式或补前提。节奏偏好不作为掌握证据。

## 4. 学习目标与理解检查

### 4.1 目标要能观察

在系统学习一个新主题／小节时，先提出 1–3 个核心目标；这是控制负担的默认粒度，不是每次提问的必填表。单个问题可直接使用问题本身作为目标。

目标写成“在什么条件下，能够完成什么，需保留哪些关键条件”。区分用户要求／课程范围与助手建议，必学程度相对于当前目的判断。用户没有确认助手提出的路线时，保留为拟议目标，不记成用户承诺。

例：能根据问题与历史选择原样通过、改写或澄清；改写后保留实体、时间、限制条件和任务意图，并解释理由。仅写“了解 Query 改写”不足以指导检查。

### 4.2 何时检查，何时直接继续

- 用户要求测验、练习或检查掌握时，执行理解检查。
- 用户已经给出推理、解释或实践结果时，直接据此核对，不为留痕额外出同类题。
- 核心概念讲清、小节结束，或重复出现同类困难时，可以提出一个短任务；等待真实作答，不能自行代答后记为通过。
- 普通事实问答、纯笔记整理、只读 Review、用户明确不测时，不强制插入测验。
- 用户跳过、不作答或转向新问题时继续其任务，记录仍待验证而非答错；不反复催问。

### 4.3 一次检查的执行顺序

1. **选目标与任务**：只检查当前目标需要的能力；概念用解释／反例，边界用辨析，流程用新输入推演，技能用小实践。
2. **准备判断依据**：先明确必要要点、可接受变体和关键错误；核对题目所需事实。开放问题允许多种合理方案，不把助手个人偏好当标准答案。
3. **给题并等待**：出题阶段不主动展示答案或泄露关键步骤。若用户要求答案则提供，但不能据后续照述判为独立完成。
4. **反馈真实表现**：先说明成立的部分，再指出缺口和理由。卡住时从小提示开始，必要时完整讲解；不强制猜测。
5. **记录条件与结果**：记题目／情境、回答要点、是否看笔记或收到提示、判断依据、仍需什么证据。题目有歧义或依据不足时先修题或标待核，不归为用户错误。
6. **决定下一步**：继续学习、针对缺口补强，或换情境／隔段时间再次验证。用户作答前不提前写结果。

以上描述可用简短自然语言完成，不要求每次展示全部执行字段或长评分报告。

## 5. 个人理解状态：以证据描述，不推算总掌握率

| 状态 | 何时可以记录 | 下一步 |
| --- | --- | --- |
| 待验证 | 已讨论但未作答、已跳过，或只有“懂了” | 在合适时机给独立解释或应用机会 |
| 待补强 | 实际回答暴露了影响当前目标的缺口，题目及判断依据可靠 | 记录具体缺口，针对性解释后再验证 |
| 提示后完成 | 经提示、看过关键解法后，完成当前任务 | 换题检查能否独立完成 |
| 独立完成（限定任务） | 未提供针对性解法，用户自主完成且满足事先确定的要点 | 如目标需要，追加迁移或延时验证 |

开放资料任务允许查阅指定资料；必须标明条件，不能把它当成脱离资料的记忆表现。助手刚给过同题完整答案后，直接复述不算独立完成。迁移与延时是证据条件，不自动构成统一的“最高等级”。

结果按具体目标记录，不能用一道题覆盖整门课程；再次表现有缺口时更新当前判断，保留先前有效证据及条件。只记录有证据的困难，不从提问次数、阅读速度或答题时长推断心理特征与能力。

继续分开维护三类状态：知识笔记的 `status: seed/developing/evergreen`、事实核验状态、个人学习表现。不给笔记新增一个混合三者的“掌握分”，不因测验答对升级知识笔记成熟度。

## 6. 记录放在哪里，怎样避免重复

### 6.1 沿用现有职责

| 内容 | 保存位置 |
| --- | --- |
| 可复用定义、解释、误区及方法 | 既有 Knowledge 概念／案例页 |
| 知识关系与长期阅读路线 | 既有 MOC，必要时按 MOC 规则维护 |
| 当前课程目标、作答表现、提示条件、再次验证安排 | 对应来源笔记的“用户理解与校准”“学习接续” |
| 来源未知或纯对话学习 | 沿用 Inbox 的可辨识主题记录，注明来源情况；不虚构课程 |
| 笔记 Review 的 F 编号与修订状态 | 按 Review 1.3 报告规则，不当作个人错题编号 |

跨课程复习同一知识点时，先找原有理解记录，必要时引用。新表现记在本次课程／学习记录里并链接旧证据，标注日期、任务和条件；不复制通用解释，也不把不同阶段的有限表现当作相互矛盾。

### 6.2 来源模板的拟议增量

“学习目标与范围”按需出现；“用户理解与校准”扩充为下面的紧凑结构；“学习接续”只摘要当前任务与下次入口，不重复整张表：

```markdown
## 学习目标与范围

- 本节目标：具体能力及必要条件；注明用户要求／课程范围／拟议建议。
- 起点与限制：已有表现及来源；缺失信息不补造。

## 用户理解与校准

| 目标／知识点 | 最近一次真实表现 | 当前判断 | 下一次验证 |
| --- | --- | --- | --- |
| 知识点或真实笔记链接 | 日期、题目／情境、回答要点与提示条件 | 有依据的局部状态与缺口 | 具体任务＋触发时机；或暂无安排 |

## 学习接续

- 当前进度：材料章节和本节目标。
- 个人表现：引用上面的结果；没有作答则待验证。
- 待核事实／待实践：与个人理解问题分开。
- 下次入口：继续材料或验证某个目标；具体时间仅在已安排时填写。
```

这是格式示意，不是给现有所有来源强制补表。只在实际产生学习目标或验证记录时添加；无作答不预生成大量空行。复杂回答的必要证据可放表后短段落；再次验证更新当前摘要，历史重要变化保留在同文的历史记录，不覆盖成从未出错。

来源笔记可以记录一条“本节理解尚待验证”，无需把每个知识点都登记为未完成任务。只有有学习价值、近期需要追踪的目标进入复习安排，避免形成无穷队列。

## 7. 复习与恢复学习

先采用“再次进入主题时检查”的轻量方式，暂不建立自动提醒或全库调度系统。

1. 用户要求继续某课程时，读取对应来源接续，并按需读取已关联的理解证据；不从最近修改文件猜课程。
2. 有具体新问题先处理新问题；只有相关、重要的待补强／提示后完成项，才简短提示复习机会。已有“直接继续”“暂时不复习”偏好时遵从。
3. 用户明确要求复习时，默认选择 1–3 个相关目标，优先关键前提、重复困难和仅有提示后成功的项目；正常学习不因清单存在而被强制阻塞。
4. 复习任务尽量换表述或情境。正确回答只更新覆盖到的目标；出错时补强相应缺口，不把全部学习进度清零。
5. 已有独立完成证据且当前无需追踪的条目，可退出近期复习安排；这只代表暂不优先复习，不声称永久掌握。

默认“下次验证”写具体触发时机，如“下次学习本课时”“进入多路检索前”。用户需要日历计划时，再结合目标期限与可用时间制定日期，并使用实际用户时区；1／3／7／14 天只可作为可调整的候选安排，不作为已验证的通用最优值。

过去的计划日期到期不代表已经复习。未按期完成只表示未执行，不判遗忘或答错。文件中的计划不自动创建定时任务；用户明确要求提醒或后台跟进时，才使用相应自动化能力。

## 8. Query 改写试点

试点材料复用 [概念笔记](../10_Knowledge/Notes/AI/03_Engineering/RAG中的Query改写.md)、[迪士尼案例](../10_Knowledge/Notes/AI/04_Applications/Query改写案例：上海迪士尼客服问答.md) 与 [课程来源](../20_Sources/Notes/Courses/AI大模型应用课件：RAG技术与应用.md)。不重审已通过的整套材料，不预改现有掌握状态。

拟议目标与验收要点：

| 目标 | 任务类型 | 判断要点 |
| --- | --- | --- |
| 选择通过、改写或澄清 | 比较条件完整、依赖历史、缺少关键实体的不同问题 | 说明选择理由；不把所有问题强制改写，不补造未知信息 |
| 保留原意并拆分检索请求 | 给一个未讲解过的组合情境 | 实体、约束、否定与量词保留；子问题覆盖原任务 |
| 区分代码行为与真实效果 | 判断一次离线模拟能证明什么 | 能区分历史传递／解析行为、模型质量、检索效果 |

实施规则：首次只给一个任务，用户愿意继续再扩展；题目先自查是否可判定。模板中的示意答案、课件错误和助手自己的失误，均不能冒充用户作答。试点中的角色扮演或预设回答只验证流程，不成为个人掌握证据。

试点完成后形成一段真实反馈：哪些目标有证据、哪些仍待验证、是否打断跟课、记录是否有助于接续；如果用户只看题或跳过，只能报告“流程已提供，学习表现尚未验证”。

## 9. 分阶段落地与退出条件

### 阶段一：建立最小可用规则

在用户要求实施后，完成第 2 节的 5 份执行文件变更。先形成新规范，再调整 Skill 路由、模板、协作说明与 System 入口。保留现行的证据、权限、组织和写入原则；不批量改历史笔记。

验收：用第 10 节场景走查触发与输出，核对新增链接和说明是否一致；Review 规范及模板保持原版本。当前文件含既有未提交变更时，只对照实施前基线检查本次增量，不覆盖用户修改。

### 阶段二：在一个真实小节试用

按第 8 节完成一次用户实际参与的 Query 检查；在自然的下次接续中尝试恢复记录。只更新该课程来源的相关段落；通用笔记仅在形成新有效认识且符合学习写入约定时增量整理。

验收：新会话仅凭文件即可找到课程、目标、真实证据、限制和下一步；用户能看懂记录；明确问题能够先获得回答；没有把未参与的检查算作完成。真实跨会话或延时验证尚未发生时，相关项保持待验证。

### 阶段三：据使用反馈决定是否扩展

若轻量记录足够，继续采用，不因次数增加自动扩建。若实际出现跨课程待复习项难以发现、来源页难以阅读或用户明确需要日期管理，再分别设计索引、按主题整理或提醒方案；形成具体问题后另行确定范围。

若新流程造成打断或记录负担，先降低主动出题频率、收窄追踪目标，保留有效证据。若用户决定撤回试点，只移除本次流程入口或调整条款，保留历史真实学习记录，不通过重置仓库回滚其他工作。

## 10. 执行验收场景

以下是实施后的行为检查，不是宣称已经通过的测试。可以用预设输入验证分支；模拟通过不等于真实学习效果或多模型一致性已经验证。

| 输入或情境 | 合格行为 | 应避免 |
| --- | --- | --- |
| “为什么需要 Query 改写？” | 先解释问题，按需给例子 | 先要求选择四种模式或填写目标表 |
| “从零系统学 RAG” | 利用已有资料提出少量目标与路线；关键起点不明时再问 | 根据知识库已有完整笔记判定用户已有基础 |
| “我懂了，继续” | 调整讲解节奏，个人状态仍以已有证据为准 | 因口头确认升级掌握状态 |
| “考考我” | 出一个合适任务并等待回答 | 同轮给标准答案再将用户计为通过 |
| 用户经提示完成 | 记录提示条件与完成范围 | 与独立完成合并 |
| “先别测，继续下一节” | 尊重当前任务，未测项保持待验证 | 强制清空复习队列或算作答错 |
| “只测不记” | 给任务和反馈，文件不变 | 以长期写入约定覆盖本次限制 |
| 题目有歧义，或答案依据不足 | 修题／补证据，保留用户判断 | 将题目缺陷记为用户错题 |
| “review 这小节学习笔记” | Review 1.3 的三部分报告与附录，只读 | 自动测验或更新个人学习状态 |
| 发现课程 demo 丢失历史 | 核对并维护技术知识；仅用户实际误解时记录个人缺口 | 将 demo 缺陷登记为用户错题 |
| 无旧理解记录，用户要求继续 | 恢复已知进度并明示理解证据缺失 | 补造上次答题、提醒或复习日期 |
| 复习计划日期已过，但无作答 | 标未执行，按用户意图继续 | 自动标答错、遗忘或清零 |
| 无外部来源的纯讨论 | 沿用 Inbox 并注明纯对话来源 | 新建虚构课程或课程专用空目录 |
| 学习记录涉及多个来源 | 区分日期、任务与条件，引用已有证据 | 批量统一成无条件“已掌握” |

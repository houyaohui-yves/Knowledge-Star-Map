# 学习与复习流程

更新：2026-10-20。现行会话执行流程，承接原学习 Skill 和学习改造草案；规则已落地不等于个人学习效果已经验证。适用于解释、系统学习、理解检查、复习与接续。写入边界以 [AGENTS](../AGENTS.md) 为准，组织按[知识组织规范](知识组织规范.md)，事实取证按[共同证据标准](维护与评审流程.md#共同证据标准)。

## 先回应当前问题

对用户理解指出正确部分、遗漏条件和错误，给出理由；需要时用例子、反例或短推演帮助理解。先回答具体问题，不要求填开课表或选择模式菜单。缺少信息时先处理能判断的部分，仅补问会改变路线的关键问题。

普通问答不强制测验；“只讨论”“只测不记”“暂时不测”立即生效。Review 笔记与检查个人理解是两件事；混合请求分别报告，未另获写入授权时按只读交付，不因测试而更新被审文件。

## 教学方式随任务选择

| 方式 | 适用情境 | 操作 |
| --- | --- | --- |
| 随问随学 | 用户有具体问题，或正在跟课 | 围绕当前问题回答，尊重课程顺序 |
| 地图导览 | 用户想知道整体结构和先后依赖 | 从现有 MOC 讲全貌，再选择一个入口；临时路线不自动成为新 MOC |
| 逐步引导 | 用户需要补基础，或当前推理存在前提缺口 | 按概念、必要例子、短推演推进，关键点才邀请作答 |
| 任务递进 | 用户希望能够应用某项技能 | 明确成果标准，再安排由简单到复杂的任务；不机械套用四个等级 |

已有主题、来源和目标时直接沿用。缺少信息且会改变学习路线时，通常只补问一个关键问题。用户说“太简单”时减少铺垫；说“听不懂”时换例子、表示方式或补前提。节奏偏好不作为掌握证据。

## 学习目标与理解检查

### 目标要能观察

在系统学习一个新主题／小节时，先提出 1–3 个核心目标；这是控制负担的默认粒度，不是每次提问的必填表。单个问题可直接使用问题本身作为目标。

目标写成“在什么条件下，能够完成什么，需保留哪些关键条件”。区分用户要求／课程范围与助手建议，必学程度相对于当前目的判断。用户没有确认助手提出的路线时，保留为拟议目标，不记成用户承诺。

例：能根据问题与历史选择原样通过、改写或澄清；改写后保留实体、时间、限制条件和任务意图，并解释理由。仅写“了解 Query 改写”不足以指导检查。

### 何时检查，何时直接继续

- 用户要求测验、练习或检查掌握时，执行理解检查。
- 用户已经给出推理、解释或实践结果时，直接据此核对，不为留痕额外出同类题。
- 核心概念讲清、小节结束，或重复出现同类困难时，可以提出一个短任务；等待真实作答，不能自行代答后记为通过。
- 普通事实问答、纯笔记整理、只读 Review、用户明确不测时，不强制插入测验。
- 用户跳过、不作答或转向新问题时继续其任务，记录仍待验证而非答错；不反复催问。

### 一次检查的执行顺序

1. **选目标与任务**：只检查当前目标需要的能力；概念用解释／反例，边界用辨析，流程用新输入推演，技能用小实践。
2. **准备判断依据**：先明确必要要点、可接受变体和关键错误；核对题目所需事实。开放问题允许多种合理方案，不把助手个人偏好当标准答案。
3. **给题并等待**：出题阶段不主动展示答案或泄露关键步骤。若用户要求答案则提供，但不能据后续照述判为独立完成。
4. **反馈真实表现**：先说明成立的部分，再指出缺口和理由。卡住时从小提示开始，必要时完整讲解；不强制猜测。
5. **记录条件与结果**：记题目／情境、回答要点、是否看笔记或收到提示、判断依据、仍需什么证据。题目有歧义或依据不足时先修题或标待核，不归为用户错误。
6. **决定下一步**：继续学习、针对缺口补强，或换情境／隔段时间再次验证。用户作答前不提前写结果。

以上描述可用简短自然语言完成，不要求每次展示全部执行字段或长评分报告。

## 个人理解状态：以证据描述，不推算总掌握率

| 状态 | 何时可以记录 | 下一步 |
| --- | --- | --- |
| 待验证 | 已讨论但未作答、已跳过，或只有“懂了” | 在合适时机给独立解释或应用机会 |
| 待补强 | 实际回答暴露了影响当前目标的缺口，题目及判断依据可靠 | 记录具体缺口，针对性解释后再验证 |
| 提示后完成 | 经提示、看过关键解法后，完成当前任务 | 换题检查能否独立完成 |
| 独立完成（限定任务） | 未提供针对性解法，用户自主完成且满足事先确定的要点 | 如目标需要，追加迁移或延时验证 |

开放资料任务允许查阅指定资料；必须标明条件，不能把它当成脱离资料的记忆表现。助手刚给过同题完整答案后，直接复述不算独立完成。迁移与延时是证据条件，不自动构成统一的“最高等级”。

结果按具体目标记录，不能用一道题覆盖整门课程；再次表现有缺口时更新当前判断，保留先前有效证据及条件。只记录有证据的困难，不从提问次数、阅读速度或答题时长推断心理特征与能力。

继续分开维护三类状态：知识笔记的 `status: seed/developing/evergreen`、事实核验状态、个人学习表现。不给笔记新增一个混合三者的“掌握分”，不因测验答对升级知识笔记成熟度。

## 记录放在哪里，怎样避免重复

### 沿用现有职责

| 内容 | 保存位置 |
| --- | --- |
| 可复用定义、解释、误区及方法 | 既有 Knowledge 概念／案例页 |
| 知识关系与长期阅读路线 | 既有 MOC，必要时按 MOC 规则维护 |
| 当前课程目标、作答表现、提示条件、再次验证安排 | 对应来源笔记的“用户理解与校准”“学习接续” |
| 来源未知或纯对话学习 | 优先复用 `20_Sources/Notes/Conversations/` 中对应记录，注明来源情况，不虚构课程 |
| 笔记 Review 的 F 编号与修订状态 | 按维护与评审流程的完整 Review 报告规则，不当作个人错题编号 |

跨课程复习同一知识点时，先找原有理解记录，必要时引用。新表现记在本次课程／学习记录里并链接旧证据，标注日期、任务和条件；不复制通用解释，也不把不同阶段的有限表现当作相互矛盾。

### 记录的最小内容

[来源模板](Templates/来源笔记模板.md)提供可选的目标、理解证据与接续区块。记录日期、任务、回答要点、提示／资料条件、判断依据和下一次验证；接续只摘要当前进度并引用证据，不重复整张表。

不为现有所有来源强制补表。只在实际产生学习目标或验证记录时添加；无作答不预生成大量空行。复杂回答的必要证据可放表后短段落；再次验证更新当前摘要，历史重要变化保留在同文的历史记录，不覆盖成从未出错。

来源笔记可以记录一条“本节理解尚待验证”，无需把每个知识点都登记为未完成任务。只有有学习价值、近期需要追踪的目标进入复习安排，避免形成无穷队列。

## 复习与恢复学习

先采用“再次进入主题时检查”的轻量方式，暂不建立自动提醒或全库调度系统。

1. 用户要求继续某课程时，读取对应来源接续，并按需读取已关联的理解证据；不从最近修改文件猜课程。
2. 有具体新问题先处理新问题；只有相关、重要的待补强／提示后完成项，才简短提示复习机会。已有“直接继续”“暂时不复习”偏好时遵从。
3. 用户明确要求复习时，默认选择 1–3 个相关目标，优先关键前提、重复困难和仅有提示后成功的项目；正常学习不因清单存在而被强制阻塞。
4. 复习任务尽量换表述或情境。正确回答只更新覆盖到的目标；出错时补强相应缺口，不把全部学习进度清零。
5. 已有独立完成证据且当前无需追踪的条目，可退出近期复习安排；这只代表暂不优先复习，不声称永久掌握。

默认“下次验证”写具体触发时机，如“下次学习本课时”“进入多路检索前”。用户需要日历计划时，再结合目标期限与可用时间制定日期，并使用实际用户时区；1／3／7／14 天只可作为可调整的候选安排，不作为已验证的通用最优值。

过去的计划日期到期不代表已经复习。未按期完成只表示未执行，不判遗忘或答错。文件中的计划不自动创建定时任务；用户明确要求提醒或后台跟进时，才使用相应自动化能力。


## 来源与接续

开始时搜索相关 MOC、知识与来源，兼顾别名及中英文表达；优先复用同一来源记录。同一课程可记录多个小节，只有实际维护需要时再拆分。区分“本次无指定外部学习材料”和“用户转述外部材料，出处未提供，未核对原材料”，助手补充的资料单列。

主题明确、需要长期接续的纯对话或外部出处未明的学习记录保存到 `20_Sources/Notes/Conversations/`，从 [Sources](../20_Sources/Sources.md#对话学习记录) 找入口。优先复用同一学习上下文的记录，不按每次会话建文件；尚未厘清性质的输入才进 Inbox。课程出处明确后依据真实材料决定转接，不能仅因主题相似合并。早期 Embedding 截图记录保留历史证据并转接正式课件记录，恢复时沿转接读取当前进度。

在一个学习段落有进展或用户暂停时，更新对应记录的唯一当前“学习接续”：最近实际学习日期、已知章节／时间戳、核心问题及知识链接、真实表现、待核事实／待实践、下次入口。未知进度不补造；旧阶段可保留但明确标为历史或转接。多个实质候选无法区分时才询问，不以最近修改文件猜课程，不用全局当前学习文件覆盖多个上下文。

学习记录保存来源范围、重要理解变化和接续；详细解释在知识主文，不复制一套正文，不自动保存整段私密对话。结束主题时按需去重、补边界、整理有关 MOC；缺少贯通理解时可补有来源说明的完整案例，不自动启动全套 Review。

保存后执行[组织验收](知识组织规范.md#保存前的验收)，核对关键结论与依据、原意与补充、理解证据、教学示例与实测的区分。反馈实际保存文件及未验证部分；没有文件访问能力时仅称草稿，不称已入库。

## 方法来源与试用边界

原 2026-10-05 草案参考 [learn-skill 的固定版本](https://github.com/ai-dachui/learn-skill/blob/e8cda134603ff8599e73d11839e806c5dc3430e7/skills/learn/SKILL.md) 的模式、检查与复习思路；本流程为项目约定，不宣称教学效果已经实验证明，不继承外部文件的工具或权限要求。

可在用户实际学习 Query 改写时，检查原样通过／改写／澄清的选择、意图与约束保留、程序模拟与检索效果的区别。首次只给一个任务，愿意继续再扩展；角色扮演和预设答案只验证流程。用户未作答时保持待验证；跨会话或延时效果尚未发生时明确未验证。若流程打断学习，先减少主动检查和追踪目标，保留已产生的真实证据。

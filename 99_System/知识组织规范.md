# 知识组织规范

更新：2026-10-24。合并原知识笔记组织规则与 MOC 规则，集中维护内容与导航判断。

本文维护知识笔记的颗粒度、概念与案例的分工、复杂内容的表达结构，以及整理后的验收标准。适用于各主题的知识整理；来源记录、Ideas 与 Projects 按各自用途组织，不机械拆成概念词条。目录职责见 [目录结构说明](目录结构说明.md)，导航结构见本文“地图的创建与维护”。

核心约定：**概念独立成篇，案例串联应用，MOC 组织阅读；一处维护完整解释，各处保留必要上下文。**

## 按独立问题确定颗粒度

概念、方法或判断满足以下条件时，应有独立笔记，而不是长期埋在案例或上位概念的小标题中：

- 离开当前课程、案例或会话，仍能回答一个明确问题。
- 能被其他笔记直接引用，不必带上整个案例背景。
- 已有足够内容说明定义或结论、必要例子、条件或误区，独立后不只是转发链接。
- 具有自己的维护边界：以后补充这个问题，不应迫使另一篇案例持续扩张。

新建前搜索同义名称与已有内容。优先复用回答**同一问题**的笔记；标题相关或已有文章还能容纳更多段落，不构成把独立概念继续合写的理由。只有新增例子、参数细节或另一种说法时，优先补充现有笔记。

颗粒度不按字数、标题数量或课程节次判断，也不要求每个名词单独建文件。一个概念的紧密变体可共同解释；同义名称用别名；只有一两句且尚未形成有效认识的术语先用普通文本，不创建空节点。组合方法可以有独立笔记，说明组成部分如何共同工作，并链接各部分的完整解释。

例如，TF、DF、IDF 各自有独立统计含义，TF-IDF 则回答如何组合它们；N-Gram 中的 Unigram、Bigram、Trigram 目前可作为 N 的不同取值共同说明。这些是边界判断示例，不是要求其他主题照搬同样的拆分数量。

## 按内容角色分工

| 内容角色 | 主要任务 | 保留内容 |
| --- | --- | --- |
| 概念／方法笔记 | 解释是什么、怎么算、何时适用 | 定义、必要推导、最小例子、适用条件、误区与依据 |
| 判断／辨析笔记 | 解释为什么成立、哪些情况例外 | 明确结论、推理、反例与边界 |
| 案例笔记 | 展示怎样解决完整问题 | 任务、输入、处理步骤、关键中间结果、输出及解释 |
| MOC | 提供查找与阅读路径 | 问题入口、概念关系、选择依据及真实链接 |
| 来源笔记 | 保存出处与学习接续 | 来源范围、核验记录、理解证据、进度和知识入口 |

这些是内容分工，不新增强制的笔记类型或目录。概念、方法、判断和案例均可沿用 `type: knowledge`。章节按内容需要选用，不为满足模板强行补空章节。

上位概念笔记仍需解释自身，不能拆成只有链接的空壳。它可以概述与其他概念的区别，但专项定义、推导和长篇反例由对应笔记维护。

## 复杂笔记按金字塔原理组织

**复杂笔记先回答核心问题，再分层展开支撑这一回答的理由、过程与证据。** 读者应能先抓住主线，再按需要深入细节。整理时可以从材料归纳观点；写作时让已经获得支持的核心认识先出现。

### 方法依据与不确定时的查阅顺序

笔记的内容组织直接参考 [[金字塔原理：结构化思考与表达]]。该笔记及其关联概念页维护方法解释与原书依据；本规则维护方法在知识库中的适用条件、执行步骤和验收要求。新建或修订复杂笔记时，先对照总览确定中心回答、支撑关系、分组与顺序，再按下文组织正文。

对内容组织的判断不确定时，实际查阅相关内容后再决定，不只凭“结论先行”口号或套用模板：

1. **先查总览。** 从 [[金字塔原理：结构化思考与表达]] 找到对应原则与边界，说明当前结构具体哪里不清楚。
2. **再查专项方法或案例。** 按下表定位，不要求每次读完所有关联笔记。
3. **仍不确定时回原书。** 经 [[《金字塔原理》阅读记录]] 的章节页码查阅原 PDF；提取文字与图示、顺序有冲突时核对原页。依据仍不足时保留疑问与当前判断理由，不新增未经支持的硬性要求。

### 何时使用

当笔记需要综合多个子问题、多步推理、方案比较或跨概念流程，读者容易读完细节却不清楚整体认识时，采用下面的方法。复杂度按理解负担判断，不设字数、标题数或固定层数门槛。简短定义、单一公式和一问一答可以直接说明，无须套完整结构。

### 怎样组织正文

1. **确定核心问题与范围。** 明确本文供谁使用、主要回答什么、在什么条件下成立。若缺少背景会妨碍理解，可用 SCQ（背景 Situation、变化或困难 Complication、问题 Question）简短引入，然后给出回答；问题已经明确时直接作答，不强行编造冲突或铺设长导语。
2. **先给出有内容的核心认识。** 在开头用一小段概括答案、主要依据或处理路径，并就近说明影响判断的关键条件。“本文介绍三个方面”只是在报目录，不能替代认识。尚未形成结论时，先写已确认的认识、尚未解决的问题和缺失证据，不为满足结论前置而把假设写成事实。
3. **纵向建立支撑关系。** 一级章节分别展开核心回答所需要的理由、步骤或子问题；下一级提供解释、推导、证据和例子。归纳段的上层观点应概括下层共同表达的认识；演绎段须保留前提到结论的推理链，不能把相互依赖的推理环节伪装成并列理由。每节都应能说清它在回答上层的哪个问题。
4. **横向按同一问题分组。** 同一组的并列项采用一致的分类角度和相近的抽象层次；例如一组“原因”不混入“实施步骤”和“案例名称”。检查有无重复论述、遗漏必要因素或无关分支。需要划分选项时，可用 MECE（相互排斥、整体穷尽）检查约定范围内的覆盖；现实因素有交叉时改用合适维度或明确采用多标签，不把重叠分类称为已满足 MECE，也不固定为三点或五点。
5. **按关系安排顺序。** 流程按时间或依赖顺序，系统解释按组成关系，方案比较按共同维度，建议按明确的优先级或判断标准展开。需要证明的结论保留必要推导；案例先给任务、方法和结果概览，再按输入、处理、中间结果、输出展开。不同章节可以采用不同顺序，但同一组的顺序应有理由。
6. **让细节可追溯、标题可导航。** 标题尽量呈现具体问题、判断或步骤，避免连续使用含义不明的“其他”“补充”；正文也要有清楚的主题句与必要过渡，不能依赖标题才能读通。每个分论点附近保留支撑它的材料、最小例子或推导；会改变结论的前提、反例和不确定性就近说明，再按需集中整理边界。背景资料与扩展讨论可后置，但不能把理解主线必需的证据全部藏到外链。

写完先只读开头与各级标题，检查能否看出问题、回答和展开路径；再从细节向上核对每层概括是否获得支持。发现概括过强时收窄结论或补充依据，不以重新分组掩盖证据不足。

### 与现有笔记规则怎样配合

- 本方法组织一篇笔记内部的表达；独立概念仍按前文的颗粒度标准判断。知识关系继续由链接和 MOC 表达，不把金字塔层级变成强制目录树或唯一父子归属。
- 案例必须保留完整推理和关键中间结果。开头的概览帮助定位，不能代替正文的具体演算；数学证明、实验记录和来源原文摘要保留必要顺序，并区分原材料与整理者的概括。
- 在本次授权的新建或修订范围内应用，不因此批量改写旧笔记。小节 Review 的“D6 文章组织与可读性”按本规则检查：报告读者难以抓住主线、分组混乱或概括缺少支撑等具体问题，不把缺少 SCQ 小标题、固定层数或特定文风本身当成缺陷；评审仍默认只读。

## 同时保证概念可查与案例可读

通用定义、公式变体、完整推导和通用误区集中在对应概念笔记。案例保留理解当前步骤所需的简短定义、采用的公式与具体代入；允许必要复述，避免在多篇文章中维护多套完整解释。

案例应形成文内闭环：读者不打开本地课件或代码，也能知道任务与输入是什么、执行了什么处理、怎样得到结果，以及结果说明什么。为此保留必要的原文片段或摘要、字段含义、教学数据、关键中间值与推荐／判断依据。不要把这些具体材料拆走后，只留下“详见某笔记”。

概念笔记也应有足够的小例子或解释，可以单独理解核心问题；完整跨概念应用用链接关联。概念页说明方法，案例页演算该方法在具体输入上的表现，二者不必复制同一套长案例。

链接用于深入阅读，不能代替当前推理的必要前提。自拟示例、原始材料摘要和实测结果须区分；理解案例与精确复现完整实验是不同要求。需要完整数据、代码和依赖才能复算的部分应明确说明，不声称摘要足以重现实验。

## 命名、归属与关系

- 标题对应稳定、明确的问题或概念；范围过宽时加限定，如“向量的 L2 归一化”，避免把特征权重、模型参数和不同归一化操作混在同一词条。
- 按笔记自身主要问题归档，不继承它最初出现的课程或案例目录。例如余弦相似度与 L2 归一化属于基础理论，酒店推荐案例属于应用实践。
- `Notes/` 下的主题目录负责文件定位；`topics` 记录主题，`domains` 记录五大学科视角，MOC 提供阅读与查找入口。学科可以多选，正文只存一份，不要求把文件搬入五套学科目录。
- 有明确、稳定的主题群且能改善定位时，可在授权范围内使用浅层主题目录；不按数量自动建目录，也不为单篇笔记强造分类。已有主题目录不适合时可以暂留 `Notes/` 根目录，但仍须填写恰当属性并接入相关 MOC；根目录不作为“未分类”收件箱。
- 一个问题只维护一份主要正文，可被多个 MOC 引用。跨主线可发现性靠直接入口与链接，不靠复制文件或扩大目录树。
- 独立笔记应在相关已有 MOC 中获得直接入口，不只链接到上位文章的小标题；无需每篇都加入 Home，也不因拆出新笔记就新建 MOC。
- 用邻近文字说明链接关系，如“由 DF 计算 IDF”“案例应用 TF-IDF”“余弦比较向量方向”。只连接真实有关的内容，不把所有笔记两两链接。

## 增量整理与拆分

日常学习在当前主题范围内按以上标准整理；不要等一篇文章已经过长才提取已成形的独立概念。对旧笔记按当前任务逐步修订，不因本规则生效就自动全库迁移、删除或重构。

拆分前检查相关文件、未提交修改与已有入链，明确哪些内容迁移、哪些摘要和案例材料留下。提取时让定义、条件、来源依据一同迁移，保持实测与教学示例的标注；不把助手解释或用户对组织方式的满意升级为知识掌握证据。

拆分后同步更新相关 MOC、来源问题索引、自链接和旧标题锚点的入链。保留有价值的独特内容与学习证据。新文件按实际创建日期记录，既有文件保留创建日期；不因拆分提高成熟度或核验状态。

评审默认只读、学习写入授权及文件操作边界继续遵循 [AGENTS.md](../AGENTS.md)；已经获得的对应授权不需要重复确认。

## 保存前的验收

围绕本次涉及的内容检查，不要求巡视全库：

1. **概念可查**：独立问题能直接找到有实质内容的笔记，并从相关 MOC 进入。
2. **文章可读**：概念页能单独解释核心问题；复杂笔记开头能抓住核心认识，分组与顺序清楚，各层概括有下层支持；案例保留输入、步骤与结果的推理链，不依赖临时本地材料理解。
3. **解释可维护**：通用解释有明确主文；其他文章只保留必要摘要、关系说明和具体应用。
4. **迁移可追溯**：来源及支持范围、重要条件和学习证据没有丢失；链接、标题锚点、属性与公式示例没有因整理受损。

结构检查可以证明入口和引用有效，阅读体验仍以实际使用反馈改进；不把文件增多或篇幅变短当成成功标准。

## 属性与模板

属性表达文档性质，不代替正文证据。模板位于 [Templates](Templates/)，按实际内容保留字段和章节，删除空占位与编写提示，不为填表制造内容。

| 字段 | 使用约定 |
| --- | --- |
| `type` | `knowledge`、`source`、`map`、`idea`、`project`；概念、方法与案例可共用 knowledge |
| `status` | 按文档类型使用；知识的 seed 表示待展开，developing 表示正在形成，evergreen 表示经过持续整理的稳定笔记。解释完、搬迁或答对一道题均不自动升级 |
| `topics` / `domains` | 主题与学科视角；domains 可多选 Constants（形式科学）、Matter（自然科学）、Tides（社会科学）、Echoes（人文学科）、Engines（应用科学），不强制唯一目录归属 |
| `ai_area` | AI 正文按主要问题填写；六条主线的目录、范围与取值见[目录说明](目录结构说明.md#跨层级归档规则ai)，非 AI 正文不添加 |
| `created` / `updated` | 实际创建与更新日期；保留历史创建日期，不知道时不补造，拆分的新文件记录实际创建日 |
| `source` | 优先链接来源笔记；YAML Wiki 链接带引号，多来源可用带引号的列表 |
| `source_type` / `source_url` / `author` | 按实际出处填写，未知信息留待说明；不为纯对话伪造外部来源 |
| `as_of` | 信息适用的有效时间；法规、价格、版本及产品能力等注明范围，不能以访问日期冒充有效时间 |

成熟度、具体主张核验程度、个人学习表现分别判断。事实证据与实践边界见[维护与评审流程](维护与评审流程.md#共同证据标准)，个人表现见[学习与复习流程](学习与复习流程.md)。标签主要标记待整理、待验证等临时状态，不另建重复分类体系。实体、公司、产品或模型品牌用属性和真实链接表达，不因名称出现就建目录。

正式知识保持客观表述；用户曾经的错误理解只有附纠正与真实出处时才保留为误区，不能当作当前结论。无依据的争议先保留待验证，不覆盖原结论。

## 地图的创建与维护

MOC 回答从哪里进入、先看什么、知识有什么关系。浅目录存文件，地图表达关系；先长章节，再按独立导航需要建图。五大学科保留稳定导航视角，专题增长按以下标准判断。

### 先判断需要什么

| 当前需要 | 默认做法 |
| --- | --- |
| 解释一个概念、原理或方法 | 补充或新建知识笔记，不自动配一张 MOC。 |
| 把几篇相关笔记放在一起 | 在已有 MOC 中增加一个有意义的章节，并说明关系。 |
| 为一个问题提供独立、可反复使用的阅读或选择路径 | 满足下文条件后，将章节提炼为专题 MOC。 |
| 记录某次课程、学习进度、作答与掌握证据 | 写入对应学习记录，位置按学习流程处理，不因结课另建地图。 |
| 一组 MOC 已形成稳定的大主题群，文件定位确有困难 | 评估浅层文件夹分组；不随每个新概念创建子目录。 |

这些不是必须依次完成的晋级流程。已有明确导航需求和材料时可以直接建 MOC；笔记数量多、学习结束或名称听起来像“大主题”，都不是独立的创建理由。

### 何时新建专题 MOC

先检索已有地图和章节。新建前应能回答三个问题：

1. **独立性**：这张地图帮助读者解决什么导航问题？现有地图的一个章节为何已不便承担它？
2. **组织价值**：它提供了什么阅读顺序、概念关系、方案比较或按问题查找的路径，而不只是重复罗列链接？
3. **持续价值**：离开这次课程或会话后，它是否仍值得反复进入，并可继续吸收其他来源的知识？

没有明确答案时，先保留在已有章节中。已有材料应足以支撑实际导航，不为预想中的知识体系批量建空地图。不设置“满几篇笔记就必须建图”的硬门槛。

### 一张地图最少需要什么

- **问题与范围**：用简短文字说明它组织什么；容易与其他地图重叠时，说明分工。
- **知识脉络**：按问题、过程、对比或阅读顺序组织真实链接，必要时用一句话解释关系。定义和方法正文留在知识笔记，不复制一套。
- **可发现的入口**：从至少一张相关的现有 MOC 提供入口；全新主题没有合适 MOC 时，可从 Home 建立主题入口。地图内给出返回或横向关联，避免成为孤立文件。

按内容使用模板，删除无用空章节，不新增强制的父主题、层级编号或维护人字段。标题优先使用稳定主题或问题，不以课程节次、日期区分同一主题的多张地图。

同一笔记或地图可以被多个入口引用；正文只维护一份，不要求唯一父主题，也不复制成多份来适配分类。

### 专题入口展示组织结构

专题统一入口在“归档与维护边界”中展示本专题的实际组织结构，让读者在当前入口就能知道知识、来源与实践分别放在哪里。目录职责总表仍由 [[目录结构说明]] 维护，专题入口呈现与当前阅读有关的局部结构。

- 按规模使用目录树、路径表或简短说明，标明各路径的用途；不必复制全部文件清单，也不以目录树代替按问题组织的知识脉络。
- 区分专题专用目录与共享目录、现有内容与计划位置；已有但暂无正文的目录如实注明，不为展示结构新建空目录或笔记。
- 子地图说明自身的归档位置和相邻内容边界，并链接专题主入口的完整结构，避免每张地图重复维护同一棵树。
- 尚由领域地图的章节承担入口的小专题，可在该章节补充局部结构，不必为此单独建图。
- 目录或用途调整时同步更新相关专题入口；涉及全库目录说明的维护范围时，也更新目录说明。普通新增笔记只维护必要的阅读入口，不要求每次重列目录。

### 地图与学习记录如何分工

长期可复用的问题、关系、阅读路线和自查题可以留在 MOC。课程出处、学习日期、进度、实际作答和个人掌握证据保留在对应来源笔记（包括 Conversations 对话学习记录）；MOC 可以链接它们作为出处，但不重复维护进度。

按内容用途判断，不按文件是否叫“学习地图”机械搬迁。再次学习同一主题时，优先补充既有地图；只有出现独立的长期导航需求，才考虑另一张地图。

### 如何保持浅而清晰

- **目录按稳定主题群分组**：已有 AI 主题群集中在 `Topics/AI/`，规模较小的法律主题可以继续保留为 `Topics/法律.md`，不为形式对称创建空文件夹。
- **脉络主要写在地图中**：专题之间的上下文关系不必逐层对应文件夹。只有既有地图形成可解释的稳定分组、且确实改善文件定位时，才评估下一层目录；不预建整套分类树。
- **避免把深目录换成深链接链**：入口应能按问题直达关键笔记或专题，不要求逐级下钻。经常来回寻找或反复点击只是层层转发的页面时，补直接入口或合并空壳导航，不机械规定统一跳数。
- **总入口不做全量清单**：Home 与大主题入口突出主要路径，细节交给相关地图；高频内容可直达，不必每新增笔记就更新所有上层 MOC。

### 何时维护，怎样调整

在当前主题增加内容、阶段收尾或实际找不到内容时，检查相关地图即可；不要求每次学习都巡视全库，也不设固定清理周期。

| 发现的问题 | 优先处理方式 |
| --- | --- |
| 地图变长，难以扫描 | 先按问题整理章节、突出主要入口；只有某组内容形成独立导航任务时才拆图。 |
| 地图只有很少内容，几乎只是转发 | 判断是否仍有必要的入口或独立导航价值；没有时，考虑折回相关地图的章节，不因笔记少就机械合并。 |
| 多张地图范围高度重叠 | 先明确分工；没有独立价值的重复地图再考虑合并，保留独有内容与关系。 |
| 同一知识在多个 MOC 中重复展开 | 将正文集中到对应知识笔记，各地图保留符合自身语境的简短导读和链接。 |
| 旧地图暂时不再常用 | 可降低入口显著程度；仍有知识价值时继续保留，不因近期没访问就删除或归档。 |
| 学习日期、完成状态混入长期地图 | 将进度与证据归回对应学习记录，地图保留长期导航；来源链接不必删除。 |

日常学习可增补相关章节、链接和导读。涉及目录调整、批量整理，或合并后需要移动、删除旧文件时，先说明范围与引用影响，取得对应授权后再执行；提出维护建议不等于已经完成迁移。

执行合并或迁移时保留原有独特内容、来源和学习证据，并同步检查文件链接、标题锚点与入口。旧文件的删除或归档不能作为无关学习任务的顺手清理。

### 放到现有 AI 主题中如何判断

- 新学一个检索方法：先补相关笔记，并在既有 [提示词与 RAG 地图](../10_Knowledge/Maps/Topics/AI/提示词与RAG：学习地图.md) 中组织；不因学完一节视频另建地图。
- 后续增加混合检索、排序和评测内容：先检查既有地图能否用章节容纳；其中某部分真的需要独立阅读或选型路线时，才评估提炼专题 MOC。
- Agent 的相关笔记增加：先维护 [AI 工程系统](../10_Knowledge/Maps/Topics/AI/AI工程系统.md) 的 Agent 章节；是否独立建图看导航价值，不看数量是否达到某个阈值。

这些示例用于帮助判断，不要求对现有地图进行一次性批量改造。

### 完成一次维护前的检查

- 新建地图有独立用途；未新建时，相关内容也能从已有入口找到。
- 组织方式体现关系或使用路径，没有重复正文、空壳节点或为凑结构创建的文件夹。
- 相关文件链接与标题锚点有效，必要入口已同步，没有强制唯一归属。
- 专题入口的局部结构与实际位置一致，共享目录、空目录和计划位置没有混淆。
- 长期导航与本次学习进度分工清楚；来源、个人掌握证据未丢失。
- 若涉及目录职责变化，同步更新目录说明；如实说明修改范围与尚未执行的建议。

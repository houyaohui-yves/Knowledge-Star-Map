# PDF 转文本工具：实施方案与使用说明

版本：v1.0 · 2026-09-26  
状态：方案已整理，待用户指示开始开发。本文的命令、目录及接口均为拟定设计，目前尚未实现。

## 1. 目标与交付范围

构建本地命令行工具 `pdftext`，把 PDF 转换为可缓存、可按页读取的 UTF-8 TXT 或 Markdown。后续在本知识库中提供 PDF 时，助手先调用工具，再按任务需要读取正文。

首版支持：

- 有文字层的 PDF、扫描 PDF，以及两者混合的 PDF。
- 单页、左右双页扫描，以及同一文件中混合这两类页面。
- 中文印刷体为主，兼顾英文、数字及常见标点。
- 单文件、目录批处理、指定页段、版式覆盖、缓存和异常报告。
- 只提取文字；不描述插画，不调用 GPT 总结、纠错或补写。

不承诺完整还原复杂表格、公式、手写、艺术字、文字拼贴和被遮挡内容。不把横向单页或双栏文章一律视为双页；复杂阅读顺序可标记待核对。

## 3. 技术方案

### 3.1 技术选型

| 组件 | 选型 | 职责 |
| --- | --- | --- |
| 程序入口 | Python CLI | 参数、批处理、报告、缓存与读取 |
| PDF 检查与提取 | pypdf、pdfplumber | 页数、文字及坐标、内嵌图像 |
| 图像处理 | Pillow，按需使用 OpenCV | 分区、方向与倾斜校正 |
| 扫描文字识别 | RapidOCR + ONNX Runtime | 本地文本检测与中文识别 |
| 复杂页面渲染 | Poppler 页面渲染工具 | 无法安全直接提取整页图像时，渲染完整页面 |
| 结果保存 | TXT / Markdown + JSON | 正文、页码映射、质量报告 |

当前运行环境已有 pypdf、pdfplumber 和页面渲染能力。OCR 依赖、模型及与本机 Apple Silicon 的兼容性需在实施时验证；安装到独立环境，固定验证通过的版本，不修改共享运行时。

RapidOCR 是首选候选引擎，不宣称其对本样本已优于其他引擎。先做代表页验证；若中文识别不达标，再评估 Tesseract 或 PaddleOCR。首版不同时维护多个 OCR 后端，也不引入 Docling、向量数据库、云端 API 或常驻服务。

### 3.2 逐页处理流程

```text
输入文件或目录
  → 文件检查与缓存匹配
  → 逐页检查文字层、图像与版式
  → 有效文字层：按坐标提取
    扫描或异常区域：获取图像并运行 OCR
  → 单页直接处理 / 双页分区处理 / 不确定页标记
  → 按阅读顺序整理行和段落
  → 保守过滤页眉页脚与装饰文字
  → 保存正文、页码索引、质量报告
  → 终端只返回简短摘要和结果路径
```

不能仅凭“提取到几个字符”认定整页完整：只有页码的扫描页也需要 OCR；图文混合页可能需要区域识别。通过文字分布、图像覆盖和异常字符等信号判断，避免重复合并同一段文字。自动检测无法证明没有遗漏，需保留报告与抽查能力。

只有确认图像完整覆盖页面、方向和变换可正确还原时才直接提取原图；多图拼接或存在裁剪、旋转、叠加对象时使用完整页面渲染。样本适合优先尝试原图提取。

### 3.3 单页与双页适配

| 参数 | 行为 |
| --- | --- |
| `--layout auto` | 默认；逐页综合判断，不对整份文件做一次性假设 |
| `--layout single` | 将选中页面作为单页处理 |
| `--layout spread` | 将选中页面分成左右区域，默认先左后右 |
| `--single-pages` / `--spread-pages` | 指定页覆盖自动结果；两者重叠时报错 |

自动判断综合页面比例、中部连续空白、文字框分布，以及可获得的页眉页码线索。中部空白只是一项证据。需要 OCR 布局信息时先检测文字框，避免不必要地执行整页和分区两轮完整识别。

双页分割优先寻找实际中缝，不直接固定按宽度 50% 裁切。特殊页不套正文裁剪规则。封面、横向单页、双栏文章可能相似，无法可靠区分时不进行不可逆裁剪；保留全文候选和不确定标记，允许按页覆盖后重跑。

“单页”表示一个书页，不意味着文字一定只有一栏。首版尽力整理常规多栏顺序，但不保证复杂杂志布局准确。

所有页段参数使用从 1 开始的 **PDF 物理页码**。输出同时保留物理页码、左右分区和可识别的印刷页码；印刷页码仅为辅助信息，不能替代物理页码。

### 3.4 正文整理与水印处理

- 根据文字坐标、缩进和行间距恢复段落；中文换行不机械添加空格，保留英文词间空格。
- 固定区域、跨页重复的页眉页脚可过滤；封面、章节标题和正文中的重复句子不能全局删除。
- 优先通过区域和重复模式排除装饰，不实施通用去水印修复；与正文重叠的水印可能影响结果。
- 低置信度文字保留并标记，不直接删除。OCR 置信度不是准确率，也不能发现所有漏字。
- 不猜测黑条下文字；检测到或人工确认的遮挡标记为“原文遮挡”。首版不保证自动发现所有遮挡。
- 拼贴、竖排艺术字等区域标记特殊；不能以普通正文无异常的状态交付。
- Markdown 以页码标题和自然段为主，不凭空生成章节标题或语义结构。

### 3.5 输出、缓存与容错

工具拟放在 `99_System/Scripts/pdftext/`，提供依赖清单、启动入口、测试和使用文档。

默认在输入文件同级的 `_extracted/` 下建立结果目录：

```text
_extracted/江寒A-1本-<内容哈希前缀>/
  document.md       # 默认正文；可改为 TXT 或同时输出
  pages.json       # 页码、分区与正文位置映射
  report.json      # 每页状态、参数、版本、告警与处理耗时
```

中间图像和完整 OCR 框默认进入系统缓存或临时目录，不长期堆积在知识库；调试模式可保留。不覆盖原 PDF，不覆盖来源笔记，不自动生成知识节点、提交或推送。

缓存键包括完整文件哈希、处理参数、工具版本和 OCR 模型标识；参数变化重新处理对应结果。使用临时文件加原子替换，防止中断留下看似完成的正文。原文件移动后更新来源位置记录。

输出区分“成功”“完成但需核对”“部分失败”“失败”。空正文不静默视为成功。批处理遇到单文件失败继续处理其他文件，并汇总失败列表。提供单页超时、文件资源边界和清晰错误提示。密码文件需用户提供合法密码，密码不写入日志或缓存。

## 4. 成本与收益评估

### 4.1 Token 与外部费用

推荐配置完全本地转换，PDF 提取和 OCR 的外部 API 费用为 0。首次安装、模型下载和本地运行仍消耗网络、存储、电力及计算时间。

AI 调用工具、读取报告和正文依然消耗 token。收益来自减少页面图像输入、避免重复识别，以及只读取相关页段；把相同正文从 PDF 改为 Markdown 本身不会显著压缩正文 token。

若原工作流本来就只提取文字，格式转换收益可能有限。文件体积缩小比例不能当作 token 节省比例。实施后记录输出字符数、实际读取范围和耗时；如需 token 估算，使用指定模型对应 tokenizer，并明确它不是订阅额度或实际账单的精确预测。

### 4.2 工程量

| 工作项 | 估算工程量 |
| --- | --- |
| 依赖兼容与代表页 OCR 验证 | 0.5–1 工程日 |
| 文字层/OCR 流程、单双页适配、正文整理 | 1–2 工程日 |
| CLI、批处理、缓存、按页读取、报告 | 0.5–1 工程日 |
| 样本验收、文档、项目学习流程接入 | 0.5–1 工程日 |
| 总计 | 2.5–5 工程日 |

以上为工程工作量，不是实际墙钟完成时间承诺，也不是收费报价。相比此前仅针对一类样本的原型估计，本方案新增了混合版式、覆盖参数、批处理、容错与完整验收，因此正式版本预算上调。仅验证样本的最小原型仍约为 0.5–1 工程日。

### 4.3 本机资源与运行成本

CPU 即可作为首版目标，不要求购买 GPU。预留数 GB 级环境、模型与临时空间作为安装预算，最终以选定版本实测为准；逐页处理并限制并发，避免同时解码整本高分辨率图像。

文字层提取通常远快于 OCR；扫描件速度取决于像素、文字量、版式检测及机器。当前尚无样本 OCR 数据，不承诺页/秒或准确率。OCR 验证阶段分别报告首次加载时间、后续转换时间、峰值内存和缓存命中时间。

## 5. 使用说明（拟定接口，开发后可用）

以下命令从仓库根目录执行。`./99_System/Scripts/pdftext/pdftext` 为拟定启动入口，不要求用户自行激活 Python 环境。

### 5.1 在学习会话中使用

可以直接告诉助手：

> 把这份 PDF 转成 Markdown，再读取第 5–8 页讨论。

> 这份文件第 1–4 页按单页，第 5–15 页按双页转换。

助手先检查缓存或执行转换，再读取报告和相关正文；只在识别异常或需要图像信息时回看相关页面。实施时更新本项目的调用说明，保留已有学习规则。这个约定覆盖本项目，其他项目需要另外配置。

### 5.2 单文件与输出格式

```bash
./99_System/Scripts/pdftext/pdftext convert \
  "20_Sources/Files/PDFs/既往剧本杀/江寒A-1本.pdf"

./99_System/Scripts/pdftext/pdftext convert \
  "资料.pdf" --format txt

./99_System/Scripts/pdftext/pdftext convert \
  "资料.pdf" --format both
```

默认 Markdown、自动版式、自动选择文字提取或 OCR、复用有效缓存。转换命令仅打印结果路径、页数及告警摘要。

### 5.3 指定页段与版式

```bash
./99_System/Scripts/pdftext/pdftext convert \
  "资料.pdf" --pages 5-8 --layout auto

./99_System/Scripts/pdftext/pdftext convert \
  "资料.pdf" --layout single

./99_System/Scripts/pdftext/pdftext convert \
  "资料.pdf" --layout spread

./99_System/Scripts/pdftext/pdftext convert \
  "资料.pdf" --layout auto --single-pages 1-4 --spread-pages 5-15
```

最后一条仅示范人工覆盖方式，不代表所有 PDF 都采用该页段规则。

### 5.4 批处理、重跑和检查

```bash
./99_System/Scripts/pdftext/pdftext convert \
  "20_Sources/Files/PDFs/既往剧本杀/" --recursive

./99_System/Scripts/pdftext/pdftext convert "资料.pdf" --force

./99_System/Scripts/pdftext/pdftext doctor
```

目录模式默认只处理直接包含的 PDF，`--recursive` 才递归子目录。`--force` 绕过转换缓存，仍不修改原件。`doctor` 检查依赖、模型和运行环境。

### 5.5 按页读取结果

```bash
./99_System/Scripts/pdftext/pdftext read \
  "结果目录" --pages 5-8 --max-chars 12000
```

读取命令可把指定页正文返回给 AI；达到长度上限明确标记截断并返回接续位置，不能静默丢弃余文。也可使用本地文本搜索定位关键词后读取上下文。首版不建设 RAG 服务。

## 6. 验收标准与实施步骤

先完成代表页 OCR 验证，再开发完整工具。验收覆盖：

| 场景 | 检查重点 |
| --- | --- |
| 中文单页文字 PDF | 正文提取、段落、页码映射 |
| 中文单页扫描 PDF | OCR 覆盖、无整行遗漏 |
| 双页扫描 PDF | 左页全文在右页之前，无交错，无中缝裁字 |
| 封面、单双页混合 | 逐页判断，特殊页不套正文裁剪 |
| 横向单页、双栏文章 | 不因横向或中部空白直接判定双页；不确定时可覆盖 |
| 图文混合、仅少量文字层 | 不漏掉主要扫描正文，不重复合并 |
| 遮挡、拼贴、异常页面 | 保留可读内容，报告范围与不确定性 |
| 缓存、中文路径、部分失败 | 正确复用、支持空格、错误不冒充成功 |

以《江寒A-1本》的普通正文、密集正文和末尾特殊页作为真实样本；另从现有资料寻找单页样本，不足时使用受控测试样本并注明。普通正文抽样建立人工转录基准，建议字符错误率目标不高于 2%，按预先固定的空白规范化方式计算，同时单独核对人名、标点、漏行和阅读顺序。该数值是待验证的验收目标，不是已达到的性能；特殊页单独报告，不计入普通正文准确率。

最终交付：工具代码、固定依赖、使用说明、测试与样本验收报告，以及实际样本转换产物。未达到目标时明确报告原因，先调整预处理或引擎，不用 GPT 改写掩盖 OCR 错误。

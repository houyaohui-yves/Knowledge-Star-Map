# 目录结构说明

本文集中记录知识库的文件夹职责和归档边界。从根目录 [README](../README.md) 或 [System](System.md) 可找到本说明；协作维护要求同时写入根目录 [AGENTS.md](../AGENTS.md)。

## 阅读范围

- 以仓库根目录为起点计算层级：`10_Knowledge/` 是一级，`10_Knowledge/Notes/` 是二级，`10_Knowledge/Notes/AI/` 是三级。
- 下表覆盖实际存在的一级至三级内容目录及配置目录，包括空目录；不逐项介绍文件。尚未创建的规划目录不列入清单。
- 四级及更深目录由相关主题或项目入口说明；本文额外保留 AI 主线等影响全库归档的深层规则。
- `.git/` 只说明整体用途，不展开 Git 内部结构。缓存、依赖、工具生成结果等按用途说明，不枚举其内部目录；这类例外不适用于人工维护的笔记、资料或项目目录。

| 路径 | 用途与边界 |

| `10_Knowledge/Notes/Thinking/` | 思考、表达与问题分析的通用方法及应用案例；当前包含金字塔原理相关笔记，后续按问题吸收其他来源，不按书籍建立知识正文目录。 |
| `10_Knowledge/Notes/Investing/` | 投资通用知识，按基础、理念与方法、教学案例三个子目录归档；公司持续研究、账户记录与真实复盘放入投资实践项目，详见下文投资边界。 |

主题目录负责文件定位，`topics` 与 `domains` 分别记录主题和学科，MOC 组织阅读；五大学科不对应五套正文目录，同一笔记可关联多个学科。当前思考与表达笔记从 [[Engines：应用科学]] 的相应章节进入。

MOC 的创建、拆分、合并和入口维护遵循 [MOC 创建与维护规则](知识组织规范.md)。目录层级不必复制知识关系层级，课程进度与个人掌握证据不由主题地图重复维护。

读者查找某一专题的内容位置时，优先查看其统一入口的“归档与维护边界”；专题入口展示实际局部结构，本页维护全库目录职责与跨层级规则。子地图只说明自身位置并链接主入口，结构变化时同步相关说明。

### 来源与原始资料

| 路径 | 用途与边界 |
| --- | --- |
| `20_Sources/` | 知识的来源与学习证据，包括原始材料、来源笔记及如实标注的对话记录；不进入默认知识图谱。 |

| `20_Sources/Notes/` | 记录资料表达了什么、出处、阅读范围、疑点及学习接续；纯对话或外部出处未知时如实说明。主题明确的对话学习记录放入 `Conversations/`，不因缺外部 URL 而留在 Inbox。可复用认识另行提炼到 Knowledge。 |
| `20_Sources/Notes/Conversations/` | 主题明确的对话学习、用户转述与尚未识别原课程的学习记录；保留真实来源性质、理解证据和接续。出处明确后按证据转接课程记录，历史状态不冒充当前进度。 |
| `20_Sources/Notes/AI/` | 按 AI 主题集中组织的来源笔记；需要统一跟踪的 AI 专题优先放这里，通过属性注明文章、课程等来源类型。 |
| `20_Sources/Notes/Investing/` | 投资专题的外部来源笔记，如财报、公告及研究资料的出处、读取范围和核验记录；使用 `as_of` 标明时效性数据。对话学习接续仍保留在 `Conversations/`，不复制归档。 |
| `20_Sources/Notes/Articles/` | 按文章组织的来源笔记，如网页文章、独立论文与报道；已归入专题的来源不重复建档。 |
| `20_Sources/Notes/Books/` | 按书籍组织的阅读笔记、章节记录和阅读接续，与 `Files/Books/` 中的原始文件区分。 |
| `20_Sources/Notes/Courses/` | 按课程或视频系列组织的来源笔记、课程进度与学习接续；配套材料仅在本地时，保留来源、版本、获取方式和关键观察，不依赖临时文件长期存在。已按专题归档的来源可用链接引用。 |

`Books/` 与 `PDFs/` 分别侧重资料对象和文件形式，存在交叉时选择一个主要位置，以链接复用，不重复保存同一份原始材料。来源笔记也遵循同一原则：一个主要位置，多处导航引用。

小说原始资料已细分至 `20_Sources/Files/Books/Novel/Adult/`（第四、第五级）；用途见 [Sources](../20_Sources/Sources.md)，本轮版本清单与阅读范围见 [成人小说研究项目](../40_Projects/Active/AdultFictionResearch/README.md)。

### 本地工作区

| 路径 | 用途与边界 |
| --- | --- |
| `80_Local/` | 仅本机使用、无需远程长期保存的工作材料；整个目录由根 `.gitignore` 的 `/80_Local/` 忽略，不进入默认知识图谱。可按需清理，但不自动删除。 |
| `80_Local/Courses/` | 下载的课程资料、实验数据、示范程序及临时练习；有实际课程材料时再按课程建立子目录，不预建课程占位目录。 |
| `80_Local/Courses/AI大模型应用课件/` | AI 大模型应用课程的本机课件与 demo，包括 RAG 等小节；来源信息和学习进度保存在正式来源笔记，整个课程目录仍由 Git 忽略。 |

课程目录中可按需要使用 `Materials/` 保留原版、`Practice/` 保存修改代码与实验输出；这只是组织示例，当前不预建这些子目录，也不强制改造原资料包结构。小型随课练习不必逐个建立正式项目。

- **长期内容另存**：课程出处、下载地址、版本或获取说明、学习进度和关键观察保存在对应 Sources 笔记；可复用认识提炼到 Knowledge；值得持续维护的代码与成果提炼到 Projects，不连同临时数据、依赖和缓存一起搬入。
- **本地路径可能失效**：笔记中记录本地资料相对路径时，注明仅本机可用；即使清理本地文件，也应能从保留的来源信息追溯材料。
- **忽略不等于保护**：Git 忽略不提供备份或保密保护，也不控制其他网盘或备份软件。它不会自动停止跟踪已入库文件；迁入旧文件前需检查跟踪状态，不使用强制添加绕过忽略规则。
- **清理需确认**：先确认需要保留的成果和认识已保存，再由用户决定删除哪些材料；不设置自动清理，也不把其他目录的旧资料自动搬到这里。
- **新设备按需重建**：本地目录不放 `.gitkeep`，不会随 Git 克隆出现。在仓库根目录执行 `mkdir -p 80_Local/Courses` 即可重建空目录，再依据课程笔记重新获取资料；说明本身保存在受版本管理的本文中。

## 跨层级归档规则：AI

以下实际目录位于第四级，因承担全库通用分类职责，在此额外说明；主题入口是 [AI MOC](../10_Knowledge/Maps/Topics/AI/AI.md)。

**主题范围：这里的 AI 采用广义人工智能主题范围，涵盖传统机器学习、深度学习、表示／表征学习、推荐与偏好预测，以及相关工程系统、应用、产业和治理。** 正文目录按主要问题选择一个存放位置，学科关系通过 `domains` 和 MOC 表达；主题范围不要求每种方法都使用神经网络、大语言模型或显式参数训练。

主线边界按笔记回答的问题区分：通用数学、统计与学习原理进入基础理论；具体模型与预测方法的机制进入模型与训练，包括基于邻域或相似性的预测方法；系统构建进入工程系统，具体任务的完整应用流程进入应用实践。例如，协同过滤的偏好预测原理放在 `02_Models/`，完整推荐应用案例按其主要问题另行归档。

| 路径 | 用途与边界 |
| --- | --- |
| `10_Knowledge/Maps/Topics/AI/` | AI 总入口、六条主线及有独立导航价值的专题 MOC；通过问题和链接组织知识，不为每张专题地图另建子目录。 |
| `10_Knowledge/Notes/AI/01_Foundations/` | AI 的数学、统计与计算基础。 |
| `10_Knowledge/Notes/AI/02_Models/` | 模型结构与预测方法，以及训练、对齐、推断和生成机制；包含基于邻域或相似性的预测方法。 |
| `10_Knowledge/Notes/AI/03_Engineering/` | 检索、记忆、评估、部署等 AI 工程系统问题。 |
| `10_Knowledge/Notes/AI/04_Applications/` | AI 解决具体任务的实践方法与工作流。 |
| `10_Knowledge/Notes/AI/05_Industry/` | 从产业链、产品和商业模式中提炼的可复用认识。 |
| `10_Knowledge/Notes/AI/06_Governance/` | AI 安全风险、治理制度与社会影响。 |
| `20_Sources/Notes/AI/Industry/` | 发布、融资、价格、市场份额等时效性商业事实；记录 `as_of`，再将可复用认识提炼到 Knowledge。 |

`ai_area` 与六条正文目录依次对应 `foundations`、`models`、`engineering`、`applications`、`industry`、`governance`；非 AI 正文不添加此字段。

一篇 AI 知识笔记按主要问题选择一个目录，其他关系通过 Properties、MOC 和双向链接表达；公司、产品与模型品牌使用属性记录。

## 跨层级归档规则：投资

投资是长期主题入口，当前从股票起步；基金、债券、资产配置及相关经济学知识随实际内容扩展。以下第四级目录已存在，从 [投资 MOC](../10_Knowledge/Maps/Topics/Investing/投资.md) 统一进入。

| --- | --- |

| `10_Knowledge/Notes/Investing/01_Foundations/` | 概念、原理、常识与公式。公式随概念保留变量解释和适用条件，地图提供速查索引。 |
| `10_Knowledge/Notes/Investing/02_Methods/` | 投资理念、分析方法、决策和执行框架；区分通用方法、助手建议与用户形成的个人规则。 |

## 如何维护这份说明

1. **变更前查边界**：先读涉及路径的职责，检查已有目录和工作区，优先复用已有分类。
2. **变更时同步说明**：新增、移动、重命名、删除一级至三级目录，或改变目录用途时，在同一次修改中更新本文的路径、职责与边界。深层目录在主题或项目入口维护；本文已列出的深层目录也要同步更新。
3. **保持入口一致**：检查根目录 README、AGENTS 及相关导航页的链接和描述。本文集中承载目录细节，README 保留总览和入口，AGENTS 保留必须执行的维护要求。
4. **完成前对照实物**：核对实际目录与清单，补齐漏项、移除已不存在的条目、修复失效链接；不要把尚未创建的计划目录写成现有目录。工具内部结构按前述排除范围处理。
5. **按变化维护**：仅新增或修改文件、且目录职责未改变时，不必更新目录清单；不为刷新文档而批量重构目录。目录与说明的改动默认留在工作区，不自动提交或推送。

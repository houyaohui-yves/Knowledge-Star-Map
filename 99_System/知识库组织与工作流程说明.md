# 知识库组织与工作流程说明

本文解释现有内容、规则和工具怎样配合，供阅读和维护时查阅；它是导读，不新增执行要求。详细判断仍以链接到的专项规范为准。现状核对日期：2026-10-05。

项目总览见 [README](../README.md)，日常导航见 [Home](../Home.md)，常用提问方式见 [学习协作说明](学习协作说明.md)，规则与工具入口见 [System](System.md)。

## 内容如何组织

知识库以 Markdown 文件保存内容，用 Obsidian 阅读和建立链接，用 Git 管理版本，助手参与解释、核验与整理。仓库根目录也是 Obsidian Vault。

目录按用途区分内容：Inbox 临时捕获；Knowledge 保存可复用知识；Sources 保存来源；Ideas 保存创意；Projects 推进明确成果；Local 容纳本机材料；Archive 保存退出当前工作的内容；System 提供运行所需的规则、模板和工具。完整路径与归档边界集中在 [目录结构说明](目录结构说明.md)，本文不维护第二份目录清单。

`10_Knowledge/Notes/` 保存正文，`10_Knowledge/Maps/` 保存 MOC（内容地图）。目录便于定位文件，地图通过问题、关系和阅读顺序组织知识；双向链接表达跨主题关系，Properties 记录类型、领域和状态。标签主要用于待整理、待验证等工作状态。

五大学科通过 `domains` 属性和领域 MOC 表达，正文目录按稳定主题群组织。例如 `Notes/Thinking/` 存放思考与表达方法，从 [[Engines：应用科学]] 进入；独立笔记暂留 `Notes/` 根目录时也有属性与 MOC 入口，并非未分类。正文只选择一个主要存放位置，可以被多张地图引用。AI 是跨学科主题域，其六条正文主线和入口见 [README 的 AI 说明](../README.md#ai-跨学科主题域)及 [AI 地图](../10_Knowledge/Maps/Topics/AI/AI.md)。

默认知识图谱按约定只显示 Knowledge 与 Ideas。其他内容仍然可链接、阅读和引用，图谱范围不等于文件的重要性或访问权限。

概念按独立问题划分，案例保留完整推理，来源页记录出处和过程，地图组织阅读。通用解释集中维护，必要的摘要与具体演算可以复述；不按课程节数、文件行数或笔记数量机械拆分。

案例即使不打开课件，也应能理解任务、输入、步骤、中间结果和结论。长期自查题可以放在 MOC；是否作答、答得怎样和日期放在对应学习记录。具体标准见 [知识笔记组织规则](知识笔记组织规则.md)与 [MOC 创建与维护规则](MOC创建与维护规则.md)。

篇内涉及多个子问题或多步推理时，按[金字塔原理的项目执行约定](知识笔记组织规则.md#复杂笔记按金字塔原理组织)先呈现核心认识，再分组展开理由、过程与证据。案例保留完整演算，关键条件与不确定性随结论说明；这套表达方法通过现有组织规则进入写作与 Review，不改变目录和知识关系。

方法直接参考 [[金字塔原理：结构化思考与表达]]。组织判断不确定时，按[查阅顺序](知识笔记组织规则.md#方法依据与不确定时的查阅顺序)读取总览、对应专项方法，必要时经来源记录回查原书。方法解释集中在知识笔记，执行与验收集中在组织规则，其他规范和模板引用这些入口。

常用 YAML 属性包括 `type`（文档类型）、`status`（该类文档状态）、`topics`／`domains`（主题与学科）、`ai_area`（AI 主线）、`created`／`updated`（日期）、`source`（来源入口）及 `as_of`（信息对应的有效时间）。具体字段以适用模板为准，内部链接写入 YAML 时加引号。

### 三种状态分别判断

| 维度 | 判断对象 | 不能据此推导什么 |
| --- | --- | --- |
| 笔记成熟度 | 内容整理与维护程度；知识页沿用 `seed`、`developing`、`evergreen` | 不能推出所有事实已核实或用户已经掌握 |
| 事实核验状态 | 具体主张有哪些依据，哪些条件或效果未验证 | 有来源链接不代表来源支持全部主张 |
| 个人掌握程度 | 实际复述、辨析、应用或实践表现 | 助手讲解、生成完整笔记或用户表示“懂了”不足以证明掌握 |

例如，Query 改写笔记可以已经整理并通过本次内容评审，真实模型效果仍未实测，个人独立应用也仍待验证。这些状态可以同时成立。

## 日常学习怎样推进

以下是现行学习 Skill 的流程导读；具体保存要求见 [knowledge-study](../.agents/skills/knowledge-study/SKILL.md)。

1. **定位任务与已有内容。** 判断本次是在学习、评审、维护还是讨论结构；学习时查找有关来源、MOC 和笔记，优先复用同一概念的主文。
2. **先解释并核对理解。** 对用户的表达指出正确部分、遗漏条件与错误，必要时用例子、反例或短推演说明。普通提问不强制变成测验。
3. **核验关键主张。** 先读取指定材料；有不确定、时效性或专业问题时查对应依据。区分原文、用户转述、助手补充和待验证推测。
4. **在有效结论形成后保存。** 通用认识写入知识页，完整应用写入案例，材料范围和个人表现写入来源记录，导航按需补入已有 MOC。没有新结论不强行写入。
5. **检查本次改动。** 核对相关链接、锚点、属性、来源和格式；检查概念可查、案例可读、解释可维护、历史证据可追溯，不将本次检查扩展为无关全库整理。
6. **交代实际产物与限制。** 告知保存文件及尚未核实的内容；写入失败明确说明。暂停或结束学习时，维护来源记录中的接续。

来源未知或纯对话学习沿用 Inbox 的可辨识主题记录，注明来源情况；不虚构课程、视频时间戳或原文观点。

### 来源与实践证据怎样区分

读到代码，可以追踪其静态调用；用预设响应模拟，可以判断对应输入下的分支行为。没有真实模型或检索实验，就不能宣称已验证模型质量或召回收益。课件截图中的输出也不能当成本机实测。

实际查阅位置、版本、适用条件和未验证范围应随结论保留。原材料自身的错误如果已经被笔记准确指出，是有价值的学习记录，不能再次当作笔记待修问题。

### 暂停与跨会话接续

来源笔记的“学习接续”保留最近学习日期、已知章节、已讨论问题与入口、实际理解证据、待验证事项及下次起点。历史记录可以保留，但当前状态应能明确定位。

再次说“继续上次的 RAG 课程”时，助手按主题找到相应接续，读取关联知识再继续；多个实质候选时才询问。不把最近修改的文件直接认作当前课程，也不假装新会话拥有完整旧聊天历史。

## 小节 Review 怎样工作

用户明确要求“review 这小节学习笔记”等同义任务时，执行 [Review 规范](学习小节Review规范.md)。普通提问、结束学习或复习测验不会自动触发整套评审。

### 检查顺序

1. 锁定用户指定的主题、页码与学习问题，确定主审概念、案例、来源记录和直接导航。
2. 通过出链、入链与概念搜索发现关联旧笔记，核对重合结论、关键前提和旧应用；相关旧页未修改也不能直接跳过。
3. 建立学习问题覆盖矩阵，分别记录内容是否完整、事实核验到什么程度。
4. 执行八项检查，并保留实际阅读范围和证据。
5. 对候选发现检查上下文、限定条件、问题归属与影响，控制误报。
6. 按模板交付；获授权修订后，沿用问题编号落实并复核受影响项。

关联审查只扩展到必要主张与前提，不无限递归；新旧表述有差异时，先辨别场景、时间与版本，不默认新的更正确。

### 八项检查

| 编号 | 主要检查什么 |
| --- | --- |
| D1 覆盖完整性 | 必要学习问题、前提、边界是否具备 |
| D2 事实与边界 | 定义、数字、职责、因果与成立条件是否准确 |
| D3 来源与证据 | 来源是否支持主张，转述、模拟和实测是否分清 |
| D4 术语与一致性 | 同文及关联旧笔记是否存在未解释的冲突 |
| D5 案例与推理 | 输入、步骤、中间结果和输出是否成立 |
| D6 组织与可读性 | 概念、案例、来源与地图分工是否合理 |
| D7 导航与文件质量 | 链接、锚点、YAML、路径和格式是否有效 |
| D8 学习状态与接续 | 成熟度、核验和掌握是否混淆，当前进度是否准确 |

该表用于认识检查范围，具体必查项、裁定与证据标准以规范为准。

### 报告与问题跟进

报告正文固定为三部分：

1. **审核了哪些文件**：文件名、内容摘要、是否需要调整。
2. **待调整内容**：以文档链接为标题，逐项说明问题、依据、解决方案。
3. **问题解决进度**：记录实际处理、验证结果与剩余工作。

材料范围、覆盖矩阵、关联复核、八项检查和待验证事项保留在附录。每个问题使用稳定的 F 编号；P1 为优先修正的核心错误，P2 为影响理解或使用的局部问题，P3 为可选优化。级别与“待修改／已解决”等处理状态分别记录。

Review 默认只读；用户说“解决 F05”后才执行相应修订。此前已修、本轮复核与本轮实际修改必须区分。报告默认在对话交付，较长时可提供临时 Markdown；用户要求保存报告后再写入正式知识库。

## 请求与操作边界

| 请求 | 现行行为 |
| --- | --- |
| “帮我理解这个概念” | 解释、核对，形成有效内容后按学习约定增量保存 |
| “只讨论，先别记”／“等我说整理再写” | 按要求暂停文件写入 |
| “review 这小节笔记” | 检查并交报告，被审文件保持只读 |
| “按 F01、F02 修改” | 落实对应修订及必要关联检查 |
| “保存 review 报告” | 按规范保存报告，不因此修改知识正文 |
| “继续上次的某课程” | 读取对应来源接续并恢复上下文 |
| “介绍项目结构”／“分析现有规则” | 按结构说明或诊断任务处理，不自动产生学习记录 |

本次明确指令优先于一般学习默认值，已获得的相应授权不重复确认。文件实际保存不等于 Git 提交：默认把改动留在工作区，除非用户要求，不提交、推送、切换分支或清理文件。

写入前保护已有未提交内容。新增或调整目录职责时，同步目录说明与受影响入口；只修改文件而不改变目录职责时，无需重写目录清单。文件迁移或删除必须保留必要来源和引用关系，不借日常学习任务批量重构其他主题。

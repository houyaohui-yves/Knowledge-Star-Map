# MOC 创建与维护规则

MOC（内容地图）负责回答“从哪里进入、先看什么、这些知识有什么关系”，不是目录清单，也不是学习流水账。本文主要规范 `10_Knowledge/Maps/Topics/` 的增长；五大学科仍保留为 `Maps/Domains/` 中的稳定导航视角。

核心约定：**浅目录存放文件，MOC 表达知识结构；先长章节，再按实际导航需要长地图。** 目录职责见 [目录结构说明](目录结构说明.md)，创建时参考 [MOC 模板](Templates/MOC模板.md)。

本文规范地图；概念是否应从案例或上位文章独立、怎样保留案例的完整推理，按 [知识笔记组织规则](知识笔记组织规则.md) 判断。提取独立笔记后，在相关现有 MOC 补直接入口，无须为每个概念另建地图。

## 先判断需要什么

| 当前需要 | 默认做法 |
| --- | --- |
| 解释一个概念、原理或方法 | 补充或新建知识笔记，不自动配一张 MOC。 |
| 把几篇相关笔记放在一起 | 在已有 MOC 中增加一个有意义的章节，并说明关系。 |
| 为一个问题提供独立、可反复使用的阅读或选择路径 | 满足下文条件后，将章节提炼为专题 MOC。 |
| 记录某次课程、学习进度、作答与掌握证据 | 写入来源笔记；来源未知时暂存 Inbox，不因结课另建地图。 |
| 一组 MOC 已形成稳定的大主题群，文件定位确有困难 | 评估浅层文件夹分组；不随每个新概念创建子目录。 |

这些不是必须依次完成的晋级流程。已有明确导航需求和材料时可以直接建 MOC；笔记数量多、学习结束或名称听起来像“大主题”，都不是独立的创建理由。

## 何时新建专题 MOC

先检索已有地图和章节。新建前应能回答三个问题：

1. **独立性**：这张地图帮助读者解决什么导航问题？现有地图的一个章节为何已不便承担它？
2. **组织价值**：它提供了什么阅读顺序、概念关系、方案比较或按问题查找的路径，而不只是重复罗列链接？
3. **持续价值**：离开这次课程或会话后，它是否仍值得反复进入，并可继续吸收其他来源的知识？

没有明确答案时，先保留在已有章节中。已有材料应足以支撑实际导航，不为预想中的知识体系批量建空地图。不设置“满几篇笔记就必须建图”的硬门槛。

## 一张地图最少需要什么

- **问题与范围**：用简短文字说明它组织什么；容易与其他地图重叠时，说明分工。
- **知识脉络**：按问题、过程、对比或阅读顺序组织真实链接，必要时用一句话解释关系。定义和方法正文留在知识笔记，不复制一套。
- **可发现的入口**：从至少一张相关的现有 MOC 提供入口；全新主题没有合适 MOC 时，可从 Home 建立主题入口。地图内给出返回或横向关联，避免成为孤立文件。

按内容使用模板，删除无用空章节，不新增强制的父主题、层级编号或维护人字段。标题优先使用稳定主题或问题，不以课程节次、日期区分同一主题的多张地图。

同一笔记或地图可以被多个入口引用；正文只维护一份，不要求唯一父主题，也不复制成多份来适配分类。

## 地图与学习记录如何分工

长期可复用的问题、关系、阅读路线和自查题可以留在 MOC。课程出处、学习日期、进度、实际作答和个人掌握证据保留在来源笔记或暂存的 Inbox 学习记录；MOC 可以链接它们作为出处，但不重复维护进度。

按内容用途判断，不按文件是否叫“学习地图”机械搬迁。再次学习同一主题时，优先补充既有地图；只有出现独立的长期导航需求，才考虑另一张地图。

## 如何保持浅而清晰

- **目录按稳定主题群分组**：已有 AI 主题群集中在 `Topics/AI/`，规模较小的法律主题可以继续保留为 `Topics/法律.md`，不为形式对称创建空文件夹。
- **脉络主要写在地图中**：专题之间的上下文关系不必逐层对应文件夹。只有既有地图形成可解释的稳定分组、且确实改善文件定位时，才评估下一层目录；不预建整套分类树。
- **避免把深目录换成深链接链**：入口应能按问题直达关键笔记或专题，不要求逐级下钻。经常来回寻找或反复点击只是层层转发的页面时，补直接入口或合并空壳导航，不机械规定统一跳数。
- **总入口不做全量清单**：Home 与大主题入口突出主要路径，细节交给相关地图；高频内容可直达，不必每新增笔记就更新所有上层 MOC。

## 何时维护，怎样调整

在当前主题增加内容、阶段收尾或实际找不到内容时，检查相关地图即可；不要求每次学习都巡视全库，也不设固定清理周期。

| 发现的问题 | 优先处理方式 |
| --- | --- |
| 地图变长，难以扫描 | 先按问题整理章节、突出主要入口；只有某组内容形成独立导航任务时才拆图。 |
| 地图只有很少内容，几乎只是转发 | 判断是否仍有必要的入口或独立导航价值；没有时，考虑折回相关地图的章节，不因笔记少就机械合并。 |
| 多张地图范围高度重叠 | 先明确分工；没有独立价值的重复地图再考虑合并，保留独有内容与关系。 |
| 同一知识在多个 MOC 中重复展开 | 将正文集中到对应知识笔记，各地图保留符合自身语境的简短导读和链接。 |
| 旧地图暂时不再常用 | 可降低入口显著程度；仍有知识价值时继续保留，不因近期没访问就删除或归档。 |
| 学习日期、完成状态混入长期地图 | 将进度与证据归回对应学习记录，地图保留长期导航；来源链接不必删除。 |

日常学习可增补相关章节、链接和导读。涉及目录调整、批量整理，或合并后需要移动、删除旧文件时，先说明范围与引用影响，取得对应授权后再执行；提出维护建议不等于已经完成迁移。

执行合并或迁移时保留原有独特内容、来源和学习证据，并同步检查文件链接、标题锚点与入口。旧文件的删除或归档不能作为无关学习任务的顺手清理。

## 放到现有 AI 主题中如何判断

- 新学一个检索方法：先补相关笔记，并在既有 [提示词与 RAG 地图](../10_Knowledge/Maps/Topics/AI/提示词与RAG：学习地图.md) 中组织；不因学完一节视频另建地图。
- 后续增加混合检索、排序和评测内容：先检查既有地图能否用章节容纳；其中某部分真的需要独立阅读或选型路线时，才评估提炼专题 MOC。
- Agent 的相关笔记增加：先维护 [AI 工程系统](../10_Knowledge/Maps/Topics/AI/AI工程系统.md) 的 Agent 章节；是否独立建图看导航价值，不看数量是否达到某个阈值。

这些示例用于帮助判断，不要求对现有地图进行一次性批量改造。

## 完成一次维护前的检查

- 新建地图有独立用途；未新建时，相关内容也能从已有入口找到。
- 组织方式体现关系或使用路径，没有重复正文、空壳节点或为凑结构创建的文件夹。
- 相关文件链接与标题锚点有效，必要入口已同步，没有强制唯一归属。
- 长期导航与本次学习进度分工清楚；来源、个人掌握证据未丢失。
- 若涉及目录职责变化，同步更新目录说明；如实说明修改范围与尚未执行的建议。

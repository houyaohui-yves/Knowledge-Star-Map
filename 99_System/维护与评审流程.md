# 维护与评审流程

更新：2026-10-20。统一维护与评审的范围、证据、修订及复查要求；完整小节 Review 保留原 1.3 的 D1–D8、关联复核、覆盖矩阵和三部分报告。此次依据用户的整体重构授权整合；日常评审不自行改变这些标准。

本文件是执行规范。[知识维护工具](Scripts/knowledge_maintenance/README.md)已支持通用任务范围、持久事项、跨来源证据、获授权的既有内容修订、修后复查及中断恢复。AI 在当前会话选择范围、阅读证据并判断；工具检查版本与执行状态，不独立判断事实，也未接入后台触发。输入格式与恢复操作集中在工具说明。

## 选择范围与模式

| 请求 | 执行方式 |
| --- | --- |
| 查某个问题、一般诊断或维护检查 | 明确本次问题和文件范围，按下方共用流程执行，交代实际检查深度，不冒充完整小节 Review |
| review 小节、检查这一节完整性／错误／歧义 | 完整读取本文件，执行“完整小节 Review”全部流程及报告模板 |
| 按 F 编号修改、review 并修正 | 在既有授权范围完成诊断、修订及复查；对应授权不重复询问 |
| 保存评审报告 | 简短报告可追加对应来源，长报告放同一来源目录并从来源回链；用户指定路径优先，保留发现、依据及状态，不因此修改正文 |
| 制定、更新系统规范 | 只按请求调整规范与必要入口，不因此修改知识内容或学习状态 |

只读要求沿用 [AGENTS](../AGENTS.md)，报告在对话中交付，可提供临时 Markdown 完整预览。临时解析、计算与隔离模拟可用，但不写正式知识或持久队列；不默认调用付费模型、租机、修改原 demo 或执行未知脚本。材料或工具受限时完成其余检查并明示限制。普通学习结束、总结、测验和 Git 代码 review 不自动触发完整小节 Review。

## 共同证据标准

- 区分来源原意、用户理解、助手补充、推测和实测。实际材料与主张逐项对应，记录标题／URL／文件、读取范围、页码或位置、版本及适用条件。对话回链只证明讨论出处；有引用、引文匹配或哈希一致不证明语义正确。
- 仅凭视频标题或链接不算观看；只依据可访问片段、字幕、截图或标明的用户转述。补充资料不能冒充原课程；未读到的观点、页码、时间戳不补造。
- 先核指定材料，对不确定技术事实、专业及高风险事实、时效性信息查可靠依据，技术资料优先官方文档和原始论文。区分信息有效时间与访问日期，实际查阅什么就记录什么，不用搜索摘要背书全文。
- 静态代码追踪、预设响应模拟、课件截图与真实实验分别记录；模拟只证明该输入下的程序行为，不能证明模型质量或检索收益。PDF 图表或布局影响判断时核对原页；数字与公式用可复算过程验证。
- 缺来源、材料不可读、版本不明或未实测，列具体待验证主张和所缺证据，不直接判错误或计为通过。原材料有问题而笔记准确记录时，不重复算作笔记错误。
- 内容整理成熟度、事实核验与个人掌握分别判断；掌握必须来自真实表现，具体记录按[学习流程](学习与复习流程.md)。

## 从发现到复查的共同流程

1. 界定目标、深度和授权，检查当前工作区；按相关知识主张选择正文、来源、导航和必要依赖，记录扩展理由，避免无限递归。
2. 先运行合适的结构检查，再阅读上下文与证据。诊断分为无需动作、建议修订、待验证、待用户判断；执行失败／中断／输入过期另列，不能当作无需动作。
3. 发现记录稳定 ID、触发原因、文件与主张位置、实际依据、影响、建议动作、下一步及验收。相同根因复用 ID，新旧措辞先核时间、场景和条件，不默认较新内容正确。轻量任务可自然语言记录；完整 Review 用下方 F 编号格式。
4. 按授权落实可执行部分。写前比对取证版本与当前内容，发生变化先重新核对；保留用户未提交修改、历史来源与学习证据。使用维护工具时，活动操作的必要前后版本随持久账本保存，核对差异后写入，缓存删除不影响恢复；其他编辑按需保存任务前副本并记录范围。不自动回滚整个仓库。
5. 重查原问题、受影响主张、相关旧笔记、链接／锚点与必要计算或模拟；迁移同步入口。修改成功不等于问题解决，未验收标已修改待验证；多文件失败须列真实完成范围和剩余工作后继续可执行部分。
6. 交付本轮实际改动、验证和未结事项。只读在对话中交付；报告按保存报告授权归入来源，需要后续行动的事项在已有维护／保存事项授权内写入 `99_System/State/maintenance.json`。不复制所有正文中的“待验证”，不把保存报告自动扩大为修订授权。无变化不重复建报告或待办；仅相关新证据重开旧项。

内容更新由新证据、适用版本变化或实际使用缺口触发。时间久、访问少不等于失效；被替代内容按其历史价值保留条件与替代入口，归档和删除依本次授权并检查入链。资料缺失与价值取舍分别处理，不以“AI 建议”替代证据或用户判断。

完整 Review 修订沿用原 F 编号，更新下方关联复核表；不修改关联旧笔记的无关内容。新改动没有扩大影响时不重复全库检查。状态、计数及报告格式以完整 Review 的定义为准，账本 stable ID 与报告 F 编号建立对应；`awaiting_verification` 对应已修改待验证，只有验收后 `resolved` 才表示已解决。报告从当次状态生成，不能并行维护矛盾结论。

## 完整小节 Review

目标是检查已学习小节是否覆盖真实问题、表达准确、依据可追溯、案例可读，并交付可落实建议。不同模型与推理强度遵循相同检查；能力不足须缩小结论而非省略检查后称完成。组织与导航标准集中在[知识组织规范](知识组织规范.md)。

### 固定执行顺序

按以下顺序执行。每步留下表格、证据记录或结果摘要；它们是可检查的工作产物，不要求展示内部推理。较长任务可分批读文件，但在报告中保留已读与未读范围。

#### 步骤 A：锁定小节与文件

1. 读取当前请求与项目规则，检查工作区状态，避免把既有未提交内容误认为本轮新增或应回滚的内容。
2. 按以下优先级确定小节：用户明确的主题／页码／文件 → 当前对话明确结束的小节 → 对应来源笔记的学习接续。文件修改时间只能辅助查找。
3. 范围存在多个实质候选时，简短确认；等待期间可整理文件清单。不能把整章自动当成刚结束的小节，也不能静默缩减用户指定的整章范围。
4. 找到来源笔记、概念笔记、案例笔记及直接导航 MOC，再按下文 A1 发现和筛选关联旧笔记。范围由学习问题和受影响的知识关系决定，不能只取本轮新增／修改的文件，也不递归巡视全库。
5. 报告中列出小节主题、原材料页码／章节、文件及角色、检查到的具体范围、明确排除内容。没有原材料时也可审内部一致性，但标明无法完成来源对照。

**必交产物：范围清单。** 主审概念与案例正文必须通读；对跨章节共享笔记，通读本节相关内容并检查相邻限定条件，标明其余部分只作背景。不能只检索关键词就声称通读。

#### 步骤 A1：发现并界定关联旧笔记（必做）

先从本节提取关键概念、别名与重要主张，包括会影响判断的条件。例如 Query 改写不仅搜索标题，也关注指代消解、多意图、假设文档、意图保留及生成内容的证据角色。

按三条途径发现候选，记录实际搜索范围与词组：

1. **出链**：本节主审笔记直接引用的概念、前提和旧案例。
2. **入链**：引用主审笔记的已有笔记，包括指向标题锚点和使用别名显示的引用。
3. **概念搜索**：在相关主题笔记、地图和来源中搜索名称、别名、同义表达及关键主张，补查没有建立链接的重合内容。若已有证据表明内容在其他目录，定向扩展搜索并记录理由；不默认全文评审整个 Vault。

有链接、关键词命中或同属一个学科，只表示候选。依据内容关系决定纳入：

| 关系 | 必须核对的内容 | 阅读深度 |
| --- | --- | --- |
| 解释同一概念或维护重合结论 | 定义、成立条件、方法职责、重要边界与依据是否一致 | 相关章节连同限定条件；重合贯穿全文时通读全文 |
| 提供当前结论的关键前提 | 前提是否成立，当前笔记是否正确使用其条件 | 前提所在章节及必要推导／来源 |
| 应用本节方法的旧案例或流程 | 输入、步骤、输出是否与方法相容，旧示例是否仍成立 | 相关推理链，包括决定含义的上游输入与下游使用 |
| 仅提供导航、历史出处或一般背景 | 入口、归属和历史限定是否准确 | 对应条目及邻近说明，不自动升级为整篇内容评审 |

主审范围执行完整 D1–D8；关联旧笔记围绕纳入的主张执行适用检查，重点为事实／来源、一致性、案例应用和组织关系。不把旧笔记其他章节的完整性当成本节必修，也不能以“不是本次修改的文件”为由跳过相关内容。

建立候选清单，逐项注明纳入理由与计划阅读范围；有实质关联但排除的候选须说明理由。完成检查后更新为下方的关联复核表。不要求逐项罗列纯关键词噪声，可按类别归纳排除理由。没有找到关联笔记，也须报告查找范围、方法和结果，不能直接省略本步骤。

**停止与扩展条件：**直接相关主张已经核对，且没有未解决的关键前提或冲突时结束扩展。若发现新前提或冲突，只沿该问题追查必要笔记和依据，并记录扩展理由；不按链接无限递归。仅偶然发现的无关问题另列范围外线索，不计入本节缺失或擅自修订。

新旧表述不同不自动构成错误；先核对适用场景、时间、版本、教学假设和历史纠正。新笔记不因写得晚就优先正确，旧笔记也不因被多处引用就正确。冲突按原始依据裁定；证据不足时列待验证，不强行统一措辞。必要摘要与完整应用可复述，不为去重破坏案例自足性。

**必交产物：关联复核表。** 表格在步骤 C 核验后完成：

| 关联笔记 | 发现途径与纳入理由 | 对照的主张／主审位置 | 实际阅读范围 | 结论与证据／发现编号 |
| --- | --- | --- | --- | --- |
| 文件链接 | 出链／入链／概念搜索；具体知识关系 | 可定位的结论 | 标题或行号；全文或局部 | 一致／差异有合理条件／发现问题／待验证；说明依据 |

链接检查通过不能替代内容核对。搜索摘要不能冒充已读正文。已有核验可在确认对应内容、原材料版本及适用条件未变后复用，须说明沿用了哪些证据；发生变化的相关部分重新检查。

#### 步骤 B：先建立覆盖矩阵

从用户明确的学习问题、指定课件／材料与实际讨论范围提取应覆盖的问题。每行对应一个能单独判断的学习问题，避免按句子拆成大量检查项。

| 学习问题／必要知识点 | 纳入依据 | 应有内容 | 实际笔记位置 | 内容覆盖 | 事实核验 |
| --- | --- | --- | --- | --- | --- |
| 用真实内容填写 | 用户问题／材料具体位置／必要前提 | 定义、解释、条件、例子等 | 文件＋标题或行号 | 完整／部分／缺失 | 已核／部分已核／待验证 |

判断规则：

- **完整**：读者能够从笔记回答该问题，且有影响理解的必要条件；出现关键词不算完整。
- **部分**：有结论但缺关键解释、条件、例子或推理步骤；具体写出缺什么。
- **缺失**：本节应覆盖，但在主审笔记和合理关联入口中均未找到。
- 延伸知识只有影响本节结论成立或用户明确要求时才升级为必需；其他内容列为可选延伸，不因“还可以讲更多”判定笔记不完整。
- 内容覆盖与事实核验分开：写得完整的内容也可能未经核实；原始资料忠实转述也可能在事实层面错误。

**必交产物：覆盖矩阵。** 后续每个“遗漏”问题必须能指回矩阵中的纳入依据。

#### 步骤 C：逐项核验事实、逻辑与案例

对下面 D1–D8 都给出结果：`通过`、`发现问题`、`待验证`、`不适用`。每项附依据或原因，不用一个总分代替检查结果。

| 编号与维度 | 必须做的检查 | 判断依据与常见误判 |
| --- | --- | --- |
| D1 覆盖完整性 | 检查矩阵中的学习问题、必要前提、适用条件与主要误区 | 对照用户问题及材料范围；不强制把整门学科写全 |
| D2 事实与边界 | 核对定义、机制、数字、单位、公式、角色职责、因果、否定、量词和成立条件 | 找原文、官方资料或计算证据；把“可能／特定条件有效”写成“一定／普遍有效”应指出 |
| D3 来源与证据 | 对齐主张与实际来源，区分来源原意、用户理解、助手补充、推测及实测 | 引用存在不代表支持结论；截图结果、静态代码、模拟和真实运行不能混写；检查版本、有效时间与阅读范围 |
| D4 术语与一致性 | 检查同文及 A1 纳入的关联旧笔记中名称、条件、示例、结论是否一致，有无未解释的术语；完成关联复核表 | 逐字比较关键条件；保留场景、版本及历史限定，不把后文已明确纠正的转述当作作者观点，不默认新笔记更正确 |
| D5 案例与推理 | 从输入沿步骤追到中间结果、输出和解释；核对代码实际调用、公式代入、图表箭头、缺省与异常分支 | 案例要能独立读懂；精确复现实验可能另需数据。已标明的教学结果和未实测方案不应被误判为伪造实测 |
| D6 文章组织与可读性 | 检查概念／案例／MOC／来源的分工、颗粒度、重复维护、必要上下文、阅读顺序及歧义 | 按组织规则判断；必要摘要可重复。篇幅长、标题多、个人文风偏好本身不构成问题 |
| D7 导航与文件质量 | 检查新增或相关的内部链接、标题锚点、来源路径、MOC 入口、YAML 与必要属性、未替换占位符、代码块和公式格式 | 链接要实际可达；区分代码示例中的字面链接、重名文件、别名与真正断链。仅用正则检查时不能宣称完整解析器验证通过 |
| D8 学习状态与接续 | 分开判断笔记成熟度、事实核验程度与个人掌握程度；检查当前接续是否明确、遗留问题是否仍有效 | 没有用户复述或实践证据时不能标已掌握；历史阶段可保留，但应能定位唯一的当前状态 |

执行细节：

1. 主审范围中会改变读者理解或操作的关键定义、数字、代码行为和效果主张必须核验；不能只挑容易验证的几项。其他背景可抽查，报告具体范围。
2. 先核本地指定材料；对材料本身的技术错误、时效性事实或专业不确定项，再查实际支持该主张的官方文档／原始论文等可靠依据。技术资料优先一手来源。记录实际查阅位置，不能只引用搜索摘要或声称“已查证”。
3. PDF 的图表、截图和布局影响判断时查看相关页面渲染；代码先静态追踪，有必要且可隔离时再做最小模拟；数字用可复算的算式或工具核对。模拟只证明该输入下的程序行为。
4. 来源不可访问、版本不明或实测条件不足时，写清具体主张、缺少证据及下一步核验方式。不能据此直接判内容错误，也不能视为已验证。
5. 先定位问题归属：**原材料／demo 有缺陷且笔记已准确说明**，通常是已正确记录的知识，不应再次列成“笔记待修”。只有转述失真、未提示关键风险、误称已修复等才成为笔记问题。
6. 记录问题时使用实际文件与标题／行号，节选足够判断的短片段，并说明依据。处理历史材料时，不用今天的日期代替示例发生日期。

**必交产物：D1–D8 检查结果、关联复核表，以及关键发现对应的证据。** 跨笔记冲突须同时定位两侧表述并记录裁定依据。可以合并同一根因，不按句子重复报错。

#### 步骤 D：复核发现，控制误报

对每条候选发现，完成下面四问；不满足的调整为待验证或可选建议，必要时撤销：

1. 这是笔记本身的问题，还是被笔记准确描述的课件／代码问题？
2. 通读上下文后，是否已有“假设、示例、未实测、特定条件”等限定解决了疑点？
3. 有什么具体证据？它能证明错误、歧义、缺失，还是只说明个人偏好？
4. 会怎样误导读者？建议的最小修改能消除什么影响？

同时检查范围偏移：不能把本节未要求的知识列为必修，不以代码风格或产品上线标准苛求概念示例，不因想简短就删除案例必要推理，也不为了有结果而凑问题数量。

#### 步骤 E：按固定格式交付

使用 [学习小节 Review 报告模板](Templates/学习小节Review报告模板.md)。执行仍按 A–D 开展，报告开头简述日期、小节范围、模式、执行完成情况、笔记结论及关键证据限制；正文固定为以下三部分，不另外堆叠结论仪表盘、历史发现或阅读路线章节：

1. **审核了哪些文件**：表头固定为“文件名、文件内容摘要、是否需要调整”。每份被审文件一行，文件名直接链接文档。摘要用一句话说明文章讲什么或承担什么作用；局部审核须注明章节。调整状态按交付时的剩余工作填“是（F 编号）／可选（P3 与 F 编号）／否／待核实”；本轮修完标“否（本轮已修，见进度）”，不能让用户误以为从未发现问题。结论只覆盖实际核对范围，角色、具体检查点与证据复用放附录。
2. **待调整内容**：直接以有问题的文档链接为标题，在其下逐条列出问题及解决方案。每条用 F 编号和优先级标识，说明具体位置／必要原句、问题及影响、判断依据、可落实的方案与验收方法。文件按最高问题优先级排序，组内 P1→P2→P3。跨文件同一根因沿用同一编号，各文件下说明各自需要调整什么，证据只完整展开一次。本轮已修的问题仍在原文件下保留问题与方案并注明已落实，历史已解决问题只在进度表简列。没有待调整或本轮已修的问题时写“无”。
3. **问题解决进度**：按“问题／文件、状态、本轮实际处理、验证结果／剩余工作”列出。建议未执行、部分解决、已修改待验证、已解决、撤回要区分；P3 未实施明确为可选。复审沿用 F 编号，历史已解决项注明此前修订与本轮复核；未执行的验证不能写通过。只读时明确未改被审文件；如有规范、模板或报告等其他产物，在本节单列，不与知识笔记修改混算。

完整的材料与阅读范围、证据复用、覆盖矩阵、关联发现与复核表、D1–D8、待验证事项及所需证据放在**附录**。正文内容摘要不能替代审核范围记录。已确认有效的结论可留在对应检查依据中，不另加泛泛表扬章节。可附 1–3 道易混点复习题，未作答不算掌握。

**状态与计数口径：**“检查结论”“建议调整”“本轮实际修改”分别记录。发现已解决不等于本轮改过；进度状态使用“待修改”“部分解决”“已修改待验证”“已解决”“撤回”，P3 可写“可选，未实施”。在实际处理与验证列明确本轮修改还是此前修订、本轮复核，不只写含义不明的“已处理”。修改须对照本轮开始时的工作区基线；不能把既有未提交修改归为本轮成果。配套的链接等修改也须归入对应文件并说明原因和核对结果，不必人为新增问题编号。

无需强制展示统计数字；如展示，文件数按真实路径去重，主审、关联、辅助不重复计数，合计须等于文件清单行数。仅发现但未读取的候选不计已审；材料、代码及规范／报告产物与被审笔记／地图／记录分开列。已修改文件与仍建议调整文件可能重叠，不能简单相加当作总数。发现数量按 F 编号去重，只统计仍待处理项；历史已解决／撤回另列。部分完成时明确未读文件／章节，不用数量掩盖缺口。

模板中的空项按实际结果填“无”“不适用及原因”，删除仅供说明的占位文字。正文只完整展开一次问题证据，其他表格通过编号引用。报告较长时提供完整临时 Markdown 与简短摘要，先让读者看懂文件与处理点；不得只交摘要、遗漏证据附录或为了缩短报告跳过检查。

### 问题结构与结论规则

#### 每条发现必须有

```text
ID：F01（复审沿用原 ID）
级别：P1／P2／P3
类型：事实错误／歧义／必要遗漏／案例断点／组织维护／导航格式／状态记录
处理状态：待修改／部分解决／已修改待验证／已解决／撤回；P3 可选未实施单独注明
位置：文件＋准确标题或行号
现状与证据：原句或行为，以及支持判断的材料位置／算式／核验结果
影响：读者会误解或执行错什么
最小建议：具体替换、补充、移动或链接到哪里；不要只写“优化一下”
本轮实际处理：未修改，或具体改前 → 改后；部分修订写清剩余项
验收：只读时给方法；已修时给实际复核与结果，未做的明确待核
```

以上是必需的信息，不要求在文档下堆成十个字段：问题、依据、方案放第 2 部分，状态、实际处理及复核结果放第 3 部分，通过 F 编号对应。

没有充分证据的怀疑放入单独的“待验证”表，注明可能影响与核验方式，不与已确认发现混排成确定错误。不输出自报置信度百分比。

| 级别 | 判断标准 | 处理建议 |
| --- | --- | --- |
| P1 优先修正 | 核心定义／机制错误、关键事实或必要前提缺失、示例与核心结论相反，足以形成明显错误理解或操作 | 先修正再作为稳定复习依据 |
| P2 应当调整 | 局部条件、边界、接口、推理或状态存在可说明的歧义／遗漏，会影响理解、使用或接续 | 指定最小修订及验收 |
| P3 可选优化 | 主要结论成立，调整能改善可读性、导航或维护；不改变事实判断 | 与必要修订分开，避免夸大 |

按影响分级，不按出现次数、篇幅或审阅者喜好分级。没有发现时明确说“在本次范围与证据下未发现实质问题”，不保证绝对无误。

最终分别给出两个状态：

- **评审执行**：已完成约定范围／部分完成，并列出未完成项。
- **笔记结论**：需修订（存在 P1 或 P2）／可用、可优化（仅 P3）／未发现实质问题／证据不足以判断核心结论。

存在待验证不自动否定整篇；只影响局部时保持局部待验证。核心证据缺失时，不能用“文字通顺、链接正常”抵消它。默认不打总分；用户要求评分时先说明维度与权重，同时保留证据和限制。

### 交付前完成条件

- 范围已经锁定；主审文件实际读完，未读部分明确列出。
- 已完成出链、入链与概念搜索；关联复核表逐项记录纳入理由、实际阅读范围和证据，没有以链接可达代替正文核对。没有关联候选时有查找记录；实质候选排除有理由。
- 覆盖矩阵来自真实学习问题与材料，不是凭印象列目录。
- D1–D8 各有结果或不适用原因；关键语义、数值及代码行为有依据，未核验项明示。
- 每个已确认发现有定位、证据、影响、具体建议与验收；完成过误报复核。
- 报告前半部分能逐文件回答“查了什么、结论是什么、建议改什么、本轮到底改了什么”；清单、计数、发现状态与实际写入相符，未将历史修订算成本轮成果。
- 没把课程／demo 已知缺陷重复算作笔记缺陷，没把教学例子当真实业务事实。
- 没把“读完／笔记齐全／助手解释过”写成用户已掌握。
- 报告与文件变更符合本次授权；保护既有工作区内容。只读 review 若做隔离检查，应确认被审文件未改变。

未满足时先补做能做的部分；确实受材料或工具限制时，按“部分完成＋具体限制”交付。不得为通过清单而编造证据。

### 用于校准执行的边界示例

以下是行为验收场景，帮助执行者保持同一判断标准；不是每次 review 都要复述的内容。

| 场景 | 应有判断与动作 | 不合格行为 |
| --- | --- | --- |
| 已知用户刚学 Query 改写，要求 review 该小节 | 定位相应页码、概念、案例、来源与直接 MOC；不把整章 RAG 当作必审 | 因整章还有混合检索没学，判本小节缺失 |
| 未改动的旧产品案例也应用 Query 改写 | 纳入对应输入—改写—生成链，检查是否保留本节要求的对象与条件 | 只列 Git 改动文件，漏查旧案例 |
| 旧笔记讲同一概念，但没有链接主审笔记 | 用名称、别名、同义表达及关键主张搜索发现，再读相关上下文 | 把链接邻居当作全部关联范围 |
| 新旧笔记表述不同，分别适用于不同版本或场景 | 记录条件差异；必要时建议补充适用范围 | 默认新文正确，直接覆盖旧文 |
| 候选只提到 RAG，没有共享主张或关键依赖 | 归入背景／排除，并在报告中概述理由 | 无限制追查所有 AI 笔记 |
| 课件打印单引号列表，代码先 `json.loads` 再打印 Python 列表 | 区分原始响应与打印表示，不能仅凭截图判解析错误 | 把单引号展示直接报为模型 JSON 失败 |
| 笔记准确记录多意图分支丢失历史 | 核对代码后肯定记录，必要时建议后续 demo 实践 | 把 demo 缺陷再次算作笔记事实错误 |
| 前文写“500 元以下”，后文用 `price < 500`，未声明两者关系 | 指出边界歧义；明确是否包含 500，统一自然语言与运算符，并测试边界值 | 不检查边界或直接笼统评为“代码写错了” |
| 案例明确“假设输入、未运行” | 检查推理能否成立；真实效果保留待验证 | 将它记为实测，或因未实测而否定所有教学价值 |
| 本地 PDF 缺失 | 完成可读笔记的内部检查，将来源对照标待验证，说明需原材料 | 编造页码证据，或整个任务直接放弃 |
| 用户说“review”，没有要求改文 | 给有定位的建议和报告 | 顺手改正文、状态或学习接续 |
| 上轮修过概念页，本轮只读复审通过 | 进度表写“本轮未改，此前已修”与“本轮复核通过” | 因 Git 仍显示修改，就把旧修订写成本轮调整 |
| 只核对某 MOC 的 Query 入口 | 单列文件与入口范围，结论限定为导航检查 | 把该 MOC 计为全文内容评审通过 |
| 用户说“按 F01、F02 修改” | 只落实对应修订及必要关联检查，复用 ID 验收 | 再问同一授权，或扩大成全库整理 |

这些规则通过明确产物、证据和完成条件减少对隐含判断的依赖；不承诺任意模型都能完美执行。需要验证特定模型或推理强度时，应记录实际执行者、材料、报告、漏报／误报和权限遵守情况，不能将一次作者自查称为已通过多模型测试。

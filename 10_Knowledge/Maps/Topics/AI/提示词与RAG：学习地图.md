# 提示词与 RAG：学习地图

## 核心问题与范围

怎样把用户的问题、外部知识和必要示范组织成有效的模型输入，让回答有据可依，并在失败后知道该改哪里？

这张地图的主线是：**Prompt 组织输入，RAG 按需补充外部证据；Embedding 是常见的检索表示手段；Query 与知识库两侧优化帮助找到证据，反馈与评测检验是否真正改进。**

本页是可持续补充的专题入口，组织模型输入与外部知识的关系、阅读顺序和自查问题；定义与方法细节维护在对应知识笔记。它连接模型、工程和应用三条主线，不按课程或学习日期另建副本。学习进度与个人掌握证据见对应学习记录。

## 用两个阶段串起知识

离线建库回答“准备什么供检索”，在线使用回答“本次取什么给模型”。在向量检索方案中，Embedding 参与表示转换，向量库负责检索，取回的正文和来源才构成回答证据；RAG 并不必须使用向量检索。

理解检索层可进入 [[FAISS文本检索案例：向量、ID与元数据]]：它停在候选展示，尚未生成回答。搜索方式见 [[向量近邻检索：精确搜索与近似搜索]]；正确取回内容的映射与筛选见 [[向量检索中的ID与元数据]]。

```text
离线：原始资料 → 解析清洗 → 切片与元数据 → 检索表示 → 建立索引
在线：问题及必要历史 → Query 处理 → 检索候选 → 取回与筛选 Content
                                                     ↓
                         固定指令 + 证据 + 可选示范 + 当前问题
                                                     ↓
                                            模型回答与依据检查
```

“双向奔赴”发生在两侧：Query 侧补全表达但不能改变意图；知识侧改善组织与索引但不能改写事实。这个说法沿用 [[2026-09-20 提示词与 RAG 学习记录]] 中的用户转述，是工程比喻，不是统一的技术分级。

## 最容易混淆的几类内容

| 内容 | 在系统里做什么 | 是否作为事实证据／示范 |
| --- | --- | --- |
| 用户 Query 与改写 Query | 表达任务、产生检索请求 | 不是外部事实依据；改写结果须保留原意 |
| Content／Chunk | 保存取回的知识及适用条件 | 核对来源、版本与权限后作为回答依据；不是自动算作一个 Shot |
| 合成 Question | 在 question-content 方案中作为检索入口，映射回 Content | 默认不是事实依据，也不是 Few-Shot 示范 |
| Few-Shot 样例 | 示范输入到输出的映射、格式或判断边界 | 承担示范角色；事实不能自动外推到当前对象 |
| HyDE 假设文档 | 生成便于检索的表示 | 可能包含错误，不能代替召回的真实证据 |

关键分工：**找得到、足以回答、最终答对，是三个不同的检查点。** 合成问题命中成功不意味着原文足够，原文足够也不保证模型一定忠实使用。

## 需要带走的边界

- Prompt 是模型语义输入的主要接口，不是整个 AI 系统的唯一控制手段；参考资料数不决定 Shot 数。见 [[提示词工程#重要误区]]。
- RAG 不是搜索模型参数，也不等于读取文件或使用向量数据库；检索注入本身不更新权重，但系统可以结合训练或微调。见 [[RAG（检索增强生成）#来源与核验]]。
- 相似度用于候选检索，不证明事实正确；Embedding 模型与索引必须兼容。见 [[Embedding(嵌入)]]。
- 个人知识沉淀、生产 RAG 准入、是否向量化是不同决策。见 [[什么内容适合进入知识库]]。
- 原始文档、主题知识单元和问答／任务样例是可组合的策略，不是必须依次升级的三层等级。见 [[RAG知识库的构建策略]]。
- Chunk 大小、每段扩写 5～20 个问题都不是通用最优规则；切分不能丢失条件，扩写不能制造事实，效果仍需验证。见 [[RAG中的长文档语义切片]]、[[合成问题索引与Question–Content映射]]。
- 无召回不等于缺知识；要区分原文缺失、解析／切片、查询／过滤／排序和生成问题。见 [[RAG的失败诊断与反馈迭代]]。

查询处理对照：[[Query改写案例：上海迪士尼客服问答]]。逐例分析五类 Query，区分课件结果、代码分支和建议改写；原类的历史丢失与 JSON 回退已离线核验，接入 RAG 是后续方案。

以下问题可用于反复自查；是否答过、回答证据与校准保存在对应学习记录中：

1. Prompt 里有四条参考资料，没有示范输入—输出，是几个 Shot？为什么？
2. Question 匹配成功后，什么内容进入 Prompt？为什么不直接用合成问题当答案依据？
3. 原文中明明有答案，却检索不到，你会先检查哪几层？如果证据已找到但答案错了呢？
4. 用户说“新员工”，能否直接改成“试用期人员”？你如何处理这种相关但不等价的词？
5. 一份公开知识模型早就知道，但你刚刚理解，它值得进入个人知识库吗？是否因此需要向量化？

已有学习接续见 [[2026-09-20 提示词与 RAG 学习记录#学习接续]]；后续学习复用这组自查问题，不在地图中维护个人通过状态。

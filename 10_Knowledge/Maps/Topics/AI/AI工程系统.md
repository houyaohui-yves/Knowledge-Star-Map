# AI工程系统

这条主线回答：如何把模型构建成可靠、可评估、可部署的 AI 系统？

## 知识与上下文

- [[读取文件(检索增强生成 RAG)]] — 在模型外部检索相关知识，组装上下文后再生成答案。
- [[知识库与向量数据库]] — 知识库管理完整知识资产，向量数据库负责保存向量并召回相似候选。
- [[什么内容适合进入知识库]] — 分开判断个人沉淀价值、生产 RAG 的证据准入和向量索引需求。
- [[RAG中的长文档语义切片]] — 通过稳定单元 ID、LLM 语义边界和父子 Chunk 处理会议记录等长文档。
- [[RAG的双向优化与Query改写]] — 凝结对话、消解指代、拆分意图和抽取过滤条件，让用户问题更适合检索。
- [[RAG中的Query与知识切片语义对齐]] — 在 Query 侧生成知识表达，或在文档侧生成典型问题，改善问题与段落的匹配。
- [[RAG知识库的构建策略与反馈迭代]] — 组合原始文档、人工知识单元与任务样例，并从真实问题中诊断和修复系统。

### 少量复习题（尚未作答）

1. Prompt 里有四条参考资料，没有示范输入—输出，是几个 Shot？为什么？
2. Question 匹配成功后，什么内容进入 Prompt？为什么不直接用合成问题当答案依据？
3. 原文中明明有答案，却检索不到，你会先检查哪几层？如果证据已找到但答案错了呢？
4. 用户说“新员工”，能否直接改成“试用期人员”？你如何处理这种相关但不等价的词？
5. 一份公开知识模型早就知道，但你刚刚理解，它值得进入个人知识库吗？是否因此需要向量化？

先尝试用自己的话回答，再按对应笔记核对。实际作答与校准保存在 [[2026-09-20 提示词与 RAG 学习记录#学习接续]]，这里不预设掌握状态。

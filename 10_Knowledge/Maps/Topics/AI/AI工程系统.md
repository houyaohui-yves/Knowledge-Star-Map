## 文本特征与检索表示

统计文本路线是“选特征 → 计数与加权 → 得到向量 → 比较与排序”。按需要直接进入：

| 问题 | 概念入口与关系 |
| --- | --- |
| 统计哪些文本片段？ | [[N-Gram]] 提取连续组合；先分词，再选择特征范围。 |
| 当前文档提了几次？全库有多少篇提到？ | [[TF（词频）]] 与 [[DF（文档频率）]] 分别按文档内频率和包含词项的文档数统计。 |
| 怎样把全库分布变成区分权重？ | [[IDF（逆文档频率）]] 由 DF 和文档总数计算。 |
| 如何组合为一篇文本的向量？ | [[TF-IDF]] 将 TF 与 IDF 组合；[[稀疏向量与稠密向量]] 解释其存储与零值含义。 |
| 怎样按方向比较？ | [[向量的 L2 归一化]] 与 [[余弦相似度]] 解释点积、长度和方向的关系。 |
| 分数高能否证明意思一致？ | [[向量相似不等于语义一致]] 用否定与比较关系检验表示边界。 |

完整应用见 [[酒店内容推荐案例：TF-IDF、N-Gram与余弦相似度]]。另一条表示路线是 [[Embedding(嵌入)]]；表示生成与后续存储索引的分工见 [[知识库与向量数据库]]。

## Agent 与工作流

本组主线：**模型提供智能 → 系统组织受控执行 → 结合真实反馈调整 → 检查结果是否达标**。自主反思与多 Agent 是需要分别判断的设计选择，不作为必经升级。

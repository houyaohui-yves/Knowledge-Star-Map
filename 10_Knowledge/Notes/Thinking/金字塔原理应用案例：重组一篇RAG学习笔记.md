# 金字塔原理应用案例：重组一篇RAG学习笔记

**一篇可独立复习的 RAG 案例笔记，需要把任务与材料、处理过程、回答依据连起来，并标明哪些步骤已经验证。** 金字塔方法帮助我们先表达这条主线，再把细节放回它所支撑的位置。

以下是助手自拟的教学案例。文档内容、问题、检索命中与回答均为预设材料，未运行真实检索或模型，也未修改现有 RAG 课程笔记。案例只展示组织方法，不据此评价 RAG 效果。

## 输入是一份信息齐全但缺少主线的草稿

假设准备记录一个“馆舍开放时间问答”的微型 demo，手头有以下材料卡片：

| 卡片 | 内容 |
| --- | --- |
| A | 文档 S1：北馆周六 09:00 开门，17:00 关门。 |
| B | 文档 S2：南馆周六 10:00 开门，16:00 关门。 |
| C | 用户问：“北馆周六几点开门？” |
| D | 给两条材料分配稳定 ID，保留材料正文与出处字段。 |
| E | 将查询和材料转为可检索的表示，查询候选片段。 |
| F | 为讲解方便，预设检索命中 S1；没有展示向量值、得分和真实排名。 |
| G | 将问题与 S1 组装为生成阶段的上下文。 |
| H | 预设回答：“北馆周六 09:00 开门，依据 S1。” |
| I | 需对照答案与 S1，检查馆舍、星期、开门／关门字段是否一致。 |
| J | 这个例子不能证明面对复杂提问时仍能正确召回与回答。 |

按收集顺序写下这些句子，材料不会消失，但读者仍可能不知道：这个例子要说明什么，哪些是原始输入，哪些是模拟结果，什么工作尚未完成。

## 第一步：确定文章要回答的疑问

复习者的核心疑问是：**这个最小案例如何把一个问题转成有材料依据的回答，哪些环节仍是假设？**

由此可形成简短的 SCQA：已具备两条材料和一个问题（S）；仅看最终答案看不出证据如何进入模型，也容易误把预设输出当作实测（C）；需要说明材料到回答的过程及验证状态（Q）；本例把预设命中的 S1 放入上下文，使“北馆周六 09:00 开门”的预设答案可由材料逐项核对，但向量化、检索与真实模型生成仍未验证（A）。

后文用输入限定、检索与组装、回答核对三个部分展开这个回答。它们是同层的处理部分，不是三个抽象层次；部分名称也不能代替中心回答。

这是利用 [[SCQA：从读者疑问组织序言]] 对齐读者问题。没有把“介绍几个 RAG 名词”当作本文的任务。

## 第二步：先分清角色，再提炼概括

草稿卡片可以按它们在文内推理中的角色重新分配：

| 主要问题 | 对应卡片 | 该组应表达的认识 |
| --- | --- | --- |
| 任务和输入是什么？ | A、B、C、D | 问答依赖带 ID 的具体材料，馆舍与时间字段决定答案范围 |
| 材料怎样进入回答？ | E、F、G | 检索候选与上下文组装把问题连接到材料，本例命中为预设 |
| 回答为什么成立，验证到哪？ | H、I、J | 答案必须与引用材料逐项对应，预设输出不能证明模型质量 |

这是按处理流程形成的分组，顺序来自依赖关系。D 保留原始材料定位，H、I 展示如何使用该定位，必要复述不构成重复维护完整定义。

上层概括不能写成“这个系统已经能可靠回答所有开放时间问题”。现有材料最多支持说明这一次预设输入、预设命中与预设回答之间的对应关系。

## 第三步：写出读者可以独立跟随的正文

下面是一段整理后的示范正文，保留理解所需的输入与中间结果。

**本例用预设命中的 S1，把“北馆周六几点开门”与“09:00 开门”的预设答案联系起来，馆舍、星期、时间字段和引用均能由 S1 核对。** 向量化、检索与模型生成尚未运行，因此这里展示的是材料支持关系，不能证明系统效果。

### 问题限定在北馆周六的开门时间

教学材料包含两条信息：S1 写明北馆周六 09:00–17:00 开放，S2 写明南馆周六 10:00–16:00 开放。问题只问北馆的开门时间，因此需要同时匹配“北馆”“周六”“开门”，不能只找到包含“周六”的片段就直接作答。

### 预设检索命中 S1，并把它放入上下文

材料以 ID 保存正文与出处。实际实现需要把问题和材料转成可检索表示，再选出候选；本例为讲解预设候选为 S1，没有运行向量化和检索。

进入生成阶段的最小上下文可以写为：

```text
问题：北馆周六几点开门？
参考材料 S1：北馆周六 09:00 开门，17:00 关门。
任务：依据材料回答开门时间，并标出材料 ID；材料未说明时不要补造。
```

这段文本说明证据如何与问题一起提供，不表示只要加上该指令就能保证模型遵守。

### 预设答案可由 S1 支持，真实系统效果仍待检验

预设回答为“北馆周六 09:00 开门，依据 S1”。逐项核对可见，馆舍与星期相符，09:00 对应开门字段，引用 ID 也指向给定材料。

如果回答成 17:00，便混淆开门与关门；若引用 S2，则材料对象不符。这里完成的是教学输入与答案的对应检查，真实召回质量、模型是否忠于材料，以及材料缺失时怎样处理，都需另做验证。

## 第四步：检查组织有没有牺牲内容

| 验收问题 | 本例检查结果 |
| --- | --- |
| 示范正文开头是否给出有内容的认识？ | 第三步的小标题前先说明 S1 如何支持北馆周六 09:00 开门，并明确真实系统尚未验证 |
| 各部分是否回答核心疑问？ | 分别说明输入、证据进入上下文的过程、回答与证据的对应 |
| 是否保留关键中间结果？ | 保留预设命中 S1 及上下文文本，没有用外链代替 |
| 有没有把愿望写成直接结果？ | 没把“构建示范流程”概括成“验证系统可靠” |
| 读者是否知道尚未验证什么？ | 明示向量化、检索与真实模型未运行 |

本例展示的是结构整理后的可读性与可核对性，没有证明用户已掌握 RAG 或金字塔方法。真正练习时，可以拿自己的草稿做同样四步，再请另一位读者复述它的主线。

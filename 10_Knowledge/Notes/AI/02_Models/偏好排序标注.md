# 偏好排序标注

> 原文件名为“Rank List标注平台”，2026-10-03 按正文内容更名。“Rank List”尚未核实为某个具体产品的正式名称；以下补充通用的偏好排序标注机制，不推断品牌、供应商或历史项目归属。

## 核心认识

排序／偏好标注，是让标注者依据明确标准比较同一任务的多个候选结果，记录哪个更合适。标注平台负责展示任务、收集判断、管理数据和导出结果；它本身不等于奖励模型或强化学习算法。

常见形式包括两两比较、多个候选排序，以及按特定维度打分。数据形式和允许的选项应与后续训练方法匹配，不能默认所有工具都支持并列、跳过或完全相同的导出格式。

## 一条偏好记录

以下是教学数据，不是实际平台导出：

```json
{
  "prompt": "根据给定资料总结会议决定",
  "chosen": "准确保留决定、负责人和截止时间的回答",
  "rejected": "遗漏负责人并添加无依据结论的回答",
  "criterion": "忠于资料且覆盖必要信息"
}
```

chosen 表示比较中被偏好的一项，不代表绝对正确。两项都不好、信息不足或存在分歧时，应按事先定义的标注规则处理，而非强行制造可靠标签。

## 标注结果用在哪里

比较数据可以用于训练 [[奖励模型]]、偏好优化或评估模型。以奖励模型训练为例：先收集比较数据，再训练评分器；如果随后用评分器优化生成策略，那是后续训练环节。

工程上宜保留任务来源、候选版本、评价标准与必要的审核信息，检查标注一致性及训练／评估数据重叠。以上是数据质量建议，并非所有标注平台已自动具备的能力。

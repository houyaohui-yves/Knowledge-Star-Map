# 思维链（Chain-of-Thought）

## 核心认识

Chain-of-Thought（CoT，思维链）通常指通向答案的一系列中间推理步骤。经典 CoT prompting 通过提示中的解题示范，引导模型先生成中间步骤，再给出答案。应区分作为过程或文本的“思维链”和用来引出它的“思维链提示方法”。

CoT 关注怎样逐步推导；ReAct 关注怎样把推理、行动和环境反馈交替组织；Workflow 关注执行编排；RAG 关注检索外部资料并用于生成；平台提供构建与运行环境。这些概念可以组合。

## 解释与证据

### 直观例子

助手自拟教学示例，非模型实测，也不代表模型内部过程的逐字记录：

题目：买 3 本书，每本 12 元，优惠 6 元，实付多少？

- 直接答案：30 元。
- 带中间步骤的解答：总价为 3 × 12 = 36 元；减去优惠后为 36 − 6 = 30 元。

中间步骤把原问题转成更小的推导与计算，使结果可以逐项检查。但写出步骤不等于这些步骤一定正确。

### 与 Prompt、Few-Shot 的关系

2022 年的 CoT prompting 论文在提示中提供包含“问题—中间推理—答案”的少量示范，并在特定算术、常识和符号推理任务上观察到提升。这是通过上下文引导推理的方式，不要求每次提示都更新模型权重，也不能把论文实验结果外推为对所有模型和任务都有效。

后续 Zero-shot-CoT 研究使用类似“让我们一步一步思考”的提示，在没有手工示范的情况下引出逐步推理。这里的 Zero／Few-Shot 仍按示范任务的数量计算；推理写了多少步不改变 Shot 数。

仅要求答案更长不等于要求有效推理。是否使用这类提示，应结合模型与任务验证，不把某句提示当作普遍有效的固定配方。

### 与 ReAct 及多轮上下文的区别

```text
CoT（简化）：问题 → 中间推导 → 答案
ReAct（简化）：目标 → 推理 → 工具行动 → 实际观察 → 更新判断 → 后续行动或答案
```

经典文本 CoT 可以在一次模型调用中生成。已有的中间文本成为后续生成可利用的前缀，不需要每写一步就重新发送一次 API 请求。

此前讨论的 ReAct 多轮衔接则会将实际工具调用与返回结果提供给后续模型调用。这引入了来自环境的新信息。CoT 文本描述“我查询到某结果”不等于系统真的执行过查询。

ReAct 原方法把推理轨迹与行动交替组织，因此两者有直接联系；但不能把 ReAct 中的每次判断都等同于完整、长篇的 CoT，也不能把所有带工具的推理系统都判定为经典 ReAct 实现。经典 ReAct 项目也展示了稀疏推理轨迹的设计。

### 与已有概念的关系

| 概念 | 关注什么 | 与 CoT 怎样配合 |
| --- | --- | --- |
| Prompt | 本次给模型的任务、信息和约束 | 可提供逐步解题示范或要求可检查的推导 |
| Workflow | 节点、条件与执行顺序 | 某个 LLM 节点可以使用 CoT；节点之间的连线不等于思维链 |
| ReAct | 推理与行动、观察反馈的交替 | 推理帮助选择或调整行动，实际工具反馈提供新信息 |
| RAG | 检索相关证据并用于生成 | 先提供证据，再由模型结合证据推导；推导不能替代缺失的事实 |
| 工具与代码执行 | 落实外部操作或计算 | 模型可设计求解方法，计算器或程序执行计算；必须核对实际返回结果 |
| Agent 平台 | 系统的构建和运行支持 | 可以承载上述组合；平台画布或“思考”界面不自动证明采用了特定方法 |

这张关系表是依据已查阅资料及既有笔记的教学归纳，不是论文给出的统一分类。

## 适用边界与常见误区

- CoT 不等于 Agent；只有逐步解答时，并未自动建立工具执行循环。
- CoT 不等于多轮对话或多次 API 调用；它可以在单次生成中出现。
- 中间步骤可能出错，也可能围绕错误答案形成看似合理的解释；长篇解释不能替代事实、计算或测试验证。
- 可见解释不能被无条件视为模型内部计算与决策原因的完整记录。研究发现部分 CoT 会遗漏真正影响输出的偏置因素；这个结论不意味着所有推理解释都无用或不真实。
- 评价时应检查结论和可验证依据。阅读界面上的推理说明，不足以确定底层实现或证明结果正确。

本节收尾还区分了“中间推理”“根据行动反馈调整”和“评价已有结果后修正”。反思的边界与后续学习范围见 [[Agent入门：Workflow、ReAct与平台#从行动反馈到自主反思]]，不将 CoT 自动等同于反思机制。

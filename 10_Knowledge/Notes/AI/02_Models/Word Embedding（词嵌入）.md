# Word Embedding（词嵌入）

## 核心认识

Word Embedding（词嵌入）用学习得到的向量表示词，是 [[Embedding(嵌入)]] 的一种。经典静态词嵌入为每个词保存一个固定向量，使词的使用关系能够通过训练反映在表示中。

## 从离散编码到学习表示

仅给词一个编号，不能让编号差反映语义。教学示例：设词表只有“猫、狗、汽车”，独热编码分别为 `[1,0,0]`、`[0,1,0]`、`[0,0,1]`。任意两个不同词的点积均为 0，因此这种编码本身没有表达“猫与狗更相关”。

Word Embedding 则让训练数据和目标决定词的向量。经典 [[Word2Vec]] 通过 CBOW（周围词预测中心词）或 Skip-gram（中心词预测周围词）的任务调整词向量，使其能编码有用的语言关系。使用环境相似的词可能形成相近表示；不是人工逐维填写“动物属性”“颜色属性”等标签，也不是训练后每次比较两个词时再重新学习向量。训练与查表的区别、具体矩阵和窗口示例由 Word2Vec 笔记维护。

## 学到了什么：坐标与关系

同一模型中，每个词的向量维度相同。例如有 10000 个词、每词 300 维，就可以把词向量看成 10000×300 的矩阵，每行对应一个词。300 是表示维度；其中的数值由训练得到，单个坐标通常没有稳定的人类可读含义。Embedding 不能只定义成“降维”：降低独热表示的维度是经典词向量的一个特点，核心还在于学习对象之间有用的关系。

课件第 17 页展示 `king` 的一个 50 维 GloVe 向量，并用热图呈现坐标大小。这说明一个词可以用一组实数表示，颜色只是数值可视化，不代表某个维度是“国王程度”或一个概率。课件将范围概括为 `[-2,2]`，但其示例实际包含 `−2.223`；不能把这个范围作为词向量的通用约束。

GloVe 与 Word2Vec 都是学习词嵌入的方法，但不是同一个算法：GloVe 利用全局词—词共现统计，Word2Vec 通过局部上下文预测任务学习表示。课件先用 GloVe 举例，再转入 Word2Vec，需要区分例子使用的方法。

### king − man + woman ≈ queen 表达什么

课件第 18 页展示这个经典类比：

$$
\mathbf v_{king}-\mathbf v_{man}+\mathbf v_{woman}\approx\mathbf v_{queen}
$$

直观解释：某些训练空间中，“man → woman”的关系方向与“king → queen”近似对应；对给定向量作组合，再查询近邻，可能找到 `queen`。这是统计关系的几何示意，不是逐坐标严格相等的恒等式，也不是任意词组都能成功的语义推理规则。工具的归一化与组合方式还会影响查询结果。

高相似度也可能来自相关话题、相似用法而非同义：例如小说里经常出现在相关场景的两个人物，词向量可以接近，却仍是两个不同人物。不能由词类比的成功推出模型能可靠判断整句的否定、比较或事实矛盾。

## 与酒店案例中 TF-IDF 向量的区别

| 比较点 | 酒店案例的 TF-IDF | 经典词嵌入 |
| --- | --- | --- |
| 一个向量表示谁 | 一家酒店的整段描述 | 词表中的一个词 |
| 坐标含义 | 对应词项或 N-Gram 的统计权重 | 训练得到的表示坐标，通常难以逐维命名 |
| 从哪里得到数值 | 文档内词频与全库文档频率等统计 | 语料、模型结构与训练目标 |
| 常见结构 | 高维 [[稀疏向量与稠密向量|稀疏向量]] | 较低维稠密向量 |

[[酒店内容推荐案例：TF-IDF、N-Gram与余弦相似度]] 比较的是酒店描述向量；将每个词换成词向量后，还需决定怎样得到每家酒店的整体表示，不能直接把词级查表当成完整推荐系统。两条路线都可以用余弦比较，但向量的生成方式和所表示的对象不同。

### 为什么从酒店向量转到“表示一个词”

前者回答“这篇介绍提到了哪些词项，各有多大权重”，后者回答“这个词怎样用可计算的坐标表示，它与其他词的使用关系怎样体现”。酒店案例先切分，再提取 N-Gram 候选，筛选得到所有酒店共用的词表；各酒店使用相同的列，只有列内数值不同，不是每家酒店各有一套维度。

助手自拟的简化语料：A 的介绍切分为“泳池／停车场”，B 为“游泳池／停车场”，C 为“早餐／健身房”。只取 Unigram，固定词项顺序 `[泳池, 游泳池, 停车场, 早餐, 健身房]`，为突出结构先用计数，暂不做 TF-IDF 加权：

```text
酒店 A：[1, 0, 1, 0, 0]
酒店 B：[0, 1, 1, 0, 0]
酒店 C：[0, 0, 0, 1, 1]
```

每个向量表示整篇介绍。在这套逐词项匹配的表示里，“泳池”和“游泳池”是不同列；这两列本身不告诉算法它们意思相近。实际酒店脚本还会加入 Bigram／Trigram、筛选特征、TF-IDF 加权与归一化，但没有因此学习这两个词的同义关系。

词嵌入可以另为“泳池”与“游泳池”分配相近坐标，例如 `[0.9,0.1]` 与 `[0.85,0.15]`。这里是助手人为设置的二维示意，不是训练结果；二维坐标不分别命名为某种设施。训练是否真能得到相近关系，要看语料、任务与效果验证。

如果再用这些词向量构造酒店表示，还需要汇聚步骤。例如假设“停车场”为 `[0.1,0.9]`，简单平均两个词，A 得到 `[0.5,0.5]`，B 得到 `[0.475,0.525]`，才重新获得可比较的酒店描述向量。示意坐标让两者方向接近，不证明真实推荐改善。完整平均与加权演算、同词不同关系的反例集中在 [[词向量汇聚为文本向量]]；这只是教学基线，不是词嵌入必须采用的唯一方案。

```text
原案例：酒店介绍 → 共同词项上的计数与 TF-IDF → 酒店向量 → 比较
词向量基线：酒店介绍 → 每个词的已学向量 → 汇聚 → 酒店向量 → 比较
```

Word2Vec 本身学习的是词向量表，**没有直接把原酒店的 3347 维 TF-IDF 向量压成一个词向量**。整篇文档降维与词级表示是不同问题。

### 向量、坐标、维度和权重的角色

酒店可以用 M 维向量表示，M 是筛选后共同词项数；[[N-Gram]] 中的 N 是片段长度，不能把两者认作同一个数。向量的元素是 TF-IDF 等数值权重，列名才对应词或多词片段。经典词嵌入则为一个词提供一个 D 维向量，其中元素是数值，不是 D 个词，也不是一个词必须对应多条向量。

同一词嵌入模型中 D 相同，才能按对应坐标汇聚；但 D 是模型配置，**没有必须小于当前应用 TF-IDF 词项数 M 的约束**。表示维度更小也不自动等于整个系统成本更低，参见 [[文本表示方案的选择：TF-IDF、词向量与句子向量#维度与成本不能直接画等号]]。

词嵌入与 TF-IDF 可以组合。词向量提供表示，TF-IDF 可以决定词在汇聚时的贡献；加权公式与条件见 [[词向量汇聚为文本向量#加权平均：可以结合 TF-IDF]]。选择是否加权、采用什么模型，仍需任务验证，不把词嵌入理解为通用的同义词替换或免除权重的步骤。

## 静态词向量与上下文化表示

经典静态词向量通常可看作一张查找表：每个词对应一个固定向量。例如英文 `bank` 的金融机构含义与河岸含义在静态表示中共用一个词向量。上下文化模型可以根据句子区分用法，产生不同的上下文表示。两者不能混为一谈。

Word Embedding 是 Embedding 的一种；**词向量、Token 向量与整句／文档向量的粒度不同**。RAG 通常检索句子或文档片段，所以需要文本级表示。词向量平均是可用的基线，但专门的句子模型可以学习更适合语义比较的表示，不能把所有文本 Embedding 统一解释为“把词向量求平均”。

## 适用边界

词向量的相似性受训练语料与目标影响，不保证所有任务上的语义判断。[[余弦相似度]] 只比较已生成的向量；高分也不能证明两个陈述没有矛盾，见 [[向量相似不等于语义一致]]。

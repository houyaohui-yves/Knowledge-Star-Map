# Embedding（嵌入）

## 核心认识

本文聚焦 AI 中常见的学习型 Embedding。Embedding 是把文字、图片、音频、用户或商品等对象，映射成一串固定维度数字向量的方法。这个向量是模型学习得到的表示，使具有相近语义、用途或关系的对象通常在向量空间中也更接近。

可以把它理解成给内容分配“语义坐标”：计算机无法直接计算两段自然语言“意思有多像”，但可以计算两个向量之间的距离或相似度。

```text
对象 x
  ↓ Embedding Model
向量 [0.12, -0.47, 0.83, ...]
```

Embedding 不是摘要、关键词列表或事实答案，也通常不能从向量精确还原原文。它是一种有损、面向任务的数学表示。

## “嵌入”这个词的范围

Embedding 是一个广义概念：

- **Token Embedding**：把单个 Token 映射成向量，是语言模型内部表示的起点。
- **[[Word Embedding（词嵌入）|Word Embedding]]**：把词映射成向量；经典静态词向量为词表中的每个词保存一个学习得到的向量。
- **上下文化表示**：同一个词在不同句子中会因上下文产生不同内部表示。
- **文本或句子 Embedding**：把一句话或一段文档压缩成一个向量，用于检索、聚类、分类和去重。
- **多模态 Embedding**：把文字、图片或音频映射到可比较的空间，用于跨模态搜索。

在 RAG 语境中，Embedding 通常指文本、句子或文档级的 Embedding，而不是 LLM 内部某个 Token 的向量。

## 向量为什么能表示语义

Embedding 模型在训练中学习：哪些对象应该靠近，哪些对象应该远离。它会把大量无法直接观察的语言特征编码进向量空间，例如主题、意图、实体关系、语气或任务相关性。

向量的单个维度通常没有稳定、可供人直接解释的含义；有意义的是整个向量的位置及它与其他向量的关系。

“相近”具体代表什么，取决于模型的训练目标。一个为语义检索训练的模型可能让“如何申请退款”和“退款办理流程”靠近；一个面向商品推荐的模型则可能更关注用户偏好。因此不存在脱离模型和任务的通用语义距离。

## 与统计文本表示的区别

[[N-Gram]] 从序列提取连续片段，[[TF-IDF]] 根据词项出现情况与全库统计构造向量；它们本身不要求训练神经网络。学习型 Embedding 则由模型的参数与训练目标决定表示。N-Gram 不是所有 Embedding 的必经前处理步骤。

TF-IDF 通常形成有明确词项维度的稀疏表示，常见文本 Embedding 使用稠密表示；但稀疏／稠密描述零值分布，不能直接当成“没有／具有语义能力”的分类，见 [[稀疏向量与稠密向量]]。

## Tokenization、N-Gram 与文本 Embedding 的分工

**生成向量不等于分割词元。** [[Token(词元)|Tokenization]] 把文本切成有序单元并编码为 ID；向量表示还取决于后续如何处理这些单元，以及模型的结构、参数和训练目标。

| 环节 | 主要作用 |
| --- | --- |
| Tokenization | 决定基本输入单元以及对应的 ID；保留单元序列 |
| [[N-Gram]] 特征提取 | 从单元序列构造连续 N 个单元的组合特征，可统计次数 |
| 上下文编码 | 利用位置与上下文关系生成表示 |
| 文本向量生成 | 将表示汇聚为句子／文档向量，表示应适配目标任务 |

两种常见路线的教学示意：

```text
统计特征路线：文本 → 切分 → N-Gram 提取 → 计数／加权 → 稀疏向量
上下文化文本模型：文本 → 模型配套 Tokenizer → Token ID
                 → Token 向量与位置等信息 → 上下文编码 → 汇聚 → 文本向量
```

第二条路线示意常见 Transformer 文本编码器，不是所有 Embedding 的统一架构。它通常不要求先人工构造 Bigram／Trigram。词元“不”单独切出仍可被模型理解为否定；把“不规范”并成一个词元也不自动解决它作用于哪个对象的问题。使用预训练模型时应保持配套 Tokenizer，不为改变词粒度随意更换词表。

## 如何比较向量

常见度量包括：

- **[[余弦相似度]]（Cosine Similarity）**：比较两个向量方向是否接近。
- **点积（Dot Product）**：同时受方向和向量长度影响；具体含义取决于模型训练方式。
- **欧氏距离（Euclidean Distance）**：比较空间中的直线距离。

应使用与 Embedding 模型训练和使用说明相适配的度量方式。两个非零向量分别做 [[向量的 L2 归一化|L2 单位归一化]] 后，其点积等于余弦相似度（实际计算可能有浮点误差）。

相似度只是模型空间中的接近程度，不等于事实正确、业务相关或能够回答问题。因此向量召回后仍可能需要 Metadata Filter、关键词检索和 Rerank。

## 向量接近的语义边界

例如“有泳池”和“没有泳池”谈论同一设施，事实判断却不同。如果表示未充分保留否定关系，两者可能仍然接近；余弦公式只能比较输入向量，不能读取原句来补回信息。不同模型的实际表现需要测量，不能由这个例子预设分数。

完整的规范／不规范句对、Unigram 与 N-Gram 演算，以及检索和矛盾判断的区别，集中在 [[向量相似不等于语义一致]]。Embedding 模型的训练目标决定“接近”更倾向表示话题相关、检索相关还是其他关系。

## Embedding 在 RAG 中的作用

建库阶段：

```text
Content / Question
→ Embedding Model
→ Document Vector / Question Vector
→ 写入向量索引并关联 chunk_id
```

查询阶段：

```text
用户 Query
→ 兼容的 Embedding Model
→ Query Vector
→ 搜索相近的已存储 Vector
→ 返回候选 chunk_id
→ 获取 Content
```

Query 和知识内容必须位于兼容的向量空间。最简单的做法是使用同一个模型和版本；某些专门的检索模型会为 Query 和 Document 使用不同提示前缀或不同编码器，但训练目标会让两侧向量仍然可比较。

不能直接比较由两个不兼容的 Embedding 模型产生的向量。更换模型、维度或关键配置时，通常需要重新为全部索引内容生成向量。

## Embedding 模型与向量数据库的分工

- **Embedding Model**：负责把对象转换成向量。
- **Vector Database / Vector Index**：负责保存、索引和搜索向量。
- **Knowledge Base**：负责管理原始内容、来源、版本、权限和知识结构。

少数产品会把生成向量和保存向量集成成一个服务，但三个概念的职责仍然不同。详见 [[知识库与向量数据库]]。

## 一个 RAG 例子

假设虚构商家的教学知识库包含以下规则（不是对现实退货政策的说明）：

```text
Content：商品签收后七天内，在保持完好的情况下可以申请退货。
```

用户问：

```text
东西到手后不想要了，几天以内能退？
```

两段话没有使用完全相同的词，但检索型 Embedding 可能把它们映射到相近位置，因为它们都涉及“签收后的退货时限”。向量检索因此能够找回该 Content，再由 LLM 根据原文回答“七天内”。

Embedding 只负责帮助找到候选段落；“七天”这个事实来自 Content，而不是从向量中读取出来。

## 模型选择与切片的影响

选择 Embedding 模型时通常要考虑：

- 是否支持目标语言与领域术语；
- 是否面向 Query–Document 检索、相似度或其他任务训练；
- 最大输入长度与长文本处理方式；
- 向量维度、存储成本、调用延迟和价格；
- 是否要求为 Query 与 Document 添加指定前缀；
- 在真实业务评测集上的 Recall@K 和排序表现。

Chunk 过长时，多个主题被压缩进同一个向量，语义可能被稀释；Chunk 过短时，又可能丢失必要上下文。因此 Embedding 效果与 [[RAG中的长文档语义切片]] 密切相关。

## 重要误区

- Embedding 不是加密，不能依赖它完整恢复原文，也不能把向量当成匿名化或安全保护机制。
- 向量维度越高不代表效果必然越好。
- 向量更相近不代表两段内容事实一致，也不代表一定能够回答问题。
- Embedding 模型不是向量数据库；一个生成向量，一个保存和搜索向量。
- 使用同一个模型不代表所有语言、领域和 Chunk 粒度都能取得理想效果，仍需业务评测。
- 原文和 Metadata 不能只保留向量后删除；向量是可以重建的检索索引，不是权威知识本身。

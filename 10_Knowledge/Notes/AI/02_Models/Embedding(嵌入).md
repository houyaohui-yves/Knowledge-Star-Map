# Embedding（嵌入）

## 核心认识

Embedding 是把文字、图片、音频、用户或商品等对象，映射成一串固定维度数字向量的方法。这个向量是模型学习得到的表示，使具有相近语义、用途或关系的对象通常在向量空间中也更接近。

可以把它理解成给内容分配“语义坐标”：计算机无法直接计算两段自然语言“意思有多像”，但可以计算两个向量之间的距离或相似度。

```text
对象 x
  ↓ Embedding Model
向量 [0.12, -0.47, 0.83, ...]
```

Embedding 不是摘要、关键词列表或事实答案，也通常不能从向量精确还原原文。它是一种有损、面向任务的数学表示。

## “嵌入”这个词的范围

Embedding 是一个广义概念：

- **Token Embedding**：把单个 Token 映射成向量，是语言模型内部表示的起点。
- **Word Embedding**：把词映射成向量；经典静态词向量为词表中的每个词保存一个学习得到的向量。
- **上下文化表示**：同一个词在不同句子中会因上下文产生不同内部表示。
- **文本或句子 Embedding**：把一句话或一段文档压缩成一个向量，用于检索、聚类、分类和去重。
- **多模态 Embedding**：把文字、图片或音频映射到可比较的空间，用于跨模态搜索。

在 RAG 语境中，Embedding 通常指文本、句子或文档级的 Embedding，而不是 LLM 内部某个 Token 的向量。

## 向量为什么能表示语义

Embedding 模型在训练中学习：哪些对象应该靠近，哪些对象应该远离。它会把大量无法直接观察的语言特征编码进向量空间，例如主题、意图、实体关系、语气或任务相关性。

向量的单个维度通常没有稳定、可供人直接解释的含义；有意义的是整个向量的位置及它与其他向量的关系。

“相近”具体代表什么，取决于模型的训练目标。一个为语义检索训练的模型可能让“如何申请退款”和“退款办理流程”靠近；一个面向商品推荐的模型则可能更关注用户偏好。因此不存在脱离模型和任务的通用语义距离。

## N-Gram：连续片段与局部统计

N-Gram 是序列中连续 N 个单元组成的片段。单元可以是词、字符或 Token，使用时须说明粒度。它描述片段结构；**N 不表示向量维度，也不是把长文档分成 N 份**。

教学示例：人为按词切分“我 / 喜欢 / 学习 / AI”，不添加句首、句尾标记：

| N | 名称 | 连续片段 |
| --- | --- | --- |
| 1 | Unigram | 我；喜欢；学习；AI |
| 2 | Bigram | 我 喜欢；喜欢 学习；学习 AI |
| 3 | Trigram | 我 喜欢 学习；喜欢 学习 AI |

这些片段通过滑动窗口获得，可以重叠。字符级示例：“向量数据库”的字符 Bigram 为“向量、量数、数据、据库”。这不等于某个模型的实际 Token 切分结果。

需要区分两个用法：

- **N-Gram 特征**：统计连续片段的出现次数，用于文本表示或匹配；片段计数可构成稀疏向量，但不会自动建立不同表达之间的语义联系。
- **N-Gram 语言模型**：用前 N−1 个单元近似完整历史，估计下一个单元的概率。例如 Bigram 模型用 $P(w_t\mid w_{t-1})$ 近似 $P(w_t\mid w_1,\ldots,w_{t-1})$。

N-Gram 提供局部顺序与统计信息，不能单凭片段相同与否充分判断语义。例如“购买”和“买入”字面不同，表达的意思却可能相近。它不是 Embedding 的必经前处理步骤；统计特征与学习得到的向量也可以结合使用。

### Tokenization、N-Gram 与文本 Embedding 的分工

**生成向量不等于分割词元。** [[Token(词元)|Tokenization]] 把文本切成有序单元并编码为 ID；向量表示还取决于后续如何处理这些单元，以及模型的结构、参数和训练目标。

| 环节 | 主要作用 |
| --- | --- |
| Tokenization | 决定基本输入单元以及对应的 ID；保留单元序列 |
| N-Gram 特征提取 | 从单元序列构造连续 N 个单元的组合特征，可统计次数 |
| 上下文编码 | 利用位置与上下文关系生成表示 |
| 文本向量生成 | 将表示汇聚为句子／文档向量，表示应适配目标任务 |

两种常见路线的教学示意：

```text
统计特征路线：文本 → 切分 → N-Gram 提取 → 计数／加权 → 稀疏向量
上下文化文本模型：文本 → 模型配套 Tokenizer → Token ID
                 → Token 向量与位置等信息 → 上下文编码 → 汇聚 → 文本向量
```

第二条路线示意常见 Transformer 文本编码器，不是所有 Embedding 的统一架构。它通常不要求先人工构造 Bigram／Trigram。词元“不”单独切出仍可被模型理解为否定；把“不规范”并成一个词元也不自动解决它作用于哪个对象的问题。使用预训练模型时应保持配套 Tokenizer，不为改变词粒度随意更换词表。

用户提供的 N-Gram 课件混合介绍了片段、特征与语言模型。需要校准：

- “只依赖前 N−1 个词”是 N-Gram 语言模型对当前词概率的近似假设；是忽略更早历史的模型选择，不是现实语言中其他词都不相关的事实。
- “N 个 item 的序列”应明确为原序列中连续 N 个单元；`A B C D E` 的 Bigram 为 `AB、BC、CD、DE`。
- “相邻两个关键词的特征组合”只描述 N=2 的 Bigram；一般 N-Gram 组合的是 N 个连续单元，不要求它们是关键词。

截图及其识别范围见 [[2026-10-02 Embedding与向量数据库学习记录#N-Gram 课件截图]]。

## Word Embedding：从离散词到学习得到的向量

仅给词一个编号，不能让编号差反映语义。教学示例：设词表只有“猫、狗、汽车”，独热编码分别为 `[1,0,0]`、`[0,1,0]`、`[0,0,1]`。任意两个不同词的点积均为 0，因此这种编码本身没有表达“猫与狗更相关”。

Word Embedding 则让训练数据和目标决定词的向量。经典 Word2Vec 的两种训练方式是：

- **CBOW**：根据周围词预测中心词。
- **Skip-gram**：根据中心词预测周围词。

通过这样的预测任务，模型调整词向量，使其能编码有用的语言关系。使用环境相似的词可能形成相近表示；不是人工逐维填写“动物属性”“颜色属性”等标签，也不是训练后每次比较两个词时再重新学习向量。

经典静态词向量通常可看作一张查找表：每个词对应一个固定向量。例如英文 `bank` 的金融机构含义与河岸含义在静态表示中共用一个词向量。上下文化模型可以根据句子区分用法，产生不同的上下文表示。两者不能混为一谈。

Word Embedding 是 Embedding 的一种；**词向量、Token 向量与整句／文档向量的粒度不同**。RAG 通常检索句子或文档片段，所以需要文本级表示。词向量平均是可用的基线，但专门的句子模型可以学习更适合语义比较的表示，不能把所有文本 Embedding 统一解释为“把词向量求平均”。

## 如何比较向量

常见度量包括：

- **余弦相似度（Cosine Similarity）**：比较两个向量方向是否接近。
- **点积（Dot Product）**：同时受方向和向量长度影响；具体含义取决于模型训练方式。
- **欧氏距离（Euclidean Distance）**：比较空间中的直线距离。

应使用与 Embedding 模型训练和使用说明相适配的度量方式。两个非零向量分别做 L2 单位归一化后，其点积等于余弦相似度（实际计算可能有浮点误差）。

相似度只是模型空间中的接近程度，不等于事实正确、业务相关或能够回答问题。因此向量召回后仍可能需要 Metadata Filter、关键词检索和 Rerank。

### 余弦相似度的计算

对处于同一个可比较空间的两个非零向量 $\mathbf a$、$\mathbf b$：

用户提供的课件截图从点积的几何关系解释了公式来源。设两向量夹角为 $\theta$：

$$
\mathbf a\cdot\mathbf b=\|\mathbf a\|_2\|\mathbf b\|_2\cos\theta
$$

两边除以非零的长度乘积，就得到下面的余弦相似度公式；因此可以直接通过坐标计算，不必先求出夹角。截图与识别范围见 [[2026-10-02 Embedding与向量数据库学习记录#课件截图与核对]]。

$$
\operatorname{cos\_sim}(\mathbf a,\mathbf b)
=\frac{\mathbf a\cdot\mathbf b}{\|\mathbf a\|_2\|\mathbf b\|_2}
=\frac{\sum_{i=1}^{d}a_i b_i}{\sqrt{\sum_{i=1}^{d}a_i^2}\sqrt{\sum_{i=1}^{d}b_i^2}}
$$

分子是对应坐标相乘后求和，即点积；分母是两个向量长度的乘积。结果等于两条向量夹角的余弦，比较的是方向。

教学示例，仅为演示计算，不是实际模型输出：取 $\mathbf a=(1,2)$、$\mathbf b=(2,1)$：

1. 点积：$1\times2+2\times1=4$。
2. 长度：$\|\mathbf a\|_2=\sqrt{1^2+2^2}=\sqrt5$，$\|\mathbf b\|_2=\sqrt5$。
3. 相似度：$4/(\sqrt5\times\sqrt5)=0.8$。

| 夹角 | 分数 | 数学含义 |
| --- | --- | --- |
| 0° | 1 | 方向完全相同，长度可以不同 |
| 90° | 0 | 两个向量正交 |
| 180° | −1 | 方向完全相反 |

夹角在 $[0°,180°]$ 内越小，余弦相似度越大。“方向接近”对应分数接近 1；只有完全同向时才等于 1。

一般取值范围是 $[-1,1]$；零向量不能用此公式计算。对只含非负分量的非零向量，范围为 $[0,1]$，但一般稠密 Embedding 可以有负分量。

向量 $(1,2)$ 与 $(2,4)$ 的余弦相似度是 1，说明余弦对正比例缩放不变。数学上的反方向不自动等于语言上的反义；0.8 也不是“意思有 80% 一样”或“有 80% 的概率正确”。同一话题的相反陈述也可能被模型映射得较近，实际分数必须计算，不能仅凭词义指定。

### 相似不等于一致：否定与比较关系的反例

用户提出两句话：

> 这个程序代码不规范，那个更规范。
>
> 这个程序代码规范，那个更不规范。

在“这个／那个”指向相同程序、评价标准一致的前提下，第一句表达“那个更规范”，第二句表达“那个更不规范”，比较方向相反；两句也分别否定和肯定了“这个程序代码规范”。它们讨论同一话题，但判断并不一致。

**高余弦相似度不能证明语义等价或没有矛盾。** 需要区分两个环节：

1. Embedding 模型决定文本如何表示，能否在向量中充分体现否定作用于哪个对象、比较方向等关系。
2. 余弦公式只比较给定向量的方向；它不读取原句，也不直接判断逻辑关系。

如果表示主要保留主题和词汇联系，而不足以区分上述关系，两句的向量可能很接近。现代上下文化文本模型可以编码顺序与否定，不能据此例断言所有模型都会忽略“不”，或一定输出接近 1 的分数。本例没有调用具体 Embedding 模型，真实分数仍待指定模型后计算。

一个更容易严格推演的教学表示是只统计 Unigram 词频。人为切分为：

```text
这个 / 程序 / 代码 / 不 / 规范 / 那个 / 更 / 规范
这个 / 程序 / 代码 / 规范 / 那个 / 更 / 不 / 规范
```

两句每个词的次数完全相同；按词表 `[这个, 程序, 代码, 不, 规范, 那个, 更]` 构造词频向量，都是 `[1, 1, 1, 1, 2, 1, 1]`，因此余弦相似度恰为 1。这里丢掉的是词序以及“不”的作用范围，即使换成欧氏距离，也无法从相同向量中找回丢失的信息。这是人为词频表示的计算，不是现代文本 Embedding 的实测结果。

保持上述切分，去掉标点、不加入句首句尾标记，改为只统计 Bigram：

| 句子 | 全部连续二元片段 |
| --- | --- |
| 第一句 | 这个 程序；程序 代码；代码 不；不 规范；规范 那个；那个 更；更 规范 |
| 第二句 | 这个 程序；程序 代码；代码 规范；规范 那个；那个 更；更 不；不 规范 |

每句有 7 个各出现一次的片段，两句共有 5 个片段。按两句片段的并集建立统一词表，计数向量的点积为 5，长度均为 $\sqrt7$，余弦相似度为 $5/7\approx0.714$。改用纯 Trigram 计数时，每句 6 个片段、共有 2 个，得到 $2/6\approx0.333$。本项目用脚本核对了这些人为片段计数，未运行文本 Embedding 模型。

这里输入单元没有改变，改变的是构造向量的特征。加入局部顺序可以区分两句，却不表示模型已经识别矛盾；更大的 N 也不保证对所有句子更好，可能增加稀疏性并难以匹配不同措辞。应按 [[Embedding(嵌入)#Tokenization、N-Gram 与文本 Embedding 的分工|表示环节]] 判断改进位置，不能将特征片段组合与分词混为一谈。

应用时应区分“找相关内容”和“判断内容是否一致”。向量检索可以用于召回候选；若目标是识别矛盾，则需进一步分析原文的对象、否定、比较和条件，可使用面向蕴含／矛盾／中立关系的 Natural Language Inference（NLI）模型辅助判断，并验证目标领域表现。一般检索 Reranker 的相关性分数也不能自动当作无矛盾证明。否定句或矛盾句还可作为训练时难区分的负例，但改进效果须具体评测。

改进路径需适配任务：

1. 若采用词频／TF-IDF 等统计表示，可加入 N-Gram 特征，检查预处理是否错误删掉否定等重要信息；它改善局部表达，不能作为完整逻辑判断。
2. 若采用上下文化文本 Embedding，保持模型配套分词器，依据否定、比较、对象互换等真实句对评测模型；有训练需求时可加入同主题但含义矛盾的难负例，训练目标应明确区分“话题相关”和“意思一致”。
3. 若最终任务是识别矛盾，增加直接读取原文句对的 NLI 分类等判断步骤。本例可以先提取“对象 A 是否规范”和“A／B 的比较方向”再对照；这属于推演建议，没有实现实际分类器。模型判断仍需验证，不能仅提高相似度阈值或换个距离函数就宣称解决。

### 三个概念如何衔接

| 概念 | 主要回答的问题 |
| --- | --- |
| N-Gram | 序列中出现了哪些连续片段？或如何用短历史预测下一单元？ |
| Word Embedding | 怎样用学习得到的向量表示一个词及其语言关系？ |
| 余弦相似度 | 给定两个向量，方向有多接近？ |

余弦相似度可以比较稀疏统计向量，也可以比较稠密 Embedding；它不是专属于 Embedding 的算法。是否有语义解释，取决于向量如何构造或训练。

## Embedding 在 RAG 中的作用

建库阶段：

```text
Content / Question
→ Embedding Model
→ Document Vector / Question Vector
→ 写入向量索引并关联 chunk_id
```

查询阶段：

```text
用户 Query
→ 兼容的 Embedding Model
→ Query Vector
→ 搜索相近的已存储 Vector
→ 返回候选 chunk_id
→ 获取 Content
```

Query 和知识内容必须位于兼容的向量空间。最简单的做法是使用同一个模型和版本；某些专门的检索模型会为 Query 和 Document 使用不同提示前缀或不同编码器，但训练目标会让两侧向量仍然可比较。

不能直接比较由两个不兼容的 Embedding 模型产生的向量。更换模型、维度或关键配置时，通常需要重新为全部索引内容生成向量。

## Embedding 模型与向量数据库的分工

- **Embedding Model**：负责把对象转换成向量。
- **Vector Database / Vector Index**：负责保存、索引和搜索向量。
- **Knowledge Base**：负责管理原始内容、来源、版本、权限和知识结构。

少数产品会把生成向量和保存向量集成成一个服务，但三个概念的职责仍然不同。详见 [[知识库与向量数据库]]。

## 一个 RAG 例子

假设虚构商家的教学知识库包含以下规则（不是对现实退货政策的说明）：

```text
Content：商品签收后七天内，在保持完好的情况下可以申请退货。
```

用户问：

```text
东西到手后不想要了，几天以内能退？
```

两段话没有使用完全相同的词，但检索型 Embedding 可能把它们映射到相近位置，因为它们都涉及“签收后的退货时限”。向量检索因此能够找回该 Content，再由 LLM 根据原文回答“七天内”。

Embedding 只负责帮助找到候选段落；“七天”这个事实来自 Content，而不是从向量中读取出来。

## 模型选择与切片的影响

选择 Embedding 模型时通常要考虑：

- 是否支持目标语言与领域术语；
- 是否面向 Query–Document 检索、相似度或其他任务训练；
- 最大输入长度与长文本处理方式；
- 向量维度、存储成本、调用延迟和价格；
- 是否要求为 Query 与 Document 添加指定前缀；
- 在真实业务评测集上的 Recall@K 和排序表现。

Chunk 过长时，多个主题被压缩进同一个向量，语义可能被稀释；Chunk 过短时，又可能丢失必要上下文。因此 Embedding 效果与 [[RAG中的长文档语义切片]] 密切相关。

## 重要误区

- Embedding 不是加密，不能依赖它完整恢复原文，也不能把向量当成匿名化或安全保护机制。
- 向量维度越高不代表效果必然越好。
- 向量更相近不代表两段内容事实一致，也不代表一定能够回答问题。
- Embedding 模型不是向量数据库；一个生成向量，一个保存和搜索向量。
- 使用同一个模型不代表所有语言、领域和 Chunk 粒度都能取得理想效果，仍需业务评测。
- 原文和 Metadata 不能只保留向量后删除；向量是可以重建的检索索引，不是权威知识本身。

- [Mikolov 等：Efficient Estimation of Word Representations in Vector Space](https://arxiv.org/html/1301.3781)：查阅词的连续表示、CBOW 与 Skip-gram 的训练任务；不将论文中的实验表现推广为所有模型的效果保证。
- [Reimers 与 Gurevych：Sentence-BERT](https://arxiv.org/abs/1908.10084)：查阅摘要，支持专门学习可用余弦比较的句子表示；不据此声称所有 LLM 隐藏状态都适合直接检索。
- [Introduction to Information Retrieval：Dot products](https://nlp.stanford.edu/IR-book/html/htmledition/dot-products-1.html)：支持点积、欧氏长度、余弦公式和单位归一化关系。
- [Wang 等：SNCSE: Contrastive Learning for Unsupervised Sentence Embedding with Soft Negative Samples](https://arxiv.org/abs/2201.05979)：查阅摘要，支持部分无监督对比学习表示可能高估字面相近但语义不同句子的相似度，以及使用否定句作为负例的训练思路；不支持对本例的具体分数或全部模型做保证。
- [Sentence Transformers：Natural Language Inference](https://www.sbert.net/examples/sentence_transformer/training/nli/README.html)：支持蕴含／矛盾／中立的任务定义、矛盾句作为难负例，以及句对分类与向量相似度的分工；本文的候选召回后核对原文是应用建议，未在本项目实现。
- [Hugging Face：Tokenizers](https://huggingface.co/learn/llm-course/chapter2/4)：查阅切分与 ID 转换、模型配套规则与词表，支持 Tokenization 与学习表示的分工。
- [scikit-learn：Text feature extraction](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction)：查阅 tokenizer 与 N-Gram 提取职责、Bigram 保留局部顺序，以及 bag-of-N-Grams 仍丢失大量结构的限制；支持统计特征的改进与边界。
- [Sentence Transformers：Creating Custom Models](https://www.sbert.net/docs/sentence_transformer/usage/custom_models.html)：查阅 Transformer 上下文表示与 Pooling 汇聚职责，支持常见文本向量流水线；不推广为所有 Embedding 架构。
- [Sentence Transformers — Semantic Search](https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)：已查阅同空间编码、对称／非对称任务和归一化检索说明，支持本文的文本检索流程；不涵盖所有类型的 Embedding。
- 本文聚焦 RAG 常见的固定维度稠密文本向量；示意坐标不是实际模型输出，模型效果与切片选择未在本项目评测。

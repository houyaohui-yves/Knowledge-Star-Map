# 向量近邻检索：精确搜索与近似搜索

## 核心认识

近邻搜索回答“哪些向量最接近查询向量”；Top-K 指选出前 K 个候选。**精确搜索追求按指定度量得到真实近邻，近似搜索用可能遗漏近邻的方式换取速度等收益**。这里的“精确”描述数值搜索结果，不是对文本事实或意思的确认。

先确定检索集合、查询表示与度量，再谈精确或近似；改变模型、过滤集合或度量，会改变“正确近邻”的定义。

## 精确搜索怎样做

最直接的方法是遍历全部 N 个候选，逐一计算与查询向量的距离，再取距离最小的 K 项。对于 D 维向量，距离计算工作量约随 N×D 增长；还需考虑选出 Top-K 的成本。

助手自拟的二维例子：查询 `q=[1,0]`，候选如下。采用平方欧氏距离时，无需开根号即可排序。

| 候选 ID | 向量 | 与 q 的平方欧氏距离 |
| --- | --- | --- |
| 0 | `[0.7,0.2]` | 0.13 |
| 1 | `[0.2,0.6]` | 1.00 |
| 2 | `[0.8,0.1]` | 0.05 |
| 3 | `[-0.4,0.3]` | 2.05 |

K=3 时依次返回 ID `[2,0,1]`。例如 ID 2 的距离为 `(1−0.8)²+(0−0.1)²=0.05`。公式和其他度量的关系见 [[欧氏距离与平方欧氏距离]]。

课件使用的 `faiss.IndexFlatL2` 就是遍历式精确搜索；包上 `IndexIDMap` 只是改变返回的 ID 标签，不会把搜索变成 ANN，也不会训练 Embedding 模型。

## 近似搜索怎样减少工作

ANN 是 Approximate Nearest Neighbor，近似近邻搜索。它不总是比较所有候选，可以借助预先组织的索引缩小搜索范围，也可能用近似表示进行比较。

两类常见结构只需先理解思路：

- **IVF**：将向量分到若干组，查询时选部分组再搜索；未搜索的组中可能存在更近的向量。
- **HNSW**：以图连接向量，查询时沿图探索接近的候选；有限探索可能遗漏更好的结果。

不同结构需要不同的构建与查询参数。扩大搜索范围往往能提高近邻召回，同时增加查询成本，实际收益要测。索引中的聚类、量化或图构建与训练语义 Embedding 是不同阶段；并非所有索引都需要 `train()`。

## 为什么更快的结果不一定更好

把“找近邻”与“找答案”分成两层：

| 检查问题 | 衡量的对象 | 一个失败例子 |
| --- | --- | --- |
| 是否找回精确搜索的近邻？ | 索引的近邻召回与资源成本 | ANN 没搜索到最近向量所在的组 |
| 近邻是否与用户任务相关、能支撑答案？ | 表示、内容与业务效果 | 精确找到相似文本，但它讲年卡权益而非退款流程 |

自拟示例：精确 Top-3 为 `{A,B,C}`，近似返回 `{A,C,D}`，按集合重合计算的近邻 Recall@3 为 `2/3`。这个数不是问答正确率；若 B 本来就是无关文本，漏掉它对业务的影响还要另判。没有距离并列时，此例的精确集合唯一；存在并列时评测应约定如何处理。

只优化索引无法补回清洗时删除的否定词，也无法让错误的原始政策变正确。有关表示边界见 [[向量相似不等于语义一致]]。

## 实践中的顺序与边界

1. 小数据先用精确搜索检查表示与度量，建立同一数据的基准结果。
2. 若查询成本确实成为问题，再比较近似索引的近邻召回、耗时、内存和构建成本。
3. 另外检查内容相关性与业务指标，不把索引召回当成最终效果。

这是助手补充的验证建议，没有“超过多少条就必须用 ANN”的统一阈值。K=3 也只是课件参数，不表示前三条都合格；资料不足时应允许少返回。过滤前后 Top-K 的区别见 [[向量检索中的ID与元数据#元数据也决定检索范围]]。

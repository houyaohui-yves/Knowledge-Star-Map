# 向量检索中的ID与元数据

## 核心认识

向量让系统找到“接近的对象”，**ID 让系统找回准确的记录，元数据让系统知道记录的来源、适用范围和筛选条件**。只有向量和距离而没有可用的内容映射，检索结果就难以展示或用于问答。

Metadata 是描述记录的附加字段，例如来源文件、页码、类别、作者、版本或城市。原文不是描述字段本身；有些系统将原文和 Metadata 都保存在 Payload 中，命名需结合具体接口理解。

## 三种标识不要混用

课件记录同时涉及三种数字／名称：

| 标识 | 例子 | 作用 |
| --- | --- | --- |
| 业务记录 ID | `doc3` | 标识原始文档；长文档切成多块时，还需块级标识 |
| 向量 ID | 整数 `2` | FAISS `IndexIDMap` 返回的标签，应用用它查对应内容 |
| 当前列表位置 | `metadata_store[2]` | 只是内存容器的第 3 项，不自动等于向量 ID |

全量一次写入且没有失败时，向量 ID 和列表位置可能恰好相等。一旦跳过、重排或删除记录，这种隐含约定就可能失效。

课件的 `IndexIDMap` 使用 64 位整数标签；这不代表所有向量数据库都只能用整数 ID。业务字符串 ID 与检索整数 ID 可以通过显式映射关联。应用应保证约定范围内的唯一性，不把重复 ID 的处理交给偶然行为。

## 如何把近邻还原成可用内容

助手自拟的最小结构：

```text
索引：向量ID 102 → [0.8, 0.1, ...]
记录表：102 → {
  business_id: doc3,
  text: “在线购票的退款申请应通过原渠道提交……”,
  metadata: {category: 退票政策, source: online_policy.html, version: v2}
}
```

查询返回 `(102, 距离)`，用键 `102` 查到正文和元数据，才能展示“候选内容是什么、来自哪里”。原文不能从 Embedding 无损解码回来。

[[FAISS]] 不管理这张业务记录表，应用可以用按 ID 建立的字典，后续再采用持久存储。提供 Payload 的数据库则可以在一次查询中一起返回记录字段。逻辑上的向量、内容和来源关系仍须正确。

## 课件中列表映射为何会出错

原代码生成向量失败时执行 `continue`，成功时却一边把记录追加到列表，一边保留原始循环编号作为向量 ID。

假设原文档顺序为 `[doc1,doc2,doc3]`，doc1 失败：

```text
成功写入的向量ID： [1, 2]
记录列表：         [doc2, doc3]
列表位置：          0     1
```

查询返回 ID 1，本应拿到 doc2；`metadata_store[1]` 却拿到 doc3。查询返回 ID 2，则访问越界。这是助手构造的失败场景，本机已用普通 Python 容器复现；不是课件截图发生过的事故。

改为 `metadata_by_id[1]=doc2`、`metadata_by_id[2]=doc3` 后，按键查找不受列表压缩影响。更完整的代码片段和成功截图见 [[FAISS文本检索案例：向量、ID与元数据#处理失败时如何保持映射正确]]。

## 元数据也决定检索范围

例如查询“西雅图、每晚不超过 200 的泳池酒店”，可以用向量匹配需求，用 `city=Seattle AND price<=200` 限定候选。检索分数不保证城市、价格或适用版本满足条件，明确的字段约束应显式表达。

**“在合格集合中取 Top-K”与“全库取 Top-K 后删除不合格结果”可能不同。** 自拟例子：全库前 3 条都在别的城市，排名第 4 的才是西雅图酒店。取 3 条后过滤会得到空结果，但西雅图集合中并非没有候选。

具体引擎如何执行过滤取决于索引与查询计划。应验证过滤后的召回；也可扩大候选或采用适合过滤的索引方案，不能声称任何产品都天然保证同样效果。权限过滤是资格条件，还应在取回正文时依据可靠授权信息复核，元数据中写一个 `permission` 字段不会自动建立权限系统。

## 更新、删除与备份应保持哪些对应关系

以下是助手补充的工程约定：

- 正文改变：同步内容版本与对应向量；仅改作者等未参与编码的字段，通常不用重算向量。
- 内容停用或删除：同步禁用或移除可检索的表示，避免“近邻还在，正文已失效”。
- 换模型或维度：建立兼容的新索引，并记录模型与配置，不能混入不兼容向量。
- 分别保存索引和记录表：保留同一批次／版本关系；只保存索引文件不能恢复原文及出处。
- 命中的 ID 没有对应记录：应暴露一致性异常，不能拿另一条“看起来相似”的记录替代。

课件使用内存列表演示，未建立上述持久化、同步或权限机制。“source 文件名”也只是记录字段，不能单凭文件名推断来源已真实验证。

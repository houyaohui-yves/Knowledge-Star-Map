# 知识库任务入口

仅在当前 Knowledge Star-Map 项目使用。以根目录 [AGENTS](../../../AGENTS.md) 为目标、权限和文件保护约定；不依赖未提供的聊天历史或固定本机路径。用户用自然语言提出任务，不需要填写配置或选择模式菜单。

## 识别任务并读取对应规范

| 任务 | 读取与执行 |
| --- | --- |
| 学习、核对理解、系统学习、考查掌握、复习、继续课程 | [学习与复习流程](../../../99_System/学习与复习流程.md)；先回应当前问题，恢复相应来源接续 |
| 查找、比较、使用已有知识解决问题 | 执行下方“查找与应用”；需核验时读取[共同证据标准](../../../99_System/维护与评审流程.md#共同证据标准) |
| 整理材料、增补或拆分知识、维护地图 | [知识组织规范](../../../99_System/知识组织规范.md)及相关[模板](../../../99_System/Templates/)，路径判断查[目录说明](../../../99_System/目录结构说明.md) |
| 小节 Review、检查本节完整性／错误／歧义 | 完整读取[维护与评审流程](../../../99_System/维护与评审流程.md)并执行完整 Review；输出用[报告模板](../../../99_System/Templates/学习小节Review报告模板.md) |
| 诊断、一般知识维护、按问题修订 | 读取维护与评审流程的范围、共同证据及闭环部分；明确检查深度，不能冒充完整 Review |
| 灵感或项目推进 | 按目录说明使用 Ideas／Projects 及相关模板；明确成果才进入 Projects，通用认识按需回流 Knowledge |

按当前任务读取必要规范，不每轮加载全部文件。学习写入前同样需读知识组织规范；混合请求保留各自边界，当前只读要求不被学习默认写入覆盖。结构设计和纯 Git 操作按 AGENTS 与当前请求处理。

## 共同任务流程

1. 从请求确定主题、成果和授权；优先处理已明确部分，仅在缺失信息影响判断时补问。
2. 用名称、别名、中英文表达检索有关 MOC、知识和来源，阅读命中正文及必要上下文。候选不等于已读；按具体问题扩展依赖，不递归巡视全库。
3. 依据适用规范回答、取证和执行；有价值的新结论优先复用已有主文，内容去向按职责判断，无法核实的范围如实保留。
4. 实际写入后检查本次差异、证据、关联入口与接续；修订任务复查原问题，失败明确已完成及剩余范围，不覆盖用户已有改动。
5. 交付当前问题的结果、实际保存文件与关键限制。无必要变化可以不写；无法访问工作区时只能提供草稿。

## 查找与应用

明确使用目的和适用条件，从相关地图与正文查到概念、案例和实际依据；同义名称也要搜索。仅有搜索摘要时先读原文再作结论，查不到就说明检索范围和缺口。时效性、专业不确定或高风险主张需补证据；教学案例不当实测能力。

回答应将已有结论用于当前问题，并指出条件变化和缺失证据，提供真实笔记入口。库内没有的补充与库内已有认识分开说明。查询本身不自动保存；明确要求沉淀或处于学习写入范围时，才将可复用新认识写回有关主文。

## 工具能力与接续

原始 PDF 可按需使用 [pdftext](../../../99_System/Scripts/pdftext/README.md)。持久维护和受控修订使用[知识维护工具](../../../99_System/Scripts/knowledge_maintenance/README.md)，先读流程与输入格式。助手依据自然语言任务生成范围和证据，不把内部 JSON 操作转交用户，也不固定套用 Query 试点清单。

接续维护先 `show` 定位相关事项；`inspect` 后实际读证据，只有已有维护／保存事项授权时才 `record`。可修问题经 `prepare` 核对差异后按已有授权 `apply`；重新读取结果与来源，复查原问题后 `verify`。中断按账本恢复，冲突先核对当前文件；命令成功不等于问题已解决。只读评审不写队列，完整 Review 的范围和检查不能被工具简化。

学习进度保存在对应学习记录；维护事项唯一归属 `99_System/State/maintenance.json`，缓存丢失不应丢掉接续。工具校验版本、引文定位和写入状态，语义与效果仍需真实证据；没有后台触发、自动外网刷新或掌握推断。实际能力及后续验收以[统一方案](../../../99_System/知识库系统架构与改造方案.md)为准。

| Prompt 接口 | 提出应用层设计最终拼接 Prompt，并询问动态添加样例 | 区分模型语义输入与整个系统的其他控制手段；补充动态 Few-Shot 流程，待用户复述 |
| 资料与样例 | 提到参考资料、样例以及 Zero／One／Few-Shot | Shot 按示范输入—输出对计数，不按参考资料数；尚未通过辨析验证 |
| RAG 主流程 | 描述文件处理、切片、向量化、Query 检索与 Prompt 组装 | 已有基本流程表达；Indexing 不只文本提取、RAG 不限向量检索等边界是助手补充 |
| 构建策略与反馈 | 提出三类做法，并收集无召回／低相关问题 | 三类不是必经升级路线；无召回不一定缺知识，需区分资料、索引、检索和生成故障 |
| 双向优化 | 提出同时处理 Query 与知识库，并列出多轮 Query 类型 | 保留意图、歧义澄清、受控条件查询等是助手补充；“双向奔赴”按转述中的工程比喻理解 |
| Question/Content | 明确指出：检索匹配的是 question，放入 Prompt 的应是 content | 有正确复述职责区别的直接证据；不因此扩展为已掌握临时 Query Vector、索引更新或多路融合 |
| 问题扩写 | 提出依据回答复杂度生成 5～20 个典型问题 | 数量只能作为实验起点；问题可答性、去重与真实 Query 评测是助手补充 |

## 后续记录如何增加

1. **研究更新**：围绕新财报、重大事件或判断变化记录；先保留当时证据与推理，再更新公司摘要。普通补充可以并入同次研究，不要求每轮对话单独建文件。
2. **持仓事实**：以用户明确提供的记录为依据，注明日期、口径、已知范围和缺口。新的快照不覆盖旧快照；讨论买卖不能记成实际成交。
3. **决策依据**：记录当时信息、持有或调整理由、反例、复核条件，并区分助手建议、用户采用与实际执行。采纳分析方法不等于认同所有参数或已取得收益。
4. **实际复盘**：使用已明确的观察期间、分红费税、资金流与比较基准，分别检查判断、执行和结果；资料不足时不计算看似精确的绩效。

未来交易流水与复盘按实际内容建立。个人投资原则形成时，通用解释归入知识方法目录；采用、修改或暂停的事实在本项目记录。不得用最新理解重写当时的决策理由。

## 公司跟踪模板：一个阅读入口，分别维护研究与账户事实

新关注公司使用以下三份模板。平时从公司主文进入，能连续阅读经营、估值与自己的持仓；持仓与操作部分通过 Obsidian 嵌入显示其唯一当前记录，不在公司研究和账户记录里各手填一份。

| 模板 | 维护什么 | 新实例建议位置 |
| --- | --- | --- |
| [[公司股票跟踪模板]] | 公司识别、生意与护城河、治理、财务、分红、估值、价格回报，以及持仓嵌入与复核任务 | `Research/市场代码公司名/公司名：研究摘要.md` |
| [[个股持仓与行动模板]] | 持仓状态、确认数量与成本、市值盈亏、仓位、个人决策与实际执行 | `Portfolio/市场代码公司名：持仓与行动.md` |
| [[公司研究更新模板]] | 重要新证据、原判断、修订理由、计算差异及向当前入口的同步 | `Research/市场代码公司名/Updates/YYYY-MM-DD 公司名：更新主题.md` |

以上是新实例的命名规则，包含占位的路径不是已建目录或文件。已有公司路径不因模板更改而强制改名。只有获得实际关注对象和对应资料后才创建公司记录；原始外部出处仍由 `20_Sources/Notes/Investing/` 的来源记录维护。

公司主文第 7 节在持仓文件实际存在后插入全文嵌入：输入 `!` 后选择真实 Wiki 链接，显示持仓文件及其各节时间。无目标时保留“尚未接入／持仓待确认”，不生成空链接。已有账目可复用；模板不是要求重复建账，也不需要新增 Obsidian 插件。

### 动静结合：按内容失效方式更新

“静态”采用低频复核，而非永久免检。研究主线仍是六步判断，维护时按变化频率切开，避免每次新财报重写整篇。

| 部分 | 更新／复核的主要触发点 | 需要联动的结果 |
| --- | --- | --- |
| 行业、商业模式与护城河 | 年度检查，或重大竞争、技术、政策和业务变化 | 正常化盈利、增长与风险假设 |
| 治理与资本配置 | 定期报告、控制权、重大交易及监管事项 | 资金可用性、派息、风险与估值 |
| 财务与现金 | 新财报及更正公告 | 正常化输入、估值与顶部研究结论 |
| 分红与其他股东回报 | 方案、批准、实施、更改与取消公告 | 未来股息、现金覆盖；个人到账须另核账户 |
| 估值模型 | 盈利、投入、股数、政策或要求收益假设变化 | 每股价值、门槛价与现价回报 |
| 行情与预期回报 | 做决策时取得的新报价，或模型改变 | 现价回报、市值与盈亏；报价变化不自动修改内在价值 |
| 数量、成本与持仓状态 | 已确认成交、股数／成本调整或新账户资料 | 市值、仓位与个人操作计划 |
| 个人决策 | 证据、组合或资金约束变化 | 保存旧决定，分别记录建议、采用与执行 |

不要求每日刷新全篇，也不把这些触发规则当成已设置的自动监控。发生新事件后，实际查证并更新对应部分。

### 每个部分的时间含义

| 字段 | 含义 | 如何维护 |
| --- | --- | --- |
| 内容更新时间 | 这一节的事实、计算或判断上次实质修改时间 | 只改文件格式不刷新全部章节日期 |
| 数据期间／信息有效时点 | 数字或事实属于哪一报告期、日期或报价时刻 | 财报期间与披露日期分别记录；混合时点按表项列明 |
| 最近复核时间 | 最近实际查过新证据、确认或修订这一节的时间 | 查过后结论未变，也可只更新复核时间并写核对依据 |
| 下一次复核触发 | 哪个事件或日期到来时应再次检查 | 暂无披露日则用事件，不把预约日当已发生 |

文件属性 `updated` 仅表示文件编辑时间。初建模板不等于完成核验，未知日期写待核；没有实际检查就不能把最近复核日期刷新为今天。当前摘要应说明其依据时点，不能以全篇最晚的日期掩盖较旧输入。

财务、股数或派息有变化而模型尚未重算时，将依赖的估值、现价回报和当前结论标为“待重算”；行情过旧则标“仅供参考／待刷新”。完成计算和核对后再恢复有效性。这里的状态由实际维护填写，没有自动日期检查或公式联动程序。

### 持仓与跟踪分为两种状态

持仓记录维护“观察待购／持有中／已清仓”，附用户或账户确认时点；资料不足先写待确认。公司主文维护“研究中／暂停／归档”，附日期和原因。两者不能互相推断：已清仓后可以继续研究，持有期间也可以暂停讨论；用户所说“已清仓归档不看”对应“已清仓＋归档”。

归档表示停止主动研究，保留原路径及历史链接，不删除记录；恢复时先核对信息缺口和当前账户事实。只有确认数量变化才改变持仓状态，未成交的计划不能改成持有或清仓。

“持有金额”拆成当前市值与成本基数；“盈亏”拆成剩余仓位浮动盈亏、已实现盈亏、实际分红和同口径累计总损益。每项写明数量依据、行情时点、费用与分红处理。无法确定历史资金流就标资料不足，不将券商调整成本与已计入分红重复相加；仓位必须注明分母、账户范围和估值时点。

### 一次更新怎样闭环

1. 先确认新证据影响哪些章节；只有报价变化时，不重新解释整家公司。
2. 重要经营或估值判断变化，先用研究更新模板保存旧输入、新证据和修改理由；重要账户变化／个人决策保留带日期的持仓快照或决策记录。小修订不强制新建历史文件。
3. 更新当前记录的相应章节及独立时间条，并将尚未处理的依赖结论标为待重算。公司分析不自动写成个人采用或真实成交。
4. 完成必要计算、检查来源与链接，再更新顶部摘要及下一次复核条件。旧判断保留当时语境，查出的事实错误追加更正。

## 后续记录如何增加

[[个人投资原则与交易纪律]] 回答“按什么依据作决定”，集中维护当前原则、目标、配置边界、检查与待定规则；[[投资组合长期跟踪（测试版）]] 回答“现在持有什么、结果怎样变化”，只保存统计口径、最新持仓、月末历史与风险待办。公司研究、交易理由、资金流水、分红核算及复盘各归对应文件。组合表保留余额与报价各自日期，月末按实际资料追加，外部净转入不当作收益。

1. **公司研究**：摘要保留当前结论与关键证据；需要详细展开的研究按集中问题写入公司 `Updates/`，包括首次专题详析和后续重要更新。先保存证据与推理，再同步摘要；同主题同轮补充合并，不要求每轮对话单独建文件。
2. **持仓事实**：以用户明确提供的记录为依据，注明日期、口径、已知范围和缺口。新的快照不覆盖旧快照；讨论买卖不能记成实际成交。
3. **决策依据**：记录当时信息、持有或调整理由、反例、复核条件，并区分助手建议、用户采用与实际执行。采纳分析方法不等于认同所有参数或已取得收益。
4. **实际复盘**：使用已明确的观察期间、分红费税、资金流与比较基准，分别检查判断、执行和结果；资料不足时不计算看似精确的绩效。

未来交易流水与复盘按实际内容建立。通用投资原理归入知识方法目录；个人采用、修改或暂停的原则集中在 [[个人投资原则与交易纪律]]，具体决策引用当时版本。不得用最新理解重写当时的决策理由。

## 公司跟踪模板：研究与个人账户分开维护

公司目录维持“一份研究摘要＋Updates/”。[[公司投资研究模板]] 的主文采用六部分：公司与投资定位、经营是否符合预期、关键风险、价值估算与现价评估、当前考核结论、下一步关注。目标约 1,500～2,500 字，复杂公司可适当超出；摘要不放研究详解附录或折叠长文。全部公司专属详析使用 [[公司研究更新模板]]，按问题放入本公司 `Updates/`，摘要对应章节直达相关分析。

研究仍须先理解生意与竞争优势，再判断 A～F 主类型、重叠特征及现金流／价差角色，并以财务、现金、治理和估值检验条件；压缩的是阅读主文，不是证据与推理。公司研究不写个人股数、成本、盈亏、仓位、到账或执行决定，也不嵌入持仓全文。

[[个股持仓与行动模板]] 在 Portfolio 引用公司研究与当时版本，结合个人原则、账户、资金和相关持仓形成操作记录。研究认为条件成立不等于个人已采用，更不等于已经成交；研究结论和个人决定各自可追溯。

| --- | --- | --- |
| [[公司投资研究模板]] | 六部分精简摘要：当前结论、关键证据、风险及后续观察；链接对应详析 | `Research/市场代码公司名/公司名：研究摘要.md` |

### 研究摘要与 Updates 的分工

**摘要负责快速了解当前判断；Updates 负责按主题保存详细研究过程及重要变化。** 外部出处、原始取数与核验记录仍归 `20_Sources/Notes/Investing/`；公司研究的解释与推理不能只留在来源记录中。Portfolio 负责个人账户与交易。

`Updates/` 不再只限发生结论变化时使用。只要需要详细展开一个公司研究问题，就可建立专题，即使这是首次研究或结论未变。文件名采用 `YYYY-MM-DD 公司名：具体研究问题或分析主题.md`，如“公司与投资定位分析”“分红与现金支持能力分析”“价值估算与现价评估”。日期指本次研究形成或旧文拆分日期；资料期、报价期另标，整理不冒充新取证。

每篇围绕一个概念集中的问题，写清方法、证据、推理、结果与限制。不把整份旧摘要换名塞进一篇“详细研究”，也不机械每个小标题都拆文件。同一主题同轮补充合并；同一事件涉及几个独立问题时可以分篇互链，各自保留集中内容。摘要按章节链接当前适用记录，读者不必在目录内猜哪篇最新。

| 情况 | 如何维护 |
| --- | --- |
| 首次研究或压缩已有长文 | 建立六部分摘要；有必要展开的主题分别写入 Updates，保留原证据、计算与未知项；不另复制一份相同摘要 |
| 普通数字、措辞、报价或分红实施状态变化 | 更新摘要相应章节及时间；短计算可写摘要／已有核验记录。若只是沿用旧模型，保留旧研究快照，不强制新文 |
| 新开展一个集中问题的详细研究 | 用专题详析记录完整过程，无须先发生结论变化，再同步摘要对应结论和入口 |
| 主分类、收益论点、模型或考核依据实质变化 | 在受影响主题下新建研究记录，引用旧记录，保留前后判断与原因；联动更新摘要 |
| 关键节点验证，结论不变 | 有实质证据与推理时保存该主题验证；不能只写“读过新公告” |
| 结论相关的事实或计算错误 | 留旧值、正确值、错因及影响，建立更正记录并在旧文追加指向，更新摘要；不影响结论的小笔误可直接修 |
| 个人成交、成本或决定变化 | 维护 Portfolio，不为账户事项自动新增公司研究 |

正式留档后，新的经营事实、模型与判断用同主题新日期记录承接，不回写历史结论。未完成的同轮研究可继续补齐，注明未完成部分及实际核验时间；同日不同轮用明确的问题或版本标识区分，不覆盖已有记录。不要按每次对话、每份财报或目录篇数机械建文件。

摘要中一个重要判断只完整维护一处：风险节概括论据，考核节说明是否触发条件；完整参数与推导在主题文档，原始取数在 Sources。摘要不容纳完整详析，无论展开还是折叠。必要跨主题关联用链接连接，避免多处维护同一套计算。

### 动静结合：按内容失效方式更新

“低频”不表示永远不变。各节更新时间独立；更新研究摘要中的哪一节，与是否需要独立留档是两件事。

| 部分 | 更新／复核触发 | 需要联动的结果 |
| --- | --- | --- |
| 公司类型、收益属性、生意及护城河 | 年度检查，或业务结构、竞争及经营机制改变 | 适用方法、正常化输入及专属考核条件 |
| 治理、资本配置及资金约束 | 定期报告、控制权、重大交易或监管变化 | 现金可用性、普通股权益与价值 |
| 财务、现金与分红 | 新报告、更正、分配方案及实施变化 | 正常化输入、派息覆盖、估值与顶部结论 |
| 估值与当前回报 | 经营／股数／政策假设改变，或决策时刷新报价 | 价值和条件价格、现价回报及考核状态；报价本身不自动改变内在价值 |
| 公司专属买入／持有／清退条件 | 支持证据、模型或关键验证结果变化 | 当前资格、反证及下一检查点；条件依据改变时独立留档 |

数量、成本、个人风险预算、仓位及操作决定只在 Portfolio 维护。本规则是人工维护安排，不意味着自动刷新或后台监控。

### 每个部分的时间含义

| 字段 | 含义 | 如何维护 |
| --- | --- | --- |
| 内容更新时间 | 这一节的事实、计算或判断上次实质修改时间 | 只改文件格式不刷新全部章节日期 |
| 数据期间／信息有效时点 | 数字或事实属于哪一报告期、日期或报价时刻 | 财报期间与披露日期分别记录；混合时点按表项列明 |
| 最近复核时间 | 最近实际查过新证据、确认或修订这一节的时间 | 查过后结论未变，也可只更新复核时间并写核对依据 |
| 下一次复核触发 | 哪个事件或日期到来时应再次检查 | 暂无披露日则用事件，不把预约日当已发生 |

文件属性 `updated` 仅表示文件编辑时间。初建模板不等于完成核验，未知日期写待核；没有实际检查就不能把最近复核日期刷新为今天。当前摘要应说明其依据时点，不能以全篇最晚的日期掩盖较旧输入。

财务、股数或派息有变化而模型尚未重算时，将依赖的估值、现价回报和当前结论标为“待重算”；行情过旧则标“仅供参考／待刷新”。完成计算和核对后再恢复有效性。这里的状态由实际维护填写，没有自动日期检查或公式联动程序。

### 持仓与跟踪分为两种状态

持仓记录维护“观察待购／持有中／已清仓”，附用户或账户确认时点；资料不足先写待确认。公司主文维护“研究中／暂停／归档”，附日期和原因。两者不能互相推断：已清仓后可以继续研究，持有期间也可以暂停讨论；用户所说“已清仓归档不看”对应“已清仓＋归档”。

归档表示停止主动研究，保留原路径及历史链接，不删除记录；恢复研究时先核对公司信息缺口，若同时处理个人操作再核对账户事实。只有确认数量变化才改变持仓状态，未成交的计划不能改成持有或清仓。

“持有金额”拆成当前市值与成本基数；“盈亏”拆成剩余仓位浮动盈亏、已实现盈亏、实际分红和同口径累计总损益。每项写明数量依据、行情时点、费用与分红处理。无法确定历史资金流就标资料不足，不将券商调整成本与已计入分红重复相加；仓位必须注明分母、账户范围和估值时点。

### 一次更新怎样闭环

1. 先区分公司研究与个人账户事项，按上表判断直接更新摘要还是需要独立 Updates；只有报价变化时，不重新解释整家公司。
2. 需要独立留档时，先保存已有旧输入、旧结论及当时理由，再写新证据和差异；关键节点验证可保留原结论并说明证据。个人决定及交易另按 Portfolio 规则保存，不复制入研究更新。
3. 更新当前记录的相应章节及独立时间条，并将尚未处理的依赖结论标为待重算。公司分析不自动写成个人采用或真实成交。
4. 完成必要计算、检查来源与链接，再更新顶部摘要及下一次复核条件。旧判断保留当时语境，查出的事实错误追加更正。
